# Proposal: opendesign-chat-image

- Date: 2026-07-26
- Status: open

## Goal

网页聊天框能发图片给模型(走 nanobot 原生 ws `media` 字段),并且发出去的图能一键
「存进收件箱」归档;顺带把上一单留下的两个粗糙面收尾:收件箱缺失时给人一条可点的出路,
以及上传成功后告诉用户**文件到底落在硬盘哪里**。

## Motivation

上一单(opendesign-image-upload,0.48.0)只做了「网页拖拽 → 收件箱」这一半。
聊天发图是另一半,而且是设计师更自然的动作:业主发来一张户型图/参考图,
他想直接甩进对话里问"这个客厅怎么改"。协议层 2026-07-26 已实测可用
(`docs/nanobot-ws-protocol.md` §2 `media` 一节,mimo-v2.5 真能看见图),
但**前端一行发图代码都没有** —— 现在往聊天框拖图什么都不会发生
(`+` 按钮的 title 至今写着"即将支持")。

## 真问题(第一性)

- 用户原话:
  - 「现在聊天窗口发图片 opendesign能看吗」
  - 「有一个问题,收件箱是在我电脑哪个文件夹」
  - 「但是每个用户不一定都有这个文件夹 而且有的人可能习惯直接放在桌面」
- 真正要解决的是:
  1. **把图给模型看** —— 设计师的输入本来就是图,纯文字对话对他是残废的。
  2. **"东西去哪了"必须看得见** —— 用户问出"收件箱在我电脑哪个文件夹"这句,
     说明 0.48.0 的提示条("已存进收件箱")对他是**不合格**的:他被迫来问我。
     一个本地工具让用户搞不清文件落在哪,是提示写错了,不是用户不懂。
  3. **不能假设那个文件夹存在** —— 0.48.0 缺收件箱只回一句"先建一个",
     等于把活推回给用户,而他是设计师、不是程序员。
- 我在这中间翻译了什么:
  - 用户说"有的人习惯直接放在桌面",我**没有**把它翻译成"要支持传到桌面"。
    查证后:桌面+下载本来就在 `DS_ORGANIZE_ROOTS` 默认白名单里,对话里说"整理桌面"
    已经能走完整条归档链。所以这句话我读成"别把收件箱当必需品",落到本单 = 
    收件箱缺失要有出路,而不是新开一条往工作区外写的路。
  - 用户说"以后要给同事用,现在可以先不做" → 首装向导**不在本单**,
    但本单不许再增加"要用户手动改配置/建文件夹"的新债。

## Scope

- in:聊天框拖拽/粘贴图片 → 缩略图预览 → 随消息发给模型(ws `media`)。
- in:助手/用户气泡上的图 →「存进收件箱」按钮(复用写针孔⑬)。
- in:上传成功提示回显**完整落盘路径**;收件箱卡片标题显示收件箱在哪。
- in:收件箱不存在 → 提示变成可点的「帮我建收件箱」(新写针孔⑭,只建固定名那一个)。

## Non-goals

- **不做**首装向导 / 多用户支持(用户明确"现在先不做")。
- **不做**往桌面或工作区外写任何字节(桌面归档走对话 + 既有 organize 白名单)。
- **不做**发图时自动双写收件箱(见 design D2:手动按钮,不自动)。
- **不做**视频/音频(协议支持,但设计师场景不急)。
- **不做**上传到指定项目/类目(与上一单同样的理由:那才是"网页能任意写项目夹")。
