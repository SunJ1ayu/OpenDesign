## Approach

### A1 界面只问一个可直接回答的问题(采纳 GPT 的措辞)

**「这个文件夹要不要显示在项目列表里?」** —— 不问「这是收件箱还是归档」。
设计师未必知道「结构目录」是什么,但一定知道某个文件夹该不该出现在项目列表里。

每行显示**当前状态 + 依据**:「你声明过」/「按常见名字猜的」/「没人说过,默认当项目」。
依据必须写出来 —— 用户要能分辨「这是我定的」和「这是它猜的」。

### A2 一次存整份清单,不是一次改一个名字(**采纳 GPT,推翻主 agent**)

主 agent 原设计是 `{"name":..., "structural": true|false}` 增量式。**这有个坑**:
声明第一个名字的瞬间,`structural_dirs()` 第②层整层关闭(代码语义:声明过就不再回落),
其他被猜掉的目录会**突然全部冒出来**。主 agent 识别出了这个坑但没解决;
GPT 的「整份存」从结构上绕过去了 —— 因为这个配置的语义本来就是整份列表。

### A3 服务端写口(采纳 GPT,含快照冲突检测)

```
POST /api/workspace/folder-visibility
{ "review_id": "<服务端本次检查下发>", "hidden": ["00-收件箱", "共享素材"] }
```
- 只允许 `review_id` / `hidden` 两个字段,多一个 **400**
- `hidden` 有数量与请求体上限;无重复;全部过单段名闸
- **名字只能来自服务端本次检查返回的集合**(当前根下一级文件夹 ∪ 原已声明但暂不存在的名字)
- 网页**传不了**工作区路径 / 配置路径 / 创建目标 —— 路径永远服务端解析
- **`review_id` 绑定配置内容 + 目录快照;期间有变化返回 409,要求刷新后重选**
  (主 agent 原设计没有这一层 —— 用户开着卡片时在资源管理器里新建了文件夹,
  按旧快照保存会静默把新文件夹藏掉)
- 只修改原 JSON 的 `structuralDirs`,**其他字段原样保留**;原子落盘,写后重载验证
- 坏配置返回可恢复状态,不抛异常、**不尝试顺手修好**

### A4 曾经声明、当前不存在的目录必须保留(采纳 GPT)

显示为「**已记住,目前没找到**」,默认保留。否则外接硬盘没插/临时改名时,
一次保存会**静默抹掉**用户过去的声明。主 agent 漏了这条。

### A5 项目在子目录下时,不显示确认区(采纳 GPT)

**已核实**:`excluded_structural()` 在 `realpath(root) != projects_root` 时**直接返回 `[]`**
(`bin/ds_workspace.py`)。即项目放在 `01-项目/` 之类子目录下时,**根本不存在误伤问题**。
主 agent 默认了「所有人都把项目摊在根目录」,会给这批用户显示一个毫无意义的确认区。

### A6 猜出来的结构目录**不预勾**在「不显示」一侧(**推翻 GPT,采纳主 agent**)

GPT 建议把规则表命中的常见名字预放在「不显示」侧(带「暂时这样处理,等你确认」标注 +
结果预览)。**否掉**,依据是本仓自己写死的原则(`ds_workspace.py` docstring):
**「宁可多列一个,不可猜错让人家的真项目从列表里消失」**。

预勾之后,用户随手一点保存,**猜测就固化成了正式声明** —— 恰好把本单要防的失败焊死。
处理:**没被声明过的一律默认「显示」**。保存后收件箱混进列表只是碍眼,错藏真项目是事故。

### A7 入口(采纳 GPT)

取代 `web/src/workspace/Sidebar.tsx:208` 现有的被动提示(**已核实**该处确实在显示
`excludedStructural`)。不新造卡片位置。

## Key trade-offs / risks

- **⚠️ 准入条件:`workspace.json` 的读改写目前没有加锁 —— 有丢更新风险。**
  **已核实**:`ds_tools.py:528 _write_workspace_json` 只做原子替换(tmp + `os.replace`),
  **整个「读→改→写」全程无锁**;`bind_project` 路径是 load_config 读 → 改 `raw` →
  写回。两个并发写会互相覆盖(最后写的赢)。仓里有现成的 `ds_common.locked_rw`,这条路径没用。
  **再加一个网页写口 = 又多一个并发来源。共享锁应视为本单上线的准入条件,而不是 follow-up。**
  (GPT 独立发现,主 agent 完全漏掉;同类问题 frontend-p1 四审也抓到过 M1 并发锁。)
- 首次要用户点几下(代价),换来的是不会静默藏掉真项目。
- 卡片只处理**已有安全先例**的动作:缺收件箱 → 复用「帮我建收件箱」;未接入 → 复用
  「接入工作区」;配置读不出 → 只提示「需要修复」,不自动覆盖。

## Alternatives considered

- **增量式写口(一次一个名字)**:否 —— 见 A2,会让第②层瞬间关闭、其他目录突然冒出。
- **预勾猜测结果**:否 —— 见 A6,与仓内既定原则冲突。
- **在卡片里提供建归档/共享目录**:否 —— 破「网页不自造目录」,也正是本单当初被推迟的原因。
- **把「不显示」等同于「设为收件箱」**:否 —— 见下方盲点①。

## 已知盲点(来自 GPT,主 agent 认同)

1. **`structuralDirs` 只表达「不要显示成项目」,不表达「它是收件箱还是归档」。**
   用户把「新文件」勾成不显示,**不会**让收件箱功能认出它 —— 收件箱语义仍来自 taxonomy。
   所以第一版措辞**必须**是「显示/不显示」,**不能**说成「设为收件箱」。
   自定义收件箱命名应是另一张独立受限的配置单,不能偷偷塞进本卡。
2. **原子替换 ≠ 不会丢更新**(见上方准入条件)。

## Test strategy (oracle)

**尚未编写。oracle 由主 agent 亲自写并先红检,再 commit 进基线,然后才派活。**

必须覆盖(草案):
- 写口:字段多一个 → 400;`hidden` 含非单段名/重复/超限 → 400;名字不在服务端下发集合内 → 400;
  网页传路径字段 → 400
- 快照:`review_id` 过期(期间目录或配置变化)→ 409
- 存量:曾声明但当前不存在的名字,保存后**仍在** `structuralDirs` 里
- 只动一个键:其他字段(`root`/`projects`/`projectsDir`/`projectsDepth`)原样保留
- 坏配置:非 dict / 非 list / 带路径成分 → 降级不崩、不覆盖用户手写内容
- **并发**:两个并发写不丢更新(准入条件的直接判据)
- A5:`projects_root != root` 时不出确认区
- A6:未声明的目录默认落在「显示」侧

**这个 oracle 能被什么骗过?**

最可能的假绿:**接口层断言全绿,但用户眼里「我的项目还是不见了」。**
因为 oracle 测的是「写口拒绝了非法输入」,测不到「卡片显示的那份清单本身就是错的」——
比如服务端下发集合算错(漏了某个一级文件夹),前端忠实显示、写口忠实接受、全绿,
而那个文件夹从此消失。
**接得住这种错的只有真机**:拿一个真实工作区(含中文名、含一个没声明过的真项目文件夹)
跑一遍,肉眼确认它出现在「显示」侧。史料:07-24 `columnCount==="3"` 全绿而正文被压成竖排。
