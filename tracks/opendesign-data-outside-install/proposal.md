# Proposal: opendesign-data-outside-install

- Date: 2026-08-15
- Status: open

## Goal

让**业主的东西活得比这个程序久**:项目档案、客户备忘、共享参考图库、总索引、
整理计划与审计、工作区设置,全部搬到安装目录之外;并加一道拦截,不许把项目文件夹
设在"会被删掉的地方"。

## Motivation

S1c 的安装器已在业主真机装成功(0.86.0),卸载确认页上写着:

> 你的资料(**备忘、对话、工作区设置**)默认不会被删除。

**这句话是假的。** 卸载执行的是 `RMDir /r "$INSTDIR"`,而下面这些全在 `$INSTDIR\ds\` 里:

| 东西 | 现在的位置 | 普通卸载(什么都不勾) |
|---|---|---|
| 设计文件(dwg/SU/效果图) | 业主自己的盘(工作区根) | 安全 |
| **共享参考图库**(`refs/` 里是**真图片**,含现场照片) | `$INSTDIR\ds\refs` | 🔴 **删掉** |
| **项目档案**(`projects/*.md`:备忘、变更记录、沟通日志) | `$INSTDIR\ds\projects` | 🔴 **删掉** |
| **客户备忘** `clients/*.md`、**总索引** `index.md` | `$INSTDIR\ds\` | 🔴 **删掉** |
| **整理计划 + 审计日志** `organize/` | `$INSTDIR\ds\organize` | 🔴 **删掉** |
| **工作区设置** `config/workspace.json` | `$INSTDIR\ds\config` | 🔴 **删掉** |
| 和助手的对话、登录口令、key | `%LOCALAPPDATA%\OpenDesign\UserData` | 保留 ✅ |

**三样点名承诺的里头,只有"对话"是真的。**

比卸载更常发生的是**更新**:S1d 设计的应用内更新是"版本化组件 + 指针换向",
真按那个做,一次例行更新就把上面这些全带走 —— 而业主不会预期"更新"会清空档案。

## 真问题(第一性)

- 用户原话:「**这个按钮是否有必要存在,如果是用户自己本来的资料肯定不能删 这个按钮也就
  没必要存在了,如果是跟助手的对话之类的,不删这些记录再装之后能衔接得上吗**」
  后续追问:「**如果会删那删掉的东西是什么 是用户全部自己的资料吗**」
- 真正要解决的是:**"卸载/更新会不会弄丢我的东西"这件事,现在没有任何机制保证** ——
  靠的是"安装目录里碰巧没有他的东西",而事实是里面装着他的图库和全部档案。
- 我在这中间翻译了什么:业主问的是**那个可选框**;我查下去发现**风险根本不在那个框上**,
  在默认路径。⇒ 本单解决的是他真正担心的东西(会不会丢),不是他字面问的那个按钮。
  **这个转译我在这里写明,如果错了,后面全错。**
- 另一半真问题(他没问、但答案依赖它):我上一轮敢说"不会删你的资料",靠的是
  **他碰巧没把项目夹设在那两个目录里面** —— `set_workspace` 只校验"绝对路径 + 存在"
  (`bin/ds_tools.py:905-913`),**没有任何东西拦这件事**。靠运气的答案不算答案。

## Scope

- in: 引入**数据根**(data root)并解析一次,默认 = `ds_root`(现有 git-pull 安装
  与本机开发仓**零变化**),Windows 包由外壳/安装器指到 `%LOCALAPPDATA%\OpenDesign\UserData`
- in: 上面表格里所有 🔴 的读写口改走数据根
- in: `set_workspace` 拦截:项目夹根不许落在安装目录或数据根**里面**
- in: 一道**机械闸**,把"哪些东西算数据"变成机器查的事(不是我记得)
- in: 卸载页与可选框的文案改成与实现一致

## Non-goals

- 不动业主的设计文件本身(它们从来就在他自己的盘上,本单一个字节都不碰)
- 不做**迁移**:业主这台机器上刚装完就卸了、还没产生过档案;git-pull 那两套
  (`F:\AI\OpenDesign`、公司机)默认值不变 ⇒ 无人需要迁移。**若将来需要,单独一单。**
- 不做 S1d 的应用内更新本体(本单只保证"数据不在会被换掉的那棵树里")
- 不重排 `%LOCALAPPDATA%\OpenDesign` 底下已有的 `UserData/Logs/Cache` 三兄弟
