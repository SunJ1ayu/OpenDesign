# Proposal: opendesign-chat-image-p2

- Date: 2026-07-26
- Status: open

## Goal

真机用起来之后冒出的一批(全部来自用户 2026-07-26 下午的实机反馈):
收件箱挪去右列常驻 + 项目列表不再把结构文件夹当项目 + 历史对话看得见发过的图 +
聊天存图起个人看得懂的名字。

## 真问题(第一性,用户原话)

- 「收件箱在我的项目列表也会出现让我建档,这也算 bug 吧」→ **是 bug**,已核实:
  项目自动发现把工作区根下所有目录都当项目候选,没排除结构目录。
- 「**不要写死目录名,因为用户的目录名不一定跟我的一样**」→ 排除必须靠"用户声明的
  事实",不能靠我猜名字。这条改变了修法本身。
- 「这个常驻的打开收件箱可以在项目助手上面,款式和左边图墙对齐,这样既解决了最右边
  太空只有项目助手也更美观」→ 采纳,并顺带纠正一个 IA 别扭:收件箱是**工作区级**的,
  本来就不该混在"这个项目的图片/文件"中间。
- 「发了图片之后切别的地方,回到历史对话就看不到之前发的图片了」→ 算 bug。
  查过网关:回放数据里带图(签名 URL),是前端 hydrate 时丢了。
- 「(三张截图)不会自动改名」→ **不是 bug**:浏览器给粘贴图起的是哈希名,天生不撞名。
  但暴露真问题:哈希名人看不懂、整理时也匹配不到项目。

## Scope

- in:项目发现排除结构目录(**按 workspace.json.structuralDirs 声明 ∪ 规则表里确实
  存在的**;两层都不中就不排除 —— 不猜)
- in:收件箱整块搬到右列顶部 + 常驻「打开」(open-folder 新 inbox 分支,路径服务端解析)
- in:历史对话回放渲染图片(只认 `/api/media/` 签名 URL)
- in:从聊天存进收件箱时起可读名(薄默认,原名有意义则保留)+ 提示告知"可以让助手改名"

## Non-goals

- **不做**工作区体检卡/提议创建结构目录(那要写配置 + 让网页命名目录,是新写面,
  单独一单吃 full 四审)。
- **不做**任何"猜这张图是什么"的启发式(不读图内容、不猜空间/类目)。
- **不做**把现有项目夹搬进 01-项目(要动用户真实文件,必须走暂存+确认,且他没要求)。
