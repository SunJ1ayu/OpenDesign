## Goal

把「前端直接点」roadmap 的 P2 队列一次清空:

| # | 条目 | 现状(已核) |
|---|---|---|
| #7 | 切阶段:状态 chip → 可点下拉 | `ChangesColumn.tsx:305-312` 是死 `<span>`;核心 `ds_tools.set_stage:934` 齐备,**但没有 HTTP 针孔**,切阶段只能回聊天打字 |
| #8 | 参考图标签 / 备注就地改 | `ds_refs` **没有任何改标签的核心函数**(只有 add_ref / add_style / link_ref)——本单要新写 `update_ref` |
| #9 | 变更修改历史在 UI 可见 | `ds_web.py:499` 每条变更**已经返回** `history` 与 `note`;`web/src/api.ts` 的 `Change` 类型压根没这两个字段,UI 零渲染 |

## Motivation

#7 / #9 的共同点是**能力已经在后端躺着,只差最后一厘米**:设计师在工作台看得见
「方案深化」这个 chip 却改不动它;`edit_change` 每次改正文都往 `## 变更历史` 段写了
`原:…` 留痕、读侧也已分桶返回,但界面一个字都没画 —— 而「记住业主改过什么」正是
这个产品的命根子。

#8 是三条里唯一要**新加核心写工具**的:参考图录进来之后标签打错、备注要补,现在只能
回聊天重说一遍(或者根本改不了)。用户明确要求本单一起做完。

## Scope

- in:#7(新写针孔 `POST /api/projects/stage` + 阶段词表下发 + stage-chip 下拉)、
  #8(新核心 `ds_refs.update_ref` + MCP 工具 + 新写针孔 `POST /api/refs/update` +
  图墙 lightbox 就地改标签/备注)、#9(纯前端渲染 `history` / `note`)。
- **两个新写口 = 安全面**,verify 必走 full 四审(07-18 教训,不打折)。

## Non-goals

- 阶段**词表本身**不改(11 项不动),不引入自定义阶段。
- 参考图的 `来源` / `文件` / `用于` 三段本单**不可编辑**(文件路径可改 = 等于换图,
  已有的 realpath/存在性闸得整套重来;`用于` 有 link_ref 专属工具)。
- 参考图**删除**不做(删索引行 = 另一类风险,且图本身不该被前端删)。
- 项目改名/删除 UI、图片上传(单独大件)、切模型(仍走终端)。

## 成功标准

1. 点 chip 能改阶段;点参考图能改标签/备注;两者都落盘走核心工具,markdown 头部/索引行
   与页脚 `最后更新` 都对。
2. 词表**单一真相源**:阶段 = `ds_tools.PROJECT_STAGES`,风格/空间 = `ds_refs` 的
   `_load_styles` / `SPACES`;前端不硬编码任何副本。
3. 词表外的值(含换行 / `|` / `## ` 注入尝试)一律拒,零落盘;未列的字段一律不动
   (索引行的 `来源` / `文件` / `用于` 段逐字节不变)。
4. 改过的变更行能在 UI 看到「改过 N 次」及每次的日期 + 原文。
5. 全量回归绿,`/api/health` 回显 0.33.0。
