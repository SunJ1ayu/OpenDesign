# Proposal: 打开软件不再被更新检查挡住

- Date: 2026-09-19
- 业主原话：「现在每次打开都会弹出正在检测更新,这严重拖慢了我们开软件的速度啊」
  「不应该让用户看到这个界面才对啊,应该是有更新才显示和进度条,没更新就跟平时打开软件一样对不对」

## 现在错在哪(实测,不是推测)

0.98.7 把「查更新 + 下载 + 安装」整条链放在**启动路径**上,并用全屏卡片挡住整个界面
(`web/src/App.tsx`:`if (startupPhase !== "ready") return <全屏卡片>`)。
后端 `check_for_update` **串行**走两个来源(订阅源 → GitHub 接口),每个 `TIMEOUT_S = 10`
⇒ 两条都超时就是 **20 秒干等**。结果缓存 `CACHE_TTL_S = 6h` 但只活在**进程内存**里
(`_cache = {}`),软件一关即失效 ⇒ **每次打开都是冷缓存,必然真去联网**。

## 要变成什么

- 没有可装的新版(或还没下好)⇒ **立即进工作区,零等待**,和没有更新功能时一模一样。
- 只有「新版已经下载完成」⇒ 才显示进度条并安装;那时进度条是真的在装,不是在等网络。

## 验收

启动路径上不发生任何网络请求;断网 / 网络挂死时冷启动耗时与关掉更新功能时同量级;
有已下载新版时才出现更新界面;手动更新入口行为不变;业主真机回显。

## 风险定级

impact-risk **high** —— 新增磁盘写口(更新状态文件),按 CLAUDE.md 这类默认 high,外审预算 2。
design-uncertainty **high** —— 见 design.md 的前提攻击,核心前提「谁在什么时候查和下载」
