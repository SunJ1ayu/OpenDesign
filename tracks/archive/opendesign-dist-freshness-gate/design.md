# Design: opendesign-dist-freshness-gate

- Change: opendesign-dist-freshness-gate
- Status: draft

- 规划双出: 不适用 —— 不是新写面(`impact.factors` 为空),也不是开放方向。
  方向是被**测量**定案的,不是被观点定案的:build 实测 3.16s/峰值 239MB ⇒
  「跑之前真 build 一次比产物」从"太慢不现实"变成"完全可行",其余方案随之出局。
  花一次双出去挑一个已被测量锁死的方向,不划算。

## Approach

把闸**独立成一个脚本** `tests/e2e/check-dist-fresh.sh`,由 `tests/e2e/run-all.sh`
在跑任何场景**之前**调用一次。

它做的事,一句话:**把当前源码 build 到仓外临时目录,与 `web/dist` 逐字节比对。**

```
mktemp -d(仓外) → npx vite build --outDir <tmp> --emptyOutDir
  → 比文件集合 + 每个文件内容
  → 一致:放行
  → 不一致:列出差异文件,告诉他跑 `npm run build` 并提交,rc=1 BLOCK
  → build 失败:rc=1 BLOCK(**不许静默放过**),原样透出 build 的最后若干行
  → trap 清理临时目录
```

三个设计决定,每个都对应一条本单要防的失败:

1. **build 到仓外临时目录,绝不动 `web/dist`。**
   这样闸**只报告、不修复** —— 「你欠一次 build」这个信号必须留在工作树上被看见,
   不能被工具悄悄抹平(抹平之后,下一个人只会看到 dist 莫名其妙变脏)。
2. **比产物,不比源码。** 这是本单的全部要点:改注释 ⇒ 产物不变 ⇒ 不该报警;
   真改代码没 build ⇒ 产物不同 ⇒ 必须报警。源码哈希和 mtime 都答不了这个问题。
3. **装在总跑入口,不在某个场景里。** 旧闸只守 1/37 的门。

`tests/e2e/llm_key.e2e.mjs` 里那道比 mtime 的旧闸随之**退场**(职责被接管且更准更全)。
理由按 CLAUDE.md「理由失效即候删,总量不许只进不出」。

## Key trade-offs / risks

- **🔴 前提风险(必须先验,否则整个方案不成立):`vite build` 必须是确定性的。**
  同样输入若产出不同字节(时间戳/随机 chunk 名/构建机器差异),这道闸会**随机红** ——
  那就是把报警器换成了噪音源,比现状更坏。⇒ 列为开工前闸 P0,不过不许写实现。
  已有旁证:08-24 两次独立 build 的内容哈希文件名均为
  `index-DrDJWOTn.css` / `index-nULi_wUm.js`,但**旁证不算,要专门连跑比对**。
- **每次总跑多花 ~3.2 秒**(总跑约 2.5 分钟 ⇒ +2%)。可接受;换来的是 37 个场景
  从"裸奔"变成"验的确实是当前产物"。
- **依赖 `web/node_modules`**。没装时 build 会失败 ⇒ 闸 BLOCK。这是对的
  (没有 node_modules 时 e2e 本来也跑不了),但**必须给可读的话**,不能甩 npm 栈。
- **内存**:build 峰值 239MB,本机可用 ~772MB。闸跑在所有场景之前,此时尚未起浏览器,
  不与 playwright 争内存。
- **单独 `node tests/e2e/xxx.e2e.mjs` 绕过总跑时不受这道闸保护。** 接受:
  `run-all.sh` 带 filter(`run-all.sh focus_ring`)是推荐的单跑方式,它照样过闸。

## Alternatives considered

- **闸改比 src 内容哈希** —— 否决。哈希把注释也算进去,「只改注释」照样报警,
  和比 mtime 同一个毛病。**这是我自己提过又自己推翻的方案,记在这防止有人再提。**
- **保持比 mtime,只把 8 个 `mutation-*.sh` 的 `cp` 改成 `cp -p`** —— 否决(治标)。
  它消掉的只是当前这一个干扰源;时间戳还会被切分支/复制/解压刷新,
  **而且漏报那一面(src 改了、dist mtime 因无关动作变新 ⇒ 闸绿而产物是旧的)一点没动。**
- **每次跑 e2e 前自动 `npm run build` 修复** —— 否决。快,但**抹掉信号**:
  「源码改了没 build」这件事本身要被看见。闸的职责是报告,不是替人干活。
- **闸退场,改成收口时人工跑一次比对** —— 否决。`run-all.sh` 存在的理由恰恰是
  「30 个 e2e 没人记得总跑,烂了 6 天没人发现」。靠人记得在这个项目已被证伪过一次。

## Test strategy (oracle)

判据 `tests/test_dist_freshness_gate.py`(python,能被全量回归自动带上),
逐条**真调** `tests/e2e/check-dist-fresh.sh`,在临时 worktree/副本上造场景:

- **O1 真过期咬得住**:改一处**会改变产物**的源码(真 CSS 规则或 TS 代码)且不 build
  ⇒ 闸必须 **rc≠0**,且输出里点名差异文件。
- **O2 只改注释不误报**:只加 CSS/TS **注释**(本次事故的原样形状)⇒ 闸必须 **rc=0**。
  ← 这条是本单存在的理由,也是旧闸和 src-哈希方案都会挂掉的那条。
- **O3 build 失败不静默放过**:喂一个语法错误的源文件 ⇒ 闸必须 **rc≠0**,
  且输出里带得出 build 的报错原文(不许只说"失败了")。
- **O4 不污染工作树**:闸跑完,`web/dist` 逐字节不变、`git status --porcelain` 不新增条目、
  临时目录已清理。
- **O5 build 确定性(前提)**:连续两次 build 到不同临时目录,产物逐字节相同。
  不成立则本方案作废。
- **O6 rc 真的传得出去**:`run-all.sh` 在闸红时**整体 rc≠0 且不继续跑任何场景**。

红检(变异)至少要咬住:把比对从"内容"退回"文件名"(O1 变体:内容变而名不变的情形)、
把闸的调用改成 `;` 接(O6 必红)、把 build 失败吞掉(O3 必红)、
把闸退回比 mtime(O2 必红 —— 这就是新旧闸的**对照组**)。

**这个 oracle 能被什么骗过?**

- **两边都空 ⇒ 恒绿。** build 没产出任何文件、而比对函数把"两边文件集合都为空"读成一致。
  断言全绿,而这道闸实际什么都没守。⇒ 接住它:O1 的真变异必须红,**且**闸自己要断言
  产物文件数 > 0,判据里显式验这一条。
- **只比文件名不比内容。** vite 现在给 js/css 带内容哈希,所以"名同=内容同"**碰巧**成立;
  但 `index.html` 不带哈希。改了 index.html 模板就会漏。⇒ O1 必须有一个变异落在 `index.html` 上。
- **rc 被 `;` / 管道吃掉。** 闸红了但 run-all.sh 照跑照报绿 —— **这个项目栽过五次**,
  是最可能的失败形态,所以单列 O6,并在红检里专门变异它。
- **闸压根没被调用**(写进了某个条件分支、或只在 `--with-gateway` 时跑)。
  ⇒ O6 走**默认路径**(不带任何参数)验证。
- 断言全绿但结果仍然错会错成什么样:**e2e 全绿,而验的是上一版的前端** ——
  也就是 0.91→0.93 这三个包一直处于的状态。那种错**只有比产物才接得住**;
  真机/截图都接不住(界面看着正常,只是少了你以为已经生效的那次改动)。
