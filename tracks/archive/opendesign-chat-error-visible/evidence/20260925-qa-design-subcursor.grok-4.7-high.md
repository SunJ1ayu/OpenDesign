先核对仓库里的需求描述和现有界面说明，再按真实用户能看见的结果写测试设计。
轨道文档还是空模板。接着核对界面上用户能看见的文案和聊天入口，确认任务里的说法和产品对得上。
Direction: 验收只盯「这条聊天记录里多出来的那一句中文出错回复」：发出去之后不用离开页面就能看见，离开再回来还是这一句，并且和正常回复一眼能分开。错 key、欠费、限流、连不上、认不出的错误、主动通知、三个聊天栏，都套这同一条记录，不另起一套「后台有没有记错」的判据。

Core bet: 设计师以为软件坏了，是因为「正在思考」的小动画转完后对话是空的，回来才看到英文原文。修好的标志是这句人话从失败被确定的那一刻起就留在这轮对话下面。后台重试多久、错误码怎么分类，用户看不见，不拿来当通过条件。

How it works: 首页聊天先把五类失败各走一遍（错 key、额度用完或欠费、太频繁、连不上或超时或厂商出错、认不出的错误）。每一类只查三件事：主句用中文说清下一步去哪、厂商原文以小字附在后面、主句不出现厂商名字而是让人看输入框右下角现在显示的模型。然后用同一句中文去套组合和回归：切走再回来、改好 key 再发、出错后马上换模型、三个栏同时开着只有一个出错、带图发送、正常回复和灰色工具行不被多抄一条。设置页那句「未启用」文案单独看开关旁边的字。

Best at: 抓住会把人带去做错事的失败。错 key 却叫人去充值、欠费却叫人去改 key、思考动画消失后一片空白、回来变成英文，都是 P0。三个聊天栏（首页、项目助手、待办右栏）共用同一个全局模型按钮，按钮上写的是模型名，换模型对所有对话从下一句起生效；只在首页测会漏掉另外两栏自己的记录。

Sacrifices: 不规定整句文案，只规定必须让用户看懂的那几个意思（「设置 → 模型设置」「测试」、余额充值、稍等再发、检查网络、「模型那边出错了」）。不测重试次数，不测飞书有没有推送，不测升级前已经存在的旧英文记录，也不测「未连接聊天服务」那条琥珀横幅——那是 OpenDesign 自己没连上，此时右下角连换模型按钮都没有。

Blind spots in the brief: 「马上出现」和现在「错 key 约 1 秒、限流/厂商出错/连不上约 7 秒（后台先重试）」撞在一起，思考动画允不允许占满这段等待，简报没说死。出错回复要指向「右下角当前那家」，但按钮显示的是模型名，不是厂商名；出错后再换模型，旧句子里的「当前」会指到另一家。仓库里的定时提醒写的是推到飞书，简报要改成桌面里的助手回复，没说落在首页、项目助手还是待办栏。设置页把聊天藏起来但不卸掉，人在设置里时出错算不算「切走」。开关旁边看得见的字是「未启用 / 已启用」，读屏名称却是「启用供应商 / 禁用供应商」。工具那行灰字在一轮结束时会被清掉，出错前若已经闪过「查了待办清单」，失败后灰字还留不留，简报没写。

Smallest first step: 只在首页、当前模型的 key 是错的这一条上先定稿：发出一句话，思考动画结束后不用切页面就有一条中文助手回复；切到设置再回到这条聊天，还是这一句中文，下面小字仍是厂商原文。开发按这个做，其余错误类型套同一副骨架。

假设：重试那几秒里可以继续转思考动画；中文回复出现在这一轮已经失败的那一刻，之后对话不再是空白。三个栏各记各的，模型是全局的。主动通知先假定出现在用户当时正看着的那一栏。修复前留下的英文旧记录不在本单。

## 1. 用户故事 + 验收标准

**故事 A：发完就知道是哪类问题**

- Given 首页聊天已连上，右下角显示着当前模型，这家的 key 是错的。
- When 发出一句话。
- Then 思考动画结束后，这条用户的话下面出现一条助手回复。主句是中文，让人去「设置 → 模型设置」重填右下角这家的 key，并提到可以点「测试」。厂商原文以更小的字附在后面。主句里不出现 MiMo、DeepSeek、Kimi、GLM 或自定义供应商的名字。输入框可以接着打字发送。

- Given 当前这家是额度用完或账户欠费。
- When 发出一句话。
- Then 中文主句让人去厂商那边看余额、充值。不把下一步说成去模型设置改 key。小字仍是厂商原文。

- Given 当前这家因为太频繁被拒绝。
- When 发出一句话。
- Then 中文主句让人稍等一会儿再发。不叫人去改 key 或充值。

- Given 电脑到这家厂商的网络不通，或请求超时，或厂商服务器出错。
- When 发出一句话。
- Then 中文主句让人稍后再试。网络不通时同时让人检查网络。超时和厂商出错不叫人去改 key。

- Given 厂商返回的错对不上上面几类。
- When 发出一句话。
- Then 主句里有「模型那边出错了」，并给出下一步（稍后再试，或去看右下角这家）。小字附上原文。

**故事 B：离开再回来还是这一句**

- Given 上一轮已经在聊天里出现那条中文出错回复。
- When 切到设置、待办或另一个项目，再回到原来这一栏。
- Then 看到的仍是同一句中文主句加小字原文，不是单独一条英文，例如不会只剩 `Error: {'message': 'Invalid API key', ...}` 或那句 quota / arrears 英文。

**故事 C：改好再发就正常**

- Given 刚才因为 key 不对出过错，输入框仍能用。
- When 到「设置 → 模型设置」把右下角这家的 key 改对，点该模型行的「测试」得到 key 可用的人话，回到聊天再发一句。
- Then 新的一句得到正常助手回复。上面那条出错回复还在，不会变成第二条英文，也不会把新回复盖掉。

**故事 D：一眼能看出这是出错**

- Given 同一条对话里既有以前的正常助手回复，也有这次的出错回复。
- When 看着这两条。
- Then 出错那条在底色、标记或版式上和正常回复不同，不用读完才知道这是出错。正常回复没有这个标记。

**故事 E：主动发来的话也能看见**

- Given 用户没有刚按下发送，助手在后台送来一条定时提醒或中途通知。
- When 人正看着某个聊天栏，或切走再回来。
- Then 这条内容以助手回复出现在该栏记录里，不再是空白。它用正常回复的样子，不用出错那套标记。

**故事 F：未启用的保存提示和开关一致**

- Given 「设置 → 模型设置」里某一家开关旁边写着「未启用」。
- When 给这家存上一把 key。
- Then 提示里的叫法和开关一样，使用「未启用 / 已启用」。不再写「在上面打开「启用」」。

## 3. 探索式测试任务

1. **目标：** 错 key 时人会不会自己找到该改的地方。**重点：** 只看主句，不先读小字。能不能顺着句子走到「设置 → 模型设置」、找到右下角那个模型、点到「测试」。句子里如果出现了另一家的名字，或叫人去充值，记下来。
2. **目标：** 欠费和断网会不会把人带去改一把其实没坏的 key。**重点：** 欠费时句子是否只谈余额；拔网线或关掉到厂商的网络时是否同时提到检查网络。网恢复后下一条是否直接正常，中间不用重启软件。
3. **目标：** 三个栏会不会串话。**重点：** 项目助手出错时，首页和待办栏的记录是否原样；三个栏右下角模型名是否始终一致；在一个栏思考时，另一个栏还能发送，并且各自留下自己的中文出错。
4. **目标：** 切页面的那几秒会不会把中文弄丢。**重点：** 动画还在转时切到设置（聊天被藏起但还在）、切到待办、切到别的项目，再回来。看的是空白、英文，还是同一句中文。带图的那条，图还在不在。
5. **目标：** 正常干活有没有被出错样式沾上。**重点：** 查待办时灰字还在不在、会不会变成出错回复；连续两轮正常回复会不会多一条；主动提醒长得像普通回复还是像出错。顺手看未启用那家保存之后，提示里的词和开关上的「未启用 / 已启用」是否同一套。

## 4. 需要产品负责人拍板的疑问

1. 限流、厂商出错、连不上时，后台会先重试，现在大约要 7 秒。这 7 秒里是继续转思考动画，失败确定后立刻换上中文回复，还是发送后马上就摆出出错回复、不再等重试？验收按前一种写。
2. 出错回复不能写厂商名，要指向右下角「当前」那家。按钮上实际显示的是模型名。出错之后若马上换模型，旧句子里的「当前」就会指到新的一家。旧回复是保持发送当时那一句不变，还是希望写成「发送时右下角那家」这种不会随换模型改口的说法？
3. 定时提醒在现有说明里是推到飞书。这次要在桌面聊天里显示时，落在首页、项目助手，还是待办栏？人当时不在那个栏，要不要在侧栏上有一个能注意到的记号？飞书那条还发不发，本单不测，除非要一起改。
