# 测试设计(QA,开发前):OpenDesign「模型出错时,聊天页要告诉我出了什么事」

你是这个团队的**测试工程师**。现在是测试设计阶段:**修复还没开发**。请站在**真实用户**的角度写测试设计。
**不要读代码实现**(黑盒测试;需要的信息都在下面)。不要写「以后有人改坏代码会怎样」「手工改配置文件 / 手删文件才会碰到」这类用例 ——
产品负责人明确说过这类是「有人拿锤子砸墙墙会不会裂」,不测。不要联网。

## 产品是什么
OpenDesign:室内设计师(产品负责人本人,不是程序员)用的 Windows 桌面 AI 助手(Electron 窗口)。
聊天要用大模型,模型来自几家厂商,每家填自己的 API Key、扣各自的钱:MiMo(小米)、DeepSeek、Kimi、GLM 套餐、GLM 按量,还能「添加供应商」。
界面:左侧栏(工作区、聊天、设置);聊天有几个地方:首页聊天、每个项目自己的聊天栏、待办页的助手栏;
聊天输入框右下角有「换模型」按钮(显示当前用的模型);「设置 → 模型设置」页每家能填/改 API Key,每个模型行有「测试」按钮(会说人话告诉你 key 对不对)。
助手回复是一条条气泡;等回复时有「正在思考」的小动画;回复里调用工具时会冒一行灰色的「查了待办清单」之类。

## 现在的样子(要被修掉的)
- 模型那边出错时(API Key 填错、账户欠费/额度用完、请求太频繁被限流、厂商服务器出错、网络连不上厂商):
  发出一句话后,「正在思考」转一会儿(错 key 约 1 秒,限流/厂商出错/连不上约 7 秒,因为后台先自己重试)然后消失,**什么回复都没有,也没有任何提示**。
  用户以为软件坏了。
- 切到别的页面再切回这个聊天:那一轮下面冒出一句**英文原文**,例如
  `Error: {'message': 'Invalid API key', 'type': 'invalid_request_error'}` 或
  `The AI provider rejected the request because the API key is out of quota or the account is in arrears...`。
- 另一个小问题:设置页存了一家「未启用」厂商的 key 后,提示说「在上面打开「启用」」,而开关旁边实际写的是「未启用 / 已启用」。

## 要做成的样子
- 出错时,聊天里马上出现一条助手回复,用中文说清是哪类问题、下一步去哪里:
  key 不对 → 去「设置 → 模型设置」重填这家的 key,可点「测试」确认;额度用完/欠费 → 去厂商那边看余额充值;
  太频繁 → 稍等一会儿再发;连不上/超时/厂商出错 → 稍后再试(连不上时检查网络)。认不出的错误 → 说「模型那边出错了」并建议怎么办。
  厂商的原文以小字附在后面,方便发给别人看。
- 这条出错回复看起来和正常回复有区别(一眼看出这是出错,不是助手在胡说)。
- 切走再切回来,看到的是**同一句中文**,不再是英文原文。
- 出错后输入框照常能用,改好 key 后再发一句就正常回复。
- 这条提示**不点名是哪家厂商**(因为事后回看时软件不知道当时用的是哪家),而是指向「输入框右下角当前用的那家」。
- 同时:助手在后台主动发来的话(例如定时提醒、它中途发的一句通知)以前也会同样「看不见」,这次一并显示成助手回复。
- 小问题顺带修:提示文案改成对得上开关上的字。

## 这次请特别多想三类
1. **失败路径**:各种出错各自看到什么;出错叠着出错;网络断了又好了。
2. **组合场景**:两件事叠在一起(例如:出错后马上换模型再发;多个聊天栏同时开着、只有一个出错;出错时正好切走页面;带图发消息出错)。
3. **跨功能影响**:这次改动会碰到的别处(正常回复会不会多出一条重复的;工具调用那行灰字;历史对话回看;待办页/项目栏的聊天)。

## 请交付(中文,按这个格式)
1. **用户故事 + 验收标准**:每个故事写 Given / When / Then(用户看得见的结果)。
2. **测试用例表**:编号 | 优先级(P0 = 用户完成不了核心任务或被误导去做错的事 / P1 = 明显别扭或容易误操作 / P2 = 小问题)| 前置条件 | 操作步骤(用户怎么点)| 期望结果(用户看到什么)| 类型(主流程 / 失败路径 / 组合 / 边界 / 回归)。
