# Proposal: opendesign-chat-error-visible

- Date: 2026-09-25
- Status: open(0.98.14 三件里的第 1 件;后两件 = 输入框 5 条、侧栏方案一 + 二,各开一单,最后一张发版单)

## Goal

模型那边出错(key 不对 / 欠费·额度 / 限流 / 厂商出错 / 连不上·超时)时,聊天页当场出现一条中文说明:是哪类问题、去哪儿处理;
切走再回来看到的是同一句中文。顺带改设置页一句对不上开关文字的提示。

## Motivation

上一单(opendesign-key-restart)QA 执行录像第 9 步发现:key 填错后发一句话,「正在思考」转一下就没了,**没有回复、没有提示**;
业主会以为软件又坏了。该单 verify.md Q-1 延期、承诺发版后紧接着开单。

## 真问题(第一性)

- 用户原话:业主 09-25 12:5x「可以，就按你建议的来吧」(同意先修 Q-1 再做输入框,两样一起发 0.98.14);
  13:3x「直接方案一和方案二一起做吧」(后两件)。**Q-1 本身业主没有描述过**,是 QA 发现、我转述给他的。
- 真正要解决的是:模型调用失败时,业主**知道失败了、知道为什么、知道下一步去哪儿**,而不是对着没反应的界面猜。
- 我在这中间翻译了什么:① 「显示出来」→「说人话 + 指路」(业主不是程序员,英文原文等于没显示);
  ② 我交接时写过「哪家 key 不对」—— 探针证实网关给的错误里**没有厂商/模型字段**,回放也没有 ⇒ 改成指向「输入框右下角当前用的那家」,不点名;
  ③ 机制上把「所有没有 kind 的 message」都当完整助手消息显示(不只出错):按网关契约这类消息从不与流式正文重复,
  其中还有助手用 message 工具主动发的话、定时提醒、斜杠命令回复 —— 它们现在同样实时看不见。这一条扩大了可见面,是我提的,写在这里备查。
- 用户可观察的成功:在真网关 + 各种出错下,发出一句话后几秒内(错 key 约 1 秒;限流/厂商出错/连不上约 7 秒,网关先自己重试)
  聊天里出现一条看得出是「出错」的中文说明 + 原文小字;输入框解锁;修好 key 后再发一句正常回复;切走再切回同一句中文;
  正常对话不多出任何气泡。

## Scope

- in:`web/src/chat/transcript.ts`(无 kind 的 message 上屏 + 出错人话 + 回放同一函数);`ChatPage.tsx` 出错气泡样式与原文小字;
  `web/src/settings/modelSettings.ts` 那句「在上面打开「启用」」;对应判据(单测 + e2e);QA 设计 / 执行。

## Non-goals

- 不改 nanobot(钉版本、零改动底座);不在出错时自动去「测试」那家 key(那是新增默认自动动作,会多打厂商)。
- 不点厂商名(数据里没有)。不做「重试」按钮(业主改好 key 再发一句即可;输入框本来就解锁)。
- message 工具主动发来的**图片**实时显示不在本单(回放里本来就有;实时只显示文字)—— 若 QA 认为必要再议。

## 验收边界与轮次预算(要外审的单开工就写 —— panel 抽屉 4b)

- 这一单承诺:
  1. 五类出错(key / 欠费额度 / 限流 / 厂商 5xx / 连不上·超时)在聊天实时出现一条可辨认为出错的中文说明 + 原文;认不出的错误给通用中文说明 + 原文。
  2. 同一条在回放(切走再回来)显示同一句中文。
  3. 出错后输入框可用;正常流式回复、工具活动灰字、思考动画行为不变,不多气泡。
  4. 没有 kind 的非出错消息(主动通知等)实时显示为普通助手回复。
  5. 设置页那句提示对得上开关文字。
- 不承诺:真厂商(MiMo / DeepSeek / Kimi / GLM)各自的错误原文都能分对类 —— 没抓过的真原文分不对时落到「通用说明 + 原文」,
  不许错指方向(把欠费说成 key 错);「测试挡不住任意未来的错误实现」。
- 实质评审上限:2 轮。第 2 轮主要核验修复;用完有阻断就保持未完成,不自动续轮,延期项留在 verify.md、不自动开新单。
  **每轮派发前先跑 `track preflight opendesign-chat-error-visible`。**
