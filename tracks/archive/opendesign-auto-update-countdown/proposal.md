# Proposal: 启动时直接更新

## 当前要求（2026-09-17 用户修正，09-18 确认继续）

用户原话：“不需要倒计时，有更新直接更新然后进入软件就好了。”
track 名保留以连接既有证据；以下当前要求覆盖旧的倒计时/取消交互。

## 范围与验收

1. 启动先显示检查页；查到可自动安装的新版立即发一次 `{auto: true}`，不显示倒计时或取消按钮。
2. 检查与安装期间不挂载工作区；成功交棒只等待外壳重启，不能提前开放旧版工作区。
3. 无新版、自动检查关闭、不可自动安装或检查失败，进入现有版本；检查超过 35 秒中断只读请求，迟到响应不得触发更新。
4. 自动更新失败，进入现有版本并显示原因；回滚后提示失败，同版本仍只自动尝试一次，手动重试保持可用。
5. 使用中手动检查、重新开启自动检查，只检查，不自动安装。
6. 沿用既有后端校验、记账、锁与回滚；本轮不修改安装器、不新增后台服务。

验证：前端单测、浏览器完整启动流程、后端与 Windows 判定器、全仓检查、Windows 九场景。
版本号和正式发布不在本次实现范围，仍需用户授权。

评审预算沿用本单 2 轮：第 1 轮审旧方案，剩余第 2 轮核对既有修复及当前立即更新流程；不因断线重新计数。

# Proposal: opendesign-auto-update-countdown

- Date: 2026-09-17
- Status: open

## Goal

打开 OpenDesign 时如果查到新版:窗口里显眼处出现「发现新版 X,10 秒后自动更新」,可以点取消;
倒计时走完就走现成的一键更新(下载→校验→装旁边→换名→重启)。
**同一个版本在这台机器上自动试过一次(不论成败),以后打开就不再自动试**,只能手动点「更新」。

## Motivation

一键更新(0.98.4 起)要业主自己翻开设置、看见蓝点、再点「更新」。业主不会天天翻设置 ⇒ 实际上一直停在旧版。
查更新被限流那单(0.98.6)修好之后,「打开一次软件至少真查一次」成立了,这一单才做得了。

## 真问题(第一性)

- 用户原话:09-15 夜我给了四个选项,业主选「**提示几秒后自动更新 (Recommended)**」。那个选项的说明原文:
  「打开软件时发现新版，显示「发现新版，X 秒后自动更新」，可以点取消。更新时软件会自己关掉再打开，大约 1 分钟。
  同一个版本失败过一次就不再自动试，免得每次打开都卡住」。09-17「开始吧」。
- 真正要解决的是:**业主不用操心版本,新版自己装上**;同时**不许把他困在「打开→自动更新→失败→再打开→又自动更新」的循环里**。
- 我在这中间翻译了什么:
  - 「几秒」定成 **10 秒**(看得清、来得及点取消)。
  - 「取消」= **只管这一次打开**;下次打开还会再提示。「不再提示这个版本」业主没要,不做。
  - 「失败过一次」翻成「**自动试过一次**」:失败有一种是接力脚本换回旧版、再把旧版拉起来 —— 那时界面早没了,
    谁也来不及记"失败"。所以只能在动手前先记"我要自动试这个版本了",下次打开看到"试过、但还在旧版" = 那次没成。
    成功的那次反正已经是新版,"试过"不影响什么。
  - **只有自动那条路记账,手动点「更新」不记**:手动那条路一行不动(零回归面)。代价:手动点失败之后,
    下次打开还会自动再试**一次**(试完就记上)—— 有界,而且网络抖一下的情况下这次重试本来就是想要的。
  - 「打开软件时」翻成「**页面加载后的第一次自动查**」:业主手动点「检查更新」、或中途打开「打开时自动检查」开关,都不弹倒计时。

## Scope

- in:
  - 后端:查更新的回包加一个 `auto_update`(这次能不能自动更新 + 不能的原因);记录「试过的版本」;
    `POST /api/update/apply` 认 `{"auto": true}`,自动那条路在动手前先记账、记不下就不动手。
  - 前端:倒计时横幅(可取消)、自动更新进行中 / 失败的说明;设置里对"试过没成"的版本说一句为什么不再自动。
  - 判据:python 端点判据、node 单测、真浏览器 e2e、Windows 真机 e2e 加一条"换回旧版之后不再自动"。
- 版本号 bump 与发版:做完问业主(他还没装 0.98.6;这一版发出来可以直接手动装这一版)。

## Non-goals

- 「不再提示这个版本」、「现在就更新」按钮、稍后提醒 —— 业主没要。
- 撤回 / 最低支持版本开关(上一单 design 风险 7 转来的):坏版本的止损是**删掉那个 GitHub release**
  (订阅源和接口里都就没了),单用户场景不另造开关。
- 「打开时自动检查」开关在桌面版**记不住**(见 design 风险 2)—— 既有问题,本单不修,记账。
- 上一单转来的「三跳最坏 30 秒」「订阅源最大版 ≤ 本机时不问 API」:不改,理由见 design。
- 断点续传、签名清单。

## 验收边界与轮次预算(panel 抽屉 4b)

- 这一单承诺:
  1. 装出来的桌面版、查到可装的新版、这个版本没试过 ⇒ 打开软件后出现可见的倒计时横幅,10 秒后发起**自动**更新请求;
  2. 点取消 ⇒ 这次打开不会发更新请求;
  3. 同一个版本自动试过一次(成败都算)⇒ 以后打开不再倒计时,也不会被自动请求绕过去(服务端二次把关);手动点「更新」照常可用;
  4. 记不下"试过"⇒ 自动更新不动手(宁可不自动,不许无限循环);
  5. 不是安装包装的 / 后端不是桌面外壳起的 / 路径接力脚本处理不了 / 安装包信息不完整 ⇒ 不倒计时;
  6. 手动「检查更新」、中途打开自动检查开关 ⇒ 不倒计时;取消之后这次打开不再倒计时;
  7. 自动更新失败时,横幅上说人话,不只藏在设置里 —— 包括接力脚本回滚、旧版被重新拉起那种(重开后 10 分钟内打开时说);
  8. 记账文件只写在数据根的 `Logs\` 下(不破 t13 死线)。
- 不承诺:测试挡住任意未来的错误实现;回滚后旧版没被拉起来(关了不回来)时界面能说什么;断电级别的记账持久性以外的崩溃场景。
- 实质评审上限:**2 轮**。第 2 轮主要核验修复;用完有阻断就保持未完成,不自动续轮,延期项留在 verify.md、不自动开新单。
  **每轮派发前先跑 `track preflight opendesign-auto-update-countdown`。**
