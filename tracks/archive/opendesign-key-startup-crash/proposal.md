# Proposal: opendesign-key-startup-crash

- Date: 2026-08-16
- Status: open

## Goal

业主装了 0.88.0、填完 key 之后**开不了机**。这一单把那条崩溃修掉,并把"下次再出这种事
我能查得下去"的东西补上;顺带按业主当轮提的两条改窗口和标题。

## Motivation

0.88.0 是 08-16 白天刚发的包,17 份收据、四审三腿 PASS、五段总跑全绿 —— 业主装上去
**当晚就死在第一步**。这不是"又一个 bug",是**判据机与真机的形状差**:
出事那一行只有"填过 key 的机器"才执行,而判据机上从来没有 key.txt。

## 真问题(第一性)

- 用户原话:「关键是我输入apikey之后，就连不上，然后我关掉重启就报错了」
  「现在windows版本打开左上角出现的opendesign标题和我们本来有的前端opendesign冲突了，
  为什么不能不要外面那个框」「我们标题的opendesig后面还有一个. 这个可以去掉」
- 真正要解决的是:**装好的应用能用**。三件事按业主的感受排序 = 开得了机 > 连得上 >
  看着对。而我这边多出来的一件是:**上一次我查不下去** —— 两份真机日志摆在面前,
  仍然答不了"网关为什么死",因为外壳从来没打印过退出码。
- 我在这中间翻译了什么:业主说的"连不上"其实是**两个**独立故障叠在一起
  (网关无声死亡 + 重启后 NameError)。把它们当成一件事去修,就会修完一个以为好了。
  这次拆开了,并且**明说第二个至今没有根因**。

## Scope

- in: NameError 修复;重启收整棵树;重启不再被误报成崩溃;腿死了打退出码+日志尾巴;
  窗口改无边框 + 自绘按钮 + 原生拖拽/改大小;品牌名去掉那个点;两道新判据
  (发货代码名字存在性 / 外壳启动那条路真跑一遍)。

## Non-goals

- **不动就绪探测**。网关日志里那两坨 websockets traceback 是我们自己敲门造成的,
  难看但无害;唯一能去掉它的做法是改就绪判定,而"假就绪"比"日志难看"严重得多。
  这是查完之后有意识的降范围(原本列进了计划),不是忘了。
- 不追 22:32:11 那次网关死亡的根因 —— 这一版给的是**下次查得动**的能力(退出码),
  不是答案。没有证据就不写结论。
- 不重构 `dead_assertions.allow` 的按行号认人机制(今天第三次漂,只核正数字并留话)。
