我先核对仓库里的产品说明和这次快照差异，确认用户能看到的行为，再按真实使用路径写测试设计。
产品说明和设计里的用户可见行为已经对上。我再核对界面文案和上一单漏掉的路径，避免用例写成实现细节。
Direction: 用一条用户能看见的判据验收整单：聊天页在存 key 的全程不断线，下一句只扣按钮上写着的那一家。

Core bet: 业主 09-25 卡住的是「存完就连不上、换模型按钮没了」。修好的标志不是设置页多一个切换，而是 Windows 安装包上存 key 之后人还停在原来的对话里，右下角按钮一直在，下一句扣的是按钮上那一家的钱。

How it works: 下面的故事和用例都按窗口里能点、能看见的结果来写。聊天本来连着时，存任意一家（新填、改当前这家、添加带 key 的自定义供应商）都不应再出现「连接不上，gateway 可能没在跑」，也不用托盘退出。全新安装、还没有任何 key 时，第一次保存应出现「正在启动后台服务」，几秒后聊天自己连上、按钮出现。设置页模型行仍然只有测试 / 编辑 / 删除。

Best at: 把「断线」和「扣错钱」放在同一条路径上：正在等回复时去存 key、存完立刻发送、改了当前这家又马上换到另一家、错 key 不会静默退回本来能用的那家。

Sacrifices: 不测手改配置、手删文件、以后改坏代码。不把进程号、端口、环境变量写成用户步骤。源码老装法只留一条「仍提示请手动重启」。Linux 上端口被占用导致重启失败不在本单。

Blind spots in the brief: 「已保存，下一句对话起就用它」和「存 key 不会换掉当前模型」叠在一起，新填的那一家容易被读成下一句就改走它。全新安装只填自定义供应商时，连上之后右下角是不是已经停在这家，简报没写。第一次启动若超过「几秒」或起不来，简报只写了成功时的提示，没写人怎么走出来；现在的界面在连不上时有「立即重试」，旧提示才写「退出再打开」。

Smallest first step: 在一台已经能聊天的 Windows 安装包上先做 TC-01 和 TC-02。这两条不过，第一次填 key 和错 key 都先不用展开。

假设：验收用产品负责人自己的 Windows 安装包。错的 key 仍然算「存上了」，失败出现在「测试」或下一句对话，不在点保存的那一下。进行中的那一句用发出去时的那把 key 说完；新 key 从下一句开始。扣谁的钱，用「对的 key 能回复、错的 key 失败且按钮名字不变」来看，不看请求头。

## 1. 用户故事 + 验收标准

**S1 聊着的时候再存一家，不用退出**

- Given  Windows 安装包已经在聊天，当前是小米的某个模型，右下角换模型按钮看得见，DeepSeek 还没填 key。
- When  打开「设置 → 模型设置 → DeepSeek」，粘贴一把 DeepSeek 的 key 并保存，然后回到刚才那条聊天。
- Then  设置页出现「已保存，下一句对话起就用它」这一类话，不出现「正在重启」。回到聊天的这段时间里，不出现「连接不上，gateway 可能没在跑」，换模型按钮一直在，按钮上的名字仍是原来的小米模型。不点换模型就再发一句，仍是小米的回复。打开换模型，DeepSeek 出现在已填 key 的那一列里。

**S2 改当前这家的 key，下一句就用新的**

- Given  正在用小米，这把 key 能正常回复，换模型按钮在。
- When  在小米详情把 key 改成另一把并保存，立刻回到聊天再发一句。
- Then  保存后聊天不断、按钮仍写着刚才那个小米模型。若新 key 是有效的，这一句得到回复；若新 key 是错的，这一句失败，按钮仍停在小米，不会改成另一家并给出那一家的回复。句子和测试结果里都看不到完整 key。

**S3 刚装好，第一次存 key 自己连上**

- Given  全新安装的 Windows 版，还没填过任何一家 key，聊天页还没连上（换模型按钮不在）。
- When  在模型设置给小米粘贴一把有效 key 并保存。
- Then  设置页提示「正在启动后台服务，稍等片刻」这一类话，而不是「正在重启」。几秒后回到聊天，页面自己连上，不用点「立即重试」，也不用托盘退出再打开。右下角换模型按钮出现，菜单里至少有小米。发一句能得到小米的回复。

**S4 换模型仍然在聊天框里，不在设置列表上**

- Given  小米和 DeepSeek 都已填好 key，当前是小米。
- When  在设置页看 DeepSeek 的模型列表，只点某一行的空白处或名字；再到聊天页右下角点换模型，选中 DeepSeek 的一个模型。
- Then  设置页每一行仍然只有「测试」「编辑」「删除」，点列表不会把当前模型改成 DeepSeek。聊天框里选中之后，按钮改成那个模型并打勾，下一句走 DeepSeek。

**S5 失败了能自己回到能聊的状态**

- Given  已经有一家能正常聊天（小米 key 有效），聊天是连上的。
- When  分别遇到：DeepSeek 填了一把错 key；点「测试」时那家服务连不上；点保存时设置页提示保存失败。
- Then  错 key 仍然显示已保存，且只显示首尾几位。测试或改用那家之后，能看到看懂的失败，里面没有完整 key。小米不用退出软件就能继续回复。保存失败时不出现「已保存」，小米的掩码还在，聊天仍然连着；再存一次可以成功。

**S6 第一次没能把后台拉起来，人有路可走**

- Given  全新安装，还没有任何 key。
- When  存第一把 key 之后，聊天过了片刻仍然连不上。
- Then  聊天页看得到「连接不上，gateway 可能没在跑」和「立即重试」，而不是一直停在「正在启动」却没有任何下一步。点「立即重试」若这时服务已经起来，就自己连上并出现换模型按钮；若仍起不来，托盘退出再打开后，已保存的 key 仍是掩码，不用重填，打开后能连上并聊天。

**S7 源码老装法仍要人手重启**

- Given  不是 Windows 安装包，而是开发者用源码跑着，聊天已经连上。
- When  在设置页再存一家的 key。
- Then  提示「请手动重启」，不会假装已经自动生效。按提示重启之后，新的这家才出现在换模型菜单里；重启前当前模型不变。

**S8 别的功能不被这次改动带走**

- Given  升级前已经填过至少一家 key，并选定了一个模型；另有一条已经绑定定时任务的对话。
- When  安装带这次修改的新版本并打开；再存一家新的 key；等到下一次定时任务自己跑。
- Then  各家 key 仍是掩码，聊天按钮仍是升级前那个模型，发一句仍走这一家。存新 key 的过程中工作区、原来的聊天记录都还在。定时任务那一次仍走原来的模型，不会改去刚存的那一家。

## 3. 探索式测试任务

1. 目标：把业主 09-25 的原话走一遍。重点：先在已能聊天的窗口里新填一家 key，确认按钮从不消失、不用托盘退出；再到设置页模型列表上找「换模型」，确认那里仍然没有可点的切换，真正的切换只在输入框右下角；选中新的一家后下一句确实是那一家。
2. 目标：确认钱不会在「改 key」和「换模型」叠在一起时扣错。重点：当前这家改成错 key 后立刻发送应失败且名字不变；马上改选另一家应成功；再改回错 key 那家应再次失败。进行中的回复被存 key 打断时，已写出的半句不要变成断线。
3. 目标：全新安装只走自定义供应商。重点：保存后是「正在启动」而不是「正在重启」；连上前按钮可以不在，连上后必须自己出现；菜单里只有这家；内置厂商没有 key 的不出现；测试失败时文字里没有完整 key。
4. 目标：起不来或存失败时人走得出来。重点：保存失败不得说「已保存」；连不上时必须能看见「立即重试」，而不是永远「正在启动」。退出再打开后掩码还在，能接着聊，不用重新填。
5. 目标：看这次改动有没有碰到旁边。重点：自动更新后掩码和当前模型还在；工作区和项目聊天的记录还在；已有定时任务下一次仍走原来的模型，不改走刚存上的那家。

## 4. 需要产品负责人拍板的疑问

- 新填的是另一家（当前仍是小米）时，「已保存，下一句对话起就用它」里的「它」是这把新 key，还是下一次选到这家才用？按已定规矩，存 key 不会换掉当前模型。若这句话在「新填一家」时也原样出现，业主会以为下一句已经改走新的那家。请确认：这句话只在「改的就是当前这家」时使用，新填一家时改说「已保存，当前模型不变；要换到聊天框右下角去选」。
- 全新安装、只添加了带 key 的自定义供应商、后台刚连上时，右下角是已经停在这家，还是显示「选择模型」、必须再点一次才选中？这决定 TC-11 发第一句之前要不要先在菜单里点它。
- 第一次启动若超过「几秒」仍未连上，提示停在「正在启动后台服务」，还是改成现在聊天页已有的「连接不上」加「立即重试」，并写明可以托盘退出再打开？请定一个业主等得及的时间，超过就换后一种说法。
