# Design: opendesign-in-app-update

- Change: opendesign-in-app-update
- Status: draft

## 反锚定声明

本文件的方向在读任何外部意见之前落盘。业主 2026-09-07 当场问的
「成熟的软件工程也这么做吗」已经改过一次方向(逼出了备份/回滚那条,见 proposal 业界对照),
那一轮记在 proposal 里,不是这里的产物。

## Approach:**A + 备份回滚**,分两刀,第一刀本身就有独立价值

### 第一刀「只查不装」(D)—— 低风险,先落地
软件启动后(以及设置页里点"检查更新")去问一次 GitHub,发现有新版就在界面上说一句:
「有新版 0.99.0,更新说明:… 」+ 两个按钮:**"以后再说" / "更新"**。
第一刀里"更新"按钮先只做**打开下载页**。

⇒ 这一刀就已经砍掉业主五步里的三步(开浏览器、找仓库、翻 releases),
**而且完全不碰他机器上的文件**。它是 A 的前半段,不是另一条路,做完不用推翻。

### 第二刀「按下去就装好」(A)
"更新"按钮改成走这条链,**每一步失败都必须能回到"他还有一个能打开的软件"**:

```
1 下载   → 下到 %LOCALAPPDATA%\OpenDesign\update\ ,不碰安装目录
2 校验   → sha256 对不上 ⇒ 停,删掉,原样告诉他为什么(旧版一根毫毛没动)
3 备份   → 把整个 $INSTDIR 复制成 $INSTDIR.bak-<旧版本号>(43MB,磁盘上不值钱)
4 收摊   → 退出外壳/托盘/ds_web/nanobot(**跑着不能替换自己的文件**,.nsi:92)
5 安装   → 静默跑那个官方安装器(就是业主平时双击的同一个 exe)
6 拉起   → 重新打开
7 判定   → 🔴 **新进程自己在 /api/health 报出新版本号才算成功**
           成功 ⇒ 删备份;失败/超时 ⇒ **把备份换回去**,并告诉他"更新没成,已经退回旧版"
```

### 为什么不是 C(版本化目录 + 指针),尽管仓库里先写下的是 C

`opendesign-windows-installer` 的 tasks 第 229 行写着「版本化组件 + 指针在这一单落地」。
**我这一单不做它**,理由要经得起看:

1. C 解决的是**流量**(只下 1.1MB)。业主的痛点问过了,是**那五步手工活**,不是 43MB。
2. C 要先重构安装布局 —— 而安装布局是这个项目今年烧掉真机次数最多的地方
   (0.89 崩溃 / 0.90 黑窗 / 0.91 窗口栏 / 0.93 白屏)。**把更新功能压在一次布局重构上,
   等于把两种风险乘起来。**
3. C 的核心好处是"原子切换 + 能退回去"—— 而**第 3/7 步那对备份-回滚拿到了同样的好处的九成**,
   代价是一次 43MB 的本地拷贝。
4. 业界差量方案(Chrome courgette / Firefox partial MAR / electron blockmap)
   **全部带整包回落**。⇒ 整包这条路无论如何都要有,先做它不是绕路,是必经之路。

⇒ C 不是被否掉,是**排在后面**:等 A 跑稳、且真出现"嫌 43MB 大"的证据再做。

## Key trade-offs / risks

- 🔴 **信任根只有一条:HTTPS 到 github.com。** sha256 和 exe 同源(都在同一个 release 里),
  所以它挡得住**下坏了 / 半截包 / 中间人**,**挡不住"GitHub 账号被盗后换了资产"**。
  没有代码签名证书,这是明账,不假装有。(Sparkle 验 EdDSA、Firefox 验 MAR 签名,我们都没有。)
- 杀毒软件可能拦下"一个程序去启动另一个安装程序"。CI 上没有杀软 ⇒ **CI 绿不代表他机器绿**。
- UAC:装在 `$LOCALAPPDATA\Programs` 不需要管理员权限,所以**预期不弹 UAC** —— 但这是推的,要在 CI 上量。
- 第 4 步收摊如果收不干净(有个进程赖着),第 5 步会**悄悄跳过**被锁的文件 ⇒ 半新半旧。
  ⇒ 收摊后必须**确认端口和进程都没了**再往下走,不是发完退出信号就继续。

## Alternatives considered

- **B(自己发 zip + 自己写更新器)**:新增第二种发布物,而它不会被 `check-installer.py`
  那 23+7 条成品闸看住 ⇒ 多一种没人验的产物。否掉。
- **C**:见上,排后面不是否掉。
- **只做 D 就收工**:够诚实的一个选项,风险几乎为零。但业主明确要的是"应用内更新",
  D 只砍掉五步里的三步。⇒ D 作为第一刀落地,**不作为终点**。

## Test strategy (oracle)

**本机(无网络、无 Windows)判据** —— 全部喂录下来的真实 JSON 夹具,不打真网:
- `t1` 挑版本的逻辑**必须认预发布**:喂本仓真实的 `/releases` 响应(10 个全 prerelease)
  ⇒ 必须挑出 0.98.3。**变异:改成 `/releases/latest` 的语义(过滤掉 prerelease)⇒ 判据必须红。**
  (这条钉的就是 proposal 事实 2 那个"天生恒绿"的坑。)
- `t2` 版本比较按数比,不按字符串:`0.98.10 > 0.98.9`、`0.99.0 > 0.98.3`、`1.0.0 > 0.99.0`。
- `t3` 线上不比本地新时(相等、或本地更新的开发机)**不许提示更新**。
- `t4` sha256 对不上 ⇒ 拒绝执行,且**安装目录零改动**(断言目录树哈希不变)。
- `t5` 装完之后回显的版本号 ≠ 期望 ⇒ **走回滚路径**,且回滚后目录树 == 更新前的树(逐字节)。
- `t6` 收摊没收干净(造一个赖着的进程)⇒ **不许进入第 5 步**。
- `t7` 网络不可达 / 超时 / 返回垃圾 JSON ⇒ 安静地不提示,**不许把异常甩到界面上**。

**Windows CI 端到端**(`windows-package-probe.yml` 的兄弟支,真装真跑):
- `e1` 装 0.98.2 → 走一遍应用内更新 → 断言 `/api/health` 报 **0.98.3** + 截图里窗口在。
- `e2` 故障注入:把下回来的 exe 改坏一个字节 → 断言它拒绝安装,**且 0.98.2 还打得开**。

### 这个 oracle 能被什么骗过?

1. **CI 上没有杀毒软件、没有真实的 UAC 弹窗、没有他家那条网。** e1/e2 全绿,
   业主机器上照样可能被杀软拦在第 5 步。⇒ 这一条只有**他真机装一趟**能接住,
   而且要在他机器上**故意跑一次完整更新**,不是看见"有新版"就算验过。
2. **`t5` 的"回滚后目录树逐字节相同"在本机是拿假树测的**,真实的 `$INSTDIR` 里有
   运行时产生的文件(日志、缓存)⇒ 真机上"逐字节相同"可能天然不成立,
   判据会在真机上变成一条**恒红**或被放宽成恒绿。⇒ 断言要写成
   "**安装器管的那些文件**逐字节相同",范围要显式列出来,不是整棵树。
3. **最像绿其实错的形状**:更新成功了,但业主的**档案/设置/对话历史**被这次覆盖弄丢了。
   上面 7 条判据一条都问不到这件事。⇒ 必须单加一条:更新前后
   `%LOCALAPPDATA%\OpenDesign\`(数据根,不是程序根)**逐字节不变**,并在 e1 里也断言。
