# Proposal: config-merge-keeps-brain

- Date: 2026-08-06
- Status: open

## Goal

装机/更新时合配置,**不再把机主已经选好的大脑静默重置回模板默认**。

## Motivation

记忆里挂了两天的一条:「合配置会把大脑重置成 MiMo —— 无论打不打包都该修」。
真实形状比那句更具体:装完之后机主用 `/model` 或 `set_model.py` 换过大脑,
**下次更新再合一次配置**(不带 `--model`),模板的 MiMo 示例默认会把
`providers.custom.apiBase` 与 `agents.defaults.modelPreset` 原样盖回去。
**静默发生**,而机主不是程序员 —— 他看到的只是"助手突然变笨了",不会去翻配置。

## 真问题(第一性)

- 用户当场选的这一条(在我列的待办里点了它)。
- 真正要解决的是:**模板是"新装机的起点",不是"每次更新的真理"**。
  更新该带来的是新东西(新预设、新工具段),不是把机主的选择清零。
- 我在这中间翻译了什么:把"保住机主的大脑"翻译成"没显式指定就以目标文件已有的为准"。
  风险:目标文件里那个值可能是**坏的**(空串/占位符/悬空预设),忠实保留就是装完起不来 ——
  所以三种"看着像机主选择、其实不是"的形状都要分清。

## Scope

- in: `bin/ds_merge_config.py` 的取值优先级与收尾汇总;`bin/install.ps1` 的提示语;
  `tests/test_ds_merge_config.py`(3 + 3 条新断言)。

## Non-goals

- 不探活端点(要联网,离线脚本做不了;端点坏了 nanobot 自己会在聊天时报可见错误)。
- 不动 `apiKey` 一律写成 `${DS_LLM_KEY}` 的既有行为(流程内 key 走 key.txt)。
