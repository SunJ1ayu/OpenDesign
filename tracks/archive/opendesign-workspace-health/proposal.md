# Proposal: opendesign-workspace-health(工作区体检卡)

- Date: 2026-07-26
- Status: **方案已合并,尚未写码**

## Goal

一张卡,把「哪些文件夹被当成项目、依据是什么」摊开给用户看,并让他一键把**系统的猜测
变成自己的声明**。声明之后 `structural_dirs()` 第①层接管,后面两层启发式永久让位。
**成功标准是这张卡自己变得没东西可显示。**

## Motivation

工作区根目录下,软件必须判断「哪个文件夹是项目」。现在三层
(`ds_workspace.structural_dirs()`):①用户在 `workspace.json.structuralDirs` 里声明过的;
②没声明就按规则表里**确实存在于根**的常见名字猜;③都不中 → 不排除。

猜错的两种后果**严重程度差很远**:
- 轻:没认出收件箱 → 混进待建档列表,碍眼而已。
- **重:把真项目猜成结构目录 → 那个项目从列表里消失。**

现状只有一条**看得见但改不了**的被动提示(`web/src/workspace/Sidebar.tsx:208`
显示「XXX 当作结构文件夹,没列为项目」,是 chat-image-p2 四审的产物)。

本单当初被 `tracks/archive/opendesign-chat-image-p2/proposal.md:36` 明确推迟,
原话:「**不做**工作区体检卡/提议创建结构目录(那要写配置 + 让网页命名目录,是新写面,
单独一单吃 full 四审)」。

## 真问题(第一性)

- **用户原话**(来自 `ds_workspace.py` docstring 记录的原话,非本次会话):
  「不要写死目录名,因为用户的目录名不一定跟我的一样」。
  **本次会话用户没有直接提这个需求** —— 他要的是「从 OpenDesign 挑一件真需求」来试跑
  新工作流(GPT 执行腿 + 同步出方案),具体挑哪件是主 agent 定的。**若用户认为该换一件,
  以他为准。**
- **真正要解决的是**:不是「让用户配置结构目录」,而是「**别让我的猜测悄悄吞掉他的项目,
  而他连纠正的入口都没有**」。
- **我在这中间翻译了什么**:把「体检」翻译成了**文件系统层**(哪些文件夹算项目),
  而不是 PKB 内容层(档案有没有断链——那是 `ds_lint` 的活)。**这个转译是本单的地基,
  推错了后面全错。** 依据:被推迟时的原话说的是「写配置 + 命名目录」,是文件系统层。

## Scope

- in:卡片显示工作区位置、项目从哪读、找到几个项目;根目录每个一级文件夹一行,
  标明**当前状态 + 依据**(「你声明过」/「按常见名字猜的」/「没人说过,默认当项目」)。
- in:二选一开关「显示 / 不显示在项目列表」;保存前给一句**结果预览**。
- in:新写口,一次存**整份清单**(不是一次改一个名字,理由见 design.md A2)。
- in:入口取代 `Sidebar.tsx:208` 现有的被动提示。

## Non-goals

- **不建目录、不改名、不搬文件。** 缺收件箱 → 指向已有的「帮我建收件箱」
  (`InboxCard.tsx`,人点才建、服务端解析路径)。**不新开任何造目录的口** ——
  这正是本单当初被推迟的原因,选择**绕开**而不是解决它。
- 不做内容启发式(不读文件内容猜用途)。
- 不做 PKB 内容体检(断链/缺字段)—— `ds_lint` 已经在做,混进来会变成四不像。
- 不自动修复损坏配置(只提示,不「顺手修好」)。
- **界面措辞只能是「显示/不显示」,绝不能说成「设为收件箱」** —— 见 design.md 盲点①。
- 不做批量「一键全部修复」。
