# QA 测试设计原文:subcursor.grok-4.7-high(09-24 16:15 派,题面 20260924-qa-test-design-brief.md)

## 1. 用户故事 + 验收标准

**S1 用上小米最新模型**
- Given 已装 Windows 版，小米 key 已填好，当前正在用小米的一个旧模型。
- When 打开「设置 → 模型设置 → MiMo(小米)」。
- Then 模型列表里看得到 `mimo-v2.6-pro` 和 `mimo-v2.6-flash`。回到开始聊天的页面，右下角点模型，移到小米，能选中 `mimo-v2.6-pro`；按钮改成这个名字，这一行打勾。发一句后仍是这个名字，回复来自这把小米 key（key 错时看到的是小米的失败，不是另一家的正常回复）。

**S2 以后的新模型自己加上去**
- Given 小米 key 已能用，列表里还没有某个新的模型 ID。
- When 在小米详情点「添加模型」，填模型 ID 和上下文窗口，保存，再点该行「测试」。
- Then 这一行出现在小米列表里，测试给出成功或看懂的失败，且失败文字里没有整段 key。重启那几秒过后，换模型菜单的小米子菜单里能选到它，选中后勾在这个新 ID 上。

**S3 存另一家的 key 不换掉正在用的模型**
- Given 正在用小米的 `mimo-v2.6-pro`，DeepSeek 还没 key。
- When 在 DeepSeek 详情粘贴 key 并保存。
- Then 页面提示已保存、后台正在重启。聊天按钮仍是小米的 `mimo-v2.6-pro`，勾仍在小米这一家、这个模型上。重启完成后 DeepSeek 才出现在换模型菜单里；不点它，聊天仍走小米。

**S4 换模型时知道扣的是谁**
- Given 小米 key 有效，Kimi 填了一把无效 key，两家都已启用。
- When 在开始聊天页打开换模型框，点到 Kimi 的某个模型。
- Then 只有 Kimi 那一行打勾，子菜单里只有刚选的模型打勾。再发一句，聊天失败，按钮仍写着 Kimi 的那个模型，不会改回小米并给出小米的回复。

**S5 整页设置，更新入口还在**
- Given 侧栏「设置」旁已经出现「重启以更新」。
- When 点「设置」。
- Then 整个侧栏变成设置栏目：返回工作区、常规、模型设置。常规里仍能看到原来弹层里的外观、工作区文件夹、危险动作确认、快捷键，以及软件更新的当前版本和「检查更新」。侧栏「设置」那一行上的「重启以更新」还在原处，点它会去安装更新。点「返回工作区」回到项目列表，聊天还在。

**S6 换模型框照 ZCode 的两级样子**
- Given 至少两家已填 key 且启用，当前是其中一家的某个模型。
- When 在开始聊天页右下角点模型按钮。
- Then 弹出的是每家一行（只有已填 key 且未禁用的），当前那家打勾。移到某一家，向右弹出该家模型，当前模型打勾。最底一行「管理模型」打开设置页，并且左边已经选中刚才那一家。

**S7 禁用和删除不会把正在用的换掉**
- Given 正在用小米的某个模型，DeepSeek 也已填 key。
- When 在小米详情尝试禁用小米，或对正在用的那个模型点删除。
- Then 两处都做不成，并看得到要先在聊天里换成别的。当前勾选不变。改去禁用 DeepSeek 后，换模型菜单里没有 DeepSeek，DeepSeek 详情里 key 仍是首尾几位。再启用后，不用重填 key，DeepSeek 回到菜单里。

**S8 自定义供应商（仅 Windows 安装包）**
- Given Windows 安装包，已有一家在用。
- When 点「添加供应商」，填写名称、Base URL、API Key，API 格式处只能看到 OpenAI 兼容的 Chat Completions，并带至少一个模型，保存。
- Then 左栏「自定义供应商」出现这一家，状态点表示已配好。测试有结果。重启完成后换模型菜单能选到它。Base URL 写成某一家内置地址时，保存被拒绝，左栏不出现这家，当前模型不变。

**S9 key 不在界面上露原文**
- Given 某家已经存过 key。
- When 打开该家详情，并点 API Key 的显示/隐藏。
- Then 两种状态下都只能看到首尾几位，或完全不显示；复制这一格也得不到全文。报错句子里同样没有全文。

## 3. 探索式测试任务

1. 目标：确认「填完就能选新模型」这条路一次走完。重点：小米页先确认 v2.6 已在列表，再手填一个真的新 ID，测试成功后立刻去聊天里找它。盯住重启那几秒：按钮会不会提前改字、测试会不会转圈到重启结束、失败时会不会把 key 打在句子里。
2. 目标：确认两家之间不会扣错。重点：小米用对的 key，另一家用错的 key。先存错的那家（当前模型不得变），再在菜单里换过去发一句，必须失败且名字停在那一家；换回小米后再发，必须恢复。顺手在 GLM 套餐和 GLM 按量之间各换一次，看是不是两行、两套勾。
3. 目标：确认禁用、删除、掩码不会把人锁死或把 key 露出来。重点：在用的那家禁用按钮、在用的模型删除按钮实际点下去的反馈；换走后再禁用，菜单消失但掩码还在；显示/隐藏和复制；内置模型没有删除。
4. 目标：确认设置改成整页后，老入口还找得到。重点：有「重启以更新」时，它是否仍在侧栏设置行；常规里的检查更新、工作区文件夹、关掉危险动作确认时的问句；返回工作区之后聊天记录还在，模型名没变。
5. 目标：对照 ZCode 把两级菜单和自定义供应商走一遍。重点：悬停移进子菜单会不会消失；「管理模型」是否落到刚才那一家；自定义供应商缺模型、Base URL 填成小米那条地址时是否拒收；API 格式是否不能改成别的。

## 4. 需要产品负责人拍板的疑问

- 「刷新」点下去，用户应该看到什么变化？现在只规定了按钮在，没有规定结果。
- 自定义供应商填错名字或 Base URL 之后，除了禁用，能不能整家删掉，或在详情里改 Base URL？页面说明里只有添加和禁用。
- 存完 key、后台还在重启的那几秒，状态点算「能用」还是「没配好」？要不要保留现在这句「已保存，正在自动重启后台服务，稍等片刻」？三个圆点本身说不清这件事。

Best at: 抓住业主原话里那件完成不了的事（选小米 v2.6）和扣错钱（换模型、存 key、禁用、套餐/按量、自定义 Base URL 撞车）。回归钉死这次搬家会碰掉的三件老功能：侧栏「重启以更新」、升级后 key 还在、聊天照常。

Sacrifices: 不测手改配置文件、不测清扫规矩本身、不测从厂商自动拉模型列表、不测 Responses / Anthropic 格式。上下文窗口只验数字改完后行上看得到，不验它如何影响计费。

Blind spots in the brief: 简报把「软件更新」整块放进常规，但设计已写明「重启以更新」留在侧栏设置行，常规只接版本、检查更新和重试。简报的三态圆点没有「已保存、还在重启」。`design.md` 前半和文末判据仍写「禁用会让当前模型回落」，与后定的 D3 相反；用例按 D3 和简报里的已定规矩写。现有界面 key 只显示末四位，新规矩是首尾几位且永不出原文，显示/隐藏不得看成 ZCode 那种看全文。

Smallest first step: 先在一台已填小米 key 的 Windows 安装包上走 TC-01、TC-03、TC-14：v2.6 能选中且仍扣小米、存 DeepSeek 不改当前勾选、侧栏「重启以更新」还在。这三步不过，后面的自定义供应商和样式不用展开。
