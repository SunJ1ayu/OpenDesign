# Proposal: opendesign-minimize-animation

- Date: 2026-08-23
- Status: open

## Goal

点右上角那个「缩小」按钮的时候,窗口要像别的 Windows 程序一样**向下收进任务栏**
(系统自带的那段缩小动画),而不是当场消失。

## Motivation

业主上一次验收(0.91.0 窗口栏)之后现场发现的:窗口没了,但没有任何东西告诉他
"它去哪儿了"。成熟产品那段动画不是装饰,它是**唯一**指向任务栏的线索。

## 真问题(第一性)

- 用户原话:「opendesign项目我上次验收之后发现,现在缩小按钮在页面上是直接消失
  不会像成熟的产品一样有向下缩小的动画,这个很重要 可以引导用户知道页面在底部」
- 真正要解决的是:**最小化之后"窗口去哪儿了"没有线索**。他要的不是"有个动画",
  是"看得出它收进了底下那条任务栏"。
- 我在这中间翻译了什么:把「向下缩小的动画」翻译成 **Windows/DWM 自己那段
  最小化动画**(窗口缩向它在任务栏上那个按钮),而不是"我们在网页里做一段 CSS
  缩放"。
  - 这个转译**站得住**的理由:他说的是「像成熟的产品一样」—— 成熟产品(记事本、
    浏览器)用的就是系统那一段;而且网页里的 CSS 缩放**动的是窗口里的内容**,
    窗口边框仍旧钉在原地,看起来只会更怪。
  - 这个转译**推错的话**会错成什么样:如果他其实见过某个程序有更花的自定义收起
    效果,那我交付的"和记事本一模一样"就不是他要的。风险低,且真机一眼可判。
  - 还有一条**不由我们决定**的前提:Windows 的「显示动画」总开关(设置 →
    辅助功能 → 视觉效果)关掉的话,**任何**程序都没有这段动画。真机清单第一条
    就是拿记事本对照。

## Scope

  应该还有类似的问题你能一起找一下吗 **先不动手改**」+「按成熟产品的交互体验,
  你也可以在 github 上找一些参考看看」)。
- in: 把「无边框之后 Windows 收走了什么」这一族**全部列出来**,每条标证据来源,
  给业主一份看得见的对照(artifact)。
- 交付的清单页:https://claude.ai/code/artifact/9261b67c-0ea1-479f-a807-2f407eb22a24
- 动手改的范围**等业主看完清单再定**(方案 A / B 见 design.md)。

## Non-goals

- **不碰最大化/还原**。那一套是我们自己算 Bounds 铺满工作区的(为了不盖住任务栏),
  它本来就没有系统动画 —— 业主这次没提,不顺手扩范围。
- 不自己用定时器画一段"窗口逐帧缩小"的假动画(会掉帧、会闪,且和系统不同步)。
- 不改托盘那条路(点 × = 收进托盘,不变)。
