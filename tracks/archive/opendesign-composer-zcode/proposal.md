# Proposal: opendesign-composer-zcode

- Date: 2026-09-25
- Status: open(0.98.14 三件里的第 2 件;第 1 件 opendesign-chat-error-visible 已归档 `464b55a`;第 3 件侧栏方案一 + 二;最后一张发版单)

## Goal

照 ZCode 改聊天输入框下面那一排,按业主同意的对照图「建议抄成的样子」(https://claude.ai/artifact/KoV7k7YqC82oyiEQx2knM6 ,「输入框」页)做五条:
①「+」变菜单(图片 + 三个技能);② 输入框里打 / 弹同一份技能表;③ 模型按钮前带厂商名;④ 发送换 ↑ 图标,回复中变 ■ 停止;⑤ 问候语按时间变。
同单还上一单留下的两条「下一单必须改」的欠账(Q3′ 原文标签、R1 英文系统句)。

## Motivation

业主 09-24 看过 ZCode 后觉得我们输入框「✎ 记一下」那颗按钮有点笨(对照图上我转述的原话:「你说的「有点笨」」)——占一个位置只干一件事;
回复跑偏了只能干等;模型按钮看不出扣哪家的钱。我出了对照图和五条建议,业主 09-25 12:5x 同意。

## 真问题(第一性)

- 用户原话:09-25 12:5x「可以，就按你建议的来吧，然后还有昨天说的历史对话和项目怎么参考一下zcode」(同意对照图上的五条建议);
  13:3x「直接方案一和方案二一起做吧」(那是第 3 件侧栏)。五条的具体内容是**我提的**,写在对照图的绿色便签里,业主没有逐条改过。
- 真正要解决的是:① 常用的几件事(记一下 / 整理文件夹 / 找参考图 / 加图)有一个固定的地方找得到,不占输入框一排;
  ② 回复说跑偏了能马上打断,而不是等它说完;③ 发之前一眼看出这句会用哪家、扣哪家的钱。问候语是观感。
- 我在这中间翻译了什么:
  - 「停止」→ 用网关自带的 `/stop` 命令。**探针证实**(evidence/20260925-probe-stop.txt):网关立刻掐断厂商那边的流,
    回 `goal_status:idle` + 一句英文 “Stopped 1 task(s).”,**不发 turn_end**;已出来的半截回答存进历史;之后照常能聊。
    ⇒ 网页要自己把 idle 当成「这一轮结束」,并把那句英文说成中文(上一单欠账 R1 正好是它)。
  - 「厂商名」→ 设置页那家的名字去掉括号部分(MiMo(小米)→ MiMo;GLM 两家必须分得开:GLM 套餐 / GLM 按量)。
  - 对照图上菜单顶的搜索框、「引用某个项目 / 之前的对话」一段:**不做**(便签原话「第二步再做」;只有 4 项时搜索框是噪音,要按字筛就打 /)。
- 用户可观察的成功:在真网关 + 真界面里,① 点「+」看到图片和三个技能,点技能输入框里补好开头;② 打 / 弹出同一份表、键盘能选;
  ③ 按钮上写着「MiMo · mimo-v2.5」这样的字,换到 GLM 按量就写 GLM 按量;④ 回复中点 ■,一两秒内停下、输入框解锁、
  半截回答留着、出现中文「已停止」,切走再回来还是中文;⑤ 下午打开首页写「下午好」。原有的发图、拖图、Ctrl+V、Enter 发送、
  中文输入法选字不误发,一样都不能坏。

## Scope

- in:`web/src/chat/ChatPage.tsx`(输入卡)、新 `web/src/chat/composer*.ts`(技能表 / 打 / 筛选 / 问候语 / 厂商短名的纯函数)、
  `web/src/SkillsPage.tsx`(改为共用技能表)、`web/src/chat/transcript.ts`(idle 收尾、停止回话、R1 英文句)、
  `web/src/chat/modelError.ts`(Q3′ 标签;D2 那句对上新按钮)、`web/src/chat/inputHint.ts`(聊天输入框占位符;待办小框不动)、`web/src/chat/modelPicker.ts`(按钮文字)、
  样式;对应判据(单测 + e2e);QA 设计 / 执行。
- 欠账(上一单归档 verify.md 写的「必须」):
  - Q3′:出错说明里,网关换过的固定英文句,小字不再标「原文」;真透传的仍标「原文」。
  - R1:“Stopped N task(s).” / “No active task to stop.” / “Background task completed.” 不再原样英文上屏。

## Non-goals

- 不改 nanobot(钉版本、零改动底座);不做 ZCode 的模式、电脑操作、用量圆环、推理强度;不做菜单搜索框与「引用项目 / 对话」。
- 不做 Esc 停止(业主清单里没有;误触 Esc 会打断回复)。
- 停在工具执行中间时,已经在做的那一步(如记账、挪文件)会照常做完 —— 工具是独立进程,这是网关现有语义(与工具 30 秒超时同类),本单不改。
- 侧栏(第 3 件)、回复动画分支 brave-cannon(业主让云端处理)都不在本单。

## 验收边界与轮次预算(要外审的单开工就写 —— panel 抽屉 4b)

- 这一单承诺:
  1. 「+」菜单有图片 + 三个技能;点技能补好开头(不叠两个开头);「✎ 记一下」按钮消失;技能页与菜单用同一份技能表。
  2. 草稿以 / 开头时弹同一份技能表,可筛、可键盘选;筛不到或按 Esc 后 Enter 照常发送;输入法拼字时不误发、不误选。
  3. 模型按钮写「厂商短名 · 模型名」,GLM 套餐 / GLM 按量分得开;模型列表拿不到时退回现在的样子(只写模型名)。
  4. 发送是 ↑ 图标;回复中(含还在思考、没出字)变 ■;点了一两秒内停下、输入框解锁、半截回答保留、出现中文「已停止」,
     不上屏一条 “/stop” 用户气泡;回放(切走再回来 / 重开)同样是中文;停一个聊天栏不影响另外两个。
  5. 首页问候语按本机时间变。
  6. Q3′、R1 两条欠账落实。原有发图 / 拖图 / Ctrl+V / Enter / 输入法 / 模型菜单 / 出错说明行为不变。
- 不承诺:「测试挡不住任意未来的错误实现」;停在工具中间时那一步是否做完(见 Non-goals);网关以外的斜杠命令回话(如业主手打 /help)的中文化。
- 实质评审上限:**2 轮**(impact-risk=standard ⇒ 每轮 1 家)。第 2 轮主要核验修复;用完有阻断就保持未完成,
  不自动续轮,延期项留在 verify.md、不自动开新单。**每轮派发前先跑 `track preflight opendesign-composer-zcode`。**
