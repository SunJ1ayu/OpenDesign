我先读快照里的差异和仓库说明，核对产品描述和这次输入框改版的范围，再据此写测试设计。
仓库里只有一份说明：这是黑盒测试台，故意没有代码。`review.diff` 是空的，所以下面的验收全部按题面里用户看得见的行为来写，不靠实现猜测。

Direction: 开发前把这次输入框改版收成一份「用户看得见」的验收：三个聊天栏各聊各的，技能表只有一份，「■」只停当前这一次回复。
Core bet: 室内设计师真正会踩坑的，是停不下来、两个技能叠进同一句、以及斜杠和中文输入法抢 Enter；这三类在写界面之前用同一套 Given/When/Then 定死，比事后补用例更值。
How it works: 以题面五条改动加上两处文案为契约。主流程确认「+」、「/」、模型按钮、↑/■、首页问候能完成；失败路径按停止时机切片；组合按「两个控件同时活着」切片；回归核对题面点名还要保持的旧能力（发图、拖图、粘贴、Enter、输入法选字、模型菜单、技能页、三个聊天栏、历史、出错说明）。未发送的技能开头不写账本、不挪文件、不检索。
Best at: 让「记一下 / 整理文件夹 / 找参考图」三个入口的开头句、停止后的聊天样子、厂商按钮文案，在开发前就是同一份样例。
Sacrifices: 不测请求有没有真正 abort、不测计费、不测手改配置或手删文件。整理文件夹若已经确认并开始挪文件，停掉后只核对「助手不再继续汇报」，不要求这次把已做完的文件操作撤回。模型回答好不好不测。
Blind spots in the brief: 问候语没有钟点；改写类错误的新标签和三句系统英文的中文定稿没有文案；项目助手和待办的占位字没有改口；回复过程中输入框是否锁定没写；一个字都没有就停止时，气泡长什么样没写；「/参考」选中后，斜杠这几个字是换掉还是留着，只写了菜单的插入规则。
Smallest first step: 先定第 4 节里会改期望结果的四条（问候钟点可以后补），再用 TC-03、TC-04、TC-07、TC-13、TC-14、TC-16、TC-23 做一次开发前评审。这七条盖住「开头被叠成两个技能」和「停不下来 / 停错聊天栏」。

写进用例的假设（和拍板不一致时，只改对应期望）：

- 假设 A：回复进行中，这一处输入框锁定；「■」只停止当前回复，不把草稿发出去。停止后解锁。
- 假设 B：在「/…」里选中技能后，整段换成该技能开头，斜杠筛选字不留下。
- 假设 C：还在「正在思考」、一个字都没有就停止时，不留空白助手气泡，只留一行灰色「已停止」。
- 假设 D：三个聊天栏共用当前这一家厂商和模型；设置页名称去掉括号内的部分得到短名；自己起名的供应商原样显示，名字里的括号也保留。
- 假设 E：「/」弹出的是三项技能，不含「图片」；按技能显示名筛选。
- 假设 F：主动停止后，持久的系统行是灰色「已停止」。重开后仍是这句中文。

技能开头就这三句：`记一下:`、`帮我扫描整理这个文件夹:`、`找参考图:`。光标在开头后面，接着打字会插在开头和原来的文字之间。

## 1. 用户故事 + 验收标准

**故事 1：用「+」把技能放进当前这句话**

Given 我在首页、某个项目的「项目助手」，或待办页助手栏的输入框。  
When 我点「+」。  
Then 菜单第一项是「图片」，旁注「也可拖进来 / Ctrl+V」；下面是「记一下」「整理文件夹」「找参考图」。原来的「✎ 记一下」不在这一排。

Given 输入框是空的。  
When 我点「记一下」，或「整理文件夹」，或「找参考图」。  
Then 输入框里分别是 `记一下:`、`帮我扫描整理这个文件夹:`、`找参考图:`；光标在冒号后面；不用再点一次输入框就能接着打；菜单关上；这句话还没发出去。

Given 我已经打了「客厅墙面改成暖灰」，还没发送。  
When 我点「记一下」，然后直接打「甲」。  
Then 框里是「记一下:甲客厅墙面改成暖灰」。

Given 框里已经是「记一下:客厅墙面改成暖灰」。  
When 我改点「找参考图」。  
Then 框里是「找参考图:客厅墙面改成暖灰」，只有一个技能开头。

Given 我只点了技能，没按发送。  
When 我去看这个项目的变更账本、那个文件夹、参考图结果。  
Then 账本没有新的一条，文件还在原处，也没有新的检索结果。

**故事 2：打「/」选出同一份技能**

Given 输入框内容以半角 `/` 开头，后面还没有空格。  
When 我只打了 `/`。  
Then 弹出和「+」、技能页同一份的三项技能。

Given 弹出层还在。  
When 我打成 `/参考`。  
Then 只剩「找参考图」。我用 ↑↓ 移动高亮后，按 Enter 或 Tab，或直接点这一项。  
Then 框里变成 `找参考图:`，光标在后面，弹出层关掉，消息不发出。

Given 弹出层开着，框里是 `/参考`。  
When 我按 Esc。  
Then 弹出层关掉，框里仍是 `/参考`。

Given 我打的是 `/没有这个`，一项都对不上。  
When 我再看输入框，并在输入法没在选字时按 Enter。  
Then 不弹出技能表；这句按普通消息发出去。

Given 我正在用中文输入法，拼音还没上屏，框里以 `/` 开头。  
When 我按 Enter。  
Then 这一下是选字上屏；技能不会被套上，拼音也不会被发出去。

**故事 3：图还是从「+」、拖、粘贴进来**

Given 任意一处聊天的输入卡，当前少于 4 张图。  
When 我从「+」点「图片」，或把图片拖进输入卡，或按 Ctrl+V。  
Then 图片出现在输入卡里。

Given 已经有 4 张。  
When 我再用这三种方式加一张。  
Then 仍然是这 4 张。

Given 草稿里已经有图，也有一段文字。  
When 我再选一个技能。  
Then 图还在，技能开头补在文字前面，不发送。

**故事 4：模型按钮能看出是哪家的钱**

Given 设置里当前是这些厂商之一，并选了一个模型。  
When 我看输入卡上的模型按钮。  
Then 文字是「短名 · 模型名」。对得上的例子：`MiMo · mimo-v2.5`、`GLM 按量 · glm-5.1`、`DeepSeek 官方 · deepseek-v4-flash`。`MiMo(小米)` 显示成 MiMo，`GLM 套餐(Coding Plan)` 显示成 GLM 套餐，`Kimi 按量` 显示成 Kimi 按量。自己起的名字原样出现在圆点前面。

When 我点开按钮换成另一家、另一个模型。  
Then 按钮马上变成新的「短名 · 模型名」。三处聊天栏上这个按钮是同一句（假设 D）。

**故事 5：说到一半可以停下，再接着说**

Given 我刚发出去，助手还在「正在思考」，一个字都没有。  
When 我点「■」。  
Then 思考动画消失；聊天里有一行灰色小字「已停止」；没有空白大泡；没有写着 “/stop” 的气泡；按钮变回 ↑；输入框可以马上再打再发。

Given 字已经出了一半。  
When 我点「■」。  
Then 已经出来的半截留着，并且不再继续往外长；旁边是灰色「已停止」；按钮为 ↑。

Given 我刚刚停过，输入框已解锁。  
When 我再打一句并点 ↑。  
Then 新的一条发出去，新的「正在思考」开始；上一截和「已停止」还在。

Given 我停完后切到别的页面再回来，或关掉窗口再打开这条对话。  
When 我看这条记录。  
Then 半截回答和「已停止」都在，是中文。

Given 停的那一刻，助手正在把「记一下」写入变更账本，或已经在执行我确认过的挪文件。  
When 我点「■」，再打开账本或那个文件夹。  
Then 助手不再继续汇报。账本里可能已经有这一条，确认后已经开始的挪动可能已经做完。没确认过的整理，文件仍在原处。

**故事 6：三个聊天栏各停各的**

Given 首页、项目助手、待办助手三处都在出字。  
When 我只在项目助手点「■」。  
Then 只有项目助手出现「已停止」；首页和待办继续出字。

Given 项目助手里有未发送的字和图片，首页正在回复。  
When 我切到首页再切回去。  
Then 项目助手的字和图还在；首页那条回复不被这次切换停掉。

**故事 7：首页空着时按时间打招呼**

Given 首页还没有聊天记录，当前时刻落在某个已定时段。  
When 我打开首页。  
Then 大字是「{早上好|中午好|下午好|晚上好|夜深了},今天想聊点什么?」，下面仍是输入卡和三个建议问法。

Given 首页已经有对话。  
When 我打开首页。  
Then 这句大字问候不出现。

**故事 8：出错和系统提示不会把人带跑**

Given 这一次失败，小字来自厂商自己的原话。  
When 我看这条粉色说明。  
Then 上面是中文出错说明，下面小字以「原文:」带上那句原话；按钮是 ↑，可以改完再发。

Given 这一次是欠费这类情况，后台给的是改写过的固定英文。  
When 我看小字。  
Then 小字不用「原文」这个标签（新说法等第 4 节定稿）；粉色中文说明仍在；按钮是 ↑。

Given 我主动停下一条回复，或一个后台动作已经跑完（记一下写完，或整理文件夹在我确认后做完）。  
When 我看聊天里因此多出来的系统行，包括切走再回来、关掉重开。  
Then 这些行是中文。转录里不出现 `Stopped 1 task(s).`、`No active task to stop.`、`Background task completed.`。

**故事 9：原来的发送和技能页还在**

Given 输入法没在选字。  
When 我按 Enter，或按 Shift+Enter。  
Then Enter 发送；Shift+Enter 只换行。三处都这样。

Given 我打开技能页。  
When 我点一张技能卡片。  
Then 开一段新对话，输入框里预先填好的开头，和「+」、「/」用的是同一句；不会改写我在另一处还没发送的草稿。

## 3. 探索式测试任务

**任务 1：把停止按成一种手感**  
目标：确认设计师在「想让它闭嘴」的几个瞬间都能停，并且马上能说下一句。  
重点：刚发出、思考动画、第一句冒出来、连续出字、马上要说完；停完两秒内再发；停的时候拔网线再点 ■。看着思考动画会不会转下去、半截会不会又长一截、按钮会不会停在 ■、会不会冒出粉色出错或英文。

**任务 2：用平时打字的方式选技能**  
目标：确认搜狗或微软拼音和「/」能一起用。  
重点：`/参考`、`/记`、`/文件夹`、筛空、行中间的 `/`、空格、Esc、↑↓、Enter、Tab。拼音没上屏时连按 Enter。菜单开着时拖进第 4 张和第 5 张。已有图片和半句话时换两个技能，看开头会不会叠。

**任务 3：三栏同时说话**  
目标：确认只停得住眼前这一栏。  
重点：三处同时发送，只停中间；停的同时另一处正在写「记一下」；停完切到设置、待办、再回项目，关掉重开。核对草稿、图片、「已停止」的中文，以及账本是否已有那一条。

**任务 4：把厂商和出错说明读给设计师自己听**  
目标：确认按钮不会让人用错一家的钱，出错小字不会把改写英文说成厂商原话。  
重点：五家内置加一个自命名供应商来回换，看三处按钮是否同时变。各走一次欠费类改写，和一次厂商原话。对照小字标签、粉色中文，以及出错后能不能立刻再发。

**任务 5：新入口不要替用户做主动作**  
目标：确认技能页、「+」、「/」只是把同一句开头放进输入框。  
重点：三个入口的开头并排对。只插入、不发送时看账本和文件夹。整理文件夹在确认前看文件还在不在；确认后再停，接受「可能已经挪完、助手不再汇报」。找参考图发出后，结果应是已入库的图。

1. 早上好、中午好、下午好、晚上好、夜深了，各自从几点到几点，整点算哪一句？首页一直开着、跨过时段时，大字要不要自己变？
