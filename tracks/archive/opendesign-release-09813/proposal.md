# Proposal: OpenDesign 0.98.13 发布(正式 release `v0.98.13`)

- Date: 2026-09-25
- 业主原话:09-25 10:1x 我问「如果这轮评审没有挡住发版的问题,要不要直接发 0.98.13?」,业主答「**可以发**」⇒ 授权推送 main + 创建正式 release。
- 发的内容(已归档 PASS):`opendesign-key-restart`(`23856a9`)—— 存 key 不再重启网关(网关现读 key 文件,照 ZCode 存了就用)、
  外壳子进程不继承管家 stdin(Windows 起网关卡死的根因)、全新装机第一把 key 把网关起起来、设置页提示按情形说真话。

## 本单做什么

1. 版本号 0.98.12 → 0.98.13(`bin/ds_web.py VERSION`、`desktop/package.json`、lock 根版本;只加第三位)。
2. 本地总跑;云 Windows `electron-e2e` 整跑 FAIL 0,从同一次运行取出货三样。
3. QA:两家测试员以业主视角看中文发版说明 + 业主真机清单;两家族发布评审。
4. 推送 main;照 `installer/RELEASE.md` 发布正式 release + 中文说明;发布后生产源 smoke(latest 指向 0.98.13、字节 = artifact、旧 blockmap `download/v0.98.12/` 在)。
5. 发布 + smoke 当天归档;业主真机回显事后补进已归档 verify.md。

## 验收边界与轮次预算

- 承诺:发出去的安装包来自云上测过的同一次运行、与被测版只差更新源;正式版三样资产;生产源 latest 指向 0.98.13 且字节一致;
  已装 0.98.12 的机器能从生产源看到 0.98.13。
- 发版说明(中文)要写:0.98.12 存 key 后连不上的病修了;存 key 后四种提示各是什么意思;存 key 不替他换模型;
  **老问题(key 填错 / 额度用完时发消息没反应)这一版没修、下一版修**,以及遇到时怎么查(模型设置里点「测试」)。
- 不承诺:业主真机结果(事后补记);Q-1(出错时聊天页不显示)不在本版。
- 实质评审上限:2 轮(impact=high:公开发布 = production_side_effect)。题面只问发布会不会弄坏东西;「锤子砸墙」类照报不算阻断。
