# Proposal: opendesign-turn-id

- Date: 2026-08-05
- Status: open

## Goal

给断线重连的「消息对账」一个**真身份**:把出站信封里的 `turn_id` 存进本地消息,
对账时按 turn_id 认人,不再靠"文本+角色"猜。顺带收口「界面说发出去了、其实没送到」。

## Motivation

`chat-reconnect`(0.75.0)四审 P3/F4 记过账、design.md 明写「判为成立但本单不做」:
重连后合并服务端历史与本地消息时,判"哪条是本地独有"用的是 `role\0content` 启发式。
后果:**同一句话说两遍、中间断了线,第二遍会被当成第一遍而消失** —— 用户的话凭空没了,
而且他没有任何提示。这是本项目"不许丢用户说的话"这条底线上的已知缺口。

08-05 协议探针(`scratchpad/probe_turnid.py`,对真 gateway 实跑)确认了地基:
webui-thread 回放里 user 消息的 `turnId` **逐字节等于**我们出站信封里填的 `turn_id`。
既然身份是现成的,就没有理由继续猜。

## 真问题(第一性)

- 用户原话:「可以 做完吧」(指 08-04 收工清单 A 组四条,本 track 是其中第 3 条;
  那条清单的原文是「把 turn_id 存进本地 ChatMessage,给重连对账一个真身份…
  做完顺带收口"界面说发了但其实没送到"」)。
- 真正要解决的是:**断线不能吃掉用户说过的话**。用户不关心 turn_id,他关心的是
  "我打过的字还在不在、系统有没有骗我说发出去了"。
- 我在这中间翻译了什么:把"消息别丢"翻译成了"给每条本地消息一个服务端也认识的 id,
  用它做对账"。风险:如果丢字的真因不在对账这一步(比如在 ws 发送那一步),
  这次改动看着对、用户照样丢字 —— 所以本单把「发送失败也要如实告诉他」一起做了。

## Scope

- in: `ChatMessage` 增 `turnId` 字段;`appendLocalUser` 收下它;
  `hydrateFromThread` 从回放的 `turnId` 里读回来。
- in: 重连对账从 ChatPage 里**提成纯函数** `reconcileThread(local, replay)`,
  按 turnId 认人、turnId 缺失时退回原启发式;单测咬得住。
- in: 发送失败(ws 已死 / `send()` 抛)不再假装发出去 —— 不上屏假气泡,给一句人话提示。

## Non-goals

- 不动协议、不动网关、不改 assistant 侧的对账策略(仍以服务端为准,四审 P3 的结论不推翻)。
- 不做「消息发送状态角标(发送中/已送达)」—— 那是产品决定,得用户先拍板。
- 不碰历史分页 / `before` 参数。
