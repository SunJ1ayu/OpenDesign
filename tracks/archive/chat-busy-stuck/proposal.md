# Proposal: chat-busy-stuck

- Date: 2026-08-06
- Status: open

## Goal

修一条真 bug:**新会话发第一句就断线,重连回来发送键永久变灰,只能刷新页面。**

## Motivation

0.75.0 的四审判过一条 P1(DeepSeek 孤发现):被掐断那一轮的 `turn_end` 按协议 §4
永远不会重发,而 `busy` 只由 `turn_end`/`error` 清 ⇒ 重连后必须在对账里清 `busy`。
当时**只修了成功那条路**:清 busy 的那行写在「拉不到历史就早退」之后,
而同一个函数上方的注释自己写着「**新建的空会话拉历史必然 404,实测**」——
于是最常见的那条路径整条绕过了它。

发现渠道:08-05 那条**超时无结论**的 Kimi 腿的日志(`panel-turnid.subkimi.log:1517/1525`)——
又一次印证「失败腿的日志也要读」。

## 真问题(第一性)

- 用户原话:(这条是我在复盘里挖出来的,不是用户报的)——但用户能看见的形状是
  「打字能打,发送按钮点不动,只能刷新」。
- 真正要解决的是:**"有没有历史"和"要不要解锁输入"是两件事,不许绑在一起判。**
- 我在这中间翻译了什么:把「清 busy」从"对账成功的副产品"翻译成"重连回来就该做的事"。

## Scope

- in: `web/src/chat/ChatPage.tsx` 的 `pullThread`(对账模式下拉不到历史也放掉 busy);
  判据补一幕 `㉜`;版本 0.76.0 → 0.77.0。

## Non-goals
