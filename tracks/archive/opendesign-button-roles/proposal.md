# Proposal: opendesign-button-roles

- Date: 2026-08-01
- Status: open

## Goal

把全应用**剩下 3 个按位置命名的一次性按钮 class** 收编到既有的三档角色 class
(`.btn-primary` 主 / `.btn-secondary` 次 / `.link-act` 文字),删掉重复定义。
**只收敛,不重画。**

## Motivation

用户连着三轮在同一件事上提意见(0.64 图墙两个按钮、0.65 收件箱「打开」、0.66「打开文件夹」),
**每次都是我改一处、他下次再指出另一处** —— 因为病根没动。一次收干净,这条反馈线才会停。

## 真问题(第一性)

- 用户原话(2026-07-31,原封不动):
  > 「收件箱的打开按钮,也是打开→ 比较丑,**有没有什么规范,正常的软件工程他们是怎么做的呢**,
  > 这种按钮和发送给项目助手聊天的这种按钮应该要有区别吧」
  > 「你说的打开文件夹我觉得也统一一下就好了,都用一样的白框然后里面字」

- 真正要解决的是:**不是"这个按钮丑",是"同一件事在不同地方长得不一样"**。
  用户问的是"有没有规范",答案是**规范早就有**(`app.css` 里三档 class,连用途注释都写了),
  **只是没在用** —— 只被用了 17 处,旁边一批一次性复制品在干同样的活。

- **病根是按位置命名而不是按角色命名。** `chat-btn`(聊天区的按钮)、`gallery-link`
  (图墙的链接)说的都是"它长在哪" —— **一旦被复制到别处,名字就开始撒谎**。
  0.65 抓到过现行:收件箱那个「打开」的 class 叫 `.gallery-link`,是从图墙「图墙 →」抄的,
  而那条链接用户 0.54.0 就让我删了。

- **我在这中间翻译了什么**:用户说的是"丑 / 统一一下",我翻译成"把重复的 class 收编到
  角色 class"。**这层转译有风险**:他要的可能是"重新设计一套好看的按钮",而我做的是
  "把现有的几种统一成现有的一种"。**取现在这个解读的理由**:他两次的具体指令都是
  「统一」「都用一样的」,没有一次说"换个样子";而且收敛之后要重画随时可以,反过来不行。
  **风险记在这里,真机验收时要问他一句"够不够,还是想换个样子"。**

## Scope

- in:`.chat-btn`(5 处)→ `.btn-secondary`;`.chat-btn.primary`(2 处)→ `.btn-primary`;
  `.go-link`(1 处)→ `.link-act`;`.rail-expand-link`(1 处)→ `.link-act`。
  三条 CSS 规则随之删除。**共 9 个使用点、3 个 class。**

## Non-goals

明确不做,理由记在这里免得被"顺手":

- `.send-btn` —— 聊天输入框里的一体化控件,不是独立按钮。
- `.connect-workspace` —— **描边赤陶 = 第三种视觉**(既不是实心主按钮也不是白框次按钮)。
  它是空态里的号召性动作。**「要不要有这一档」是规格问题,不是清理问题**,单独判。
- `.skip-btn` / `.group-select-btn` / `.icon-btn` / `.icon-act` —— 图标/行内控件,不同角色。
- `.seg .opt`(分段开关)、`.g-chip`(标签)—— 不同控件,不属于按钮档。
- **不重画任何一档的长相**。观感变化只允许来自"换成角色 class"这一件事本身。
