# Proposal: opendesign-anydoc

- Date: 2026-08-07
- Status: open

## Goal

让助手能**自己读到**项目 `01-资料` 里的文档(Word / PDF / Excel / PPT / CSV / EPUB),
而不是只能看着文件名干瞪眼。用 `firecrawl-anydoc` 做转换,新增两个只读 MCP 工具:
**先列、再读**。

## Motivation

`config/taxonomy.default.json` 把 `.pdf/.doc/.docx/.xls/.xlsx/.ppt/.pptx/.txt/.csv`
全归进项目内 `01-资料`,但助手**没有任何路径能读到里面一个字**:
`bin/disable_builtin_file_tools.py` 特意关掉了 nanobot 自带的文件工具
(历史原因:MiMo 曾用 `edit_file` 绕过安全层写进 nanobot workspace 而非 DS_ROOT)。

⇒ **`01-资料` 是个只进不出的抽屉**:东西归得整整齐齐,助手当它不存在。
业主问"合同上工期写的多久",助手答不上来,而那份合同就躺在它旁边。

## 真问题(第一性)

- 用户原话(2026-08-07):
  > "我觉得这个助手存在的意义就是让助手自己记得,对于我倾向于第二个他自己判断,
  > 只是我们需要前置条件,比如这个项目的word意见就在这个项目文件夹,这样不会读错对吧,
  > 还有日期也是一个关键,知道哪个是最新的"
- 真正要解决的是:**助手要不用人提醒就想起去翻资料**,而不是"多一个读文件的按钮"。
  我原本建议的是保守版(甲:你说了它才读),**用户明确选了乙(它自己判断)并给出两个前置条件**。
  这不是我要说服他改的地方 —— 他给的是产品方向,而且两个前置条件都指对了地方。
- 我在这中间翻译了什么:把"不会读错"翻译成**"助手不能自己拼路径,只能从工具列出来的东西里挑"**。
  这是本单一切安全性的地基;翻译错了,后面全错。

## Scope

- in:
  - `list_project_docs(project)` —— 列出该项目 `01-资料` 里的文档:
    文件名、**两种日期**(文件名里写的 + 文件修改时间)、大小、能不能读。**代码解析、代码排序。**
  - `read_project_doc(project, file)` —— 读其中一份,转成 markdown 返回,**不落库**。
  - `bin/install.ps1` 加装 `firecrawl-anydoc`(版本钉死)。
  - 助手契约里加一小段:**读了必须报出处**(文件名 + 日期)。

## Non-goals

- **不自动转换、不入库。** 认领时不把合同转成摘要写进 PKB —— 那等于让助手替业主
  决定哪句话重要,选错了没人发现;而且往助手契约里加规则已栽过两次(写长了压垮别的行为)。
- **不给写口。** 只读。这一单不碰 `disable_builtin_file_tools` 的任何一行。
- **不做 OCR。** 扫描件 / 拍照 PDF 读不出字,工具要**明说读不出**,不许助手编。
- 不接入 llm-wiki(2026-08-05 已判:领域外)。
