# Proposal: opendesign-instant-ui

- Date: 2026-09-23
- Status: open

## Goal

Electron 版(0.98.9 起)双击打开时,窗口一出来就是工作台界面,不再先挂一页「OpenDesign 正在启动…」等后台。

## Motivation

业主装上 0.98.9 后注意到:每次冷启动都先看到「正在启动」,而他参考的 ZCode 没有这一步。

## 真问题(第一性)

- 用户原话:「为什么启动都会有一个正在启动,zcode好像没有这个吧」;听完两种做法后:「直接学吧」(选的是「学 ZCode」那条,不是「只把加载页画成工作台的样子」)。
- 真正要解决的是:打开软件时不再有一段「只能干等」的空窗;一双击就是能看、能点的工作台。
- 我在这中间翻译了什么:
  - 事实:当前窗口约 0.3s 出现,「正在启动」约 3.5s 后才换成工作台(云 Windows 测试机,run 35750584881 的 E2.window / E2.ui);业主机器上的时长未知。
  - 事实:当前工作台页面由 Python 后台(ds-web,127.0.0.1:8766)发出,窗口要等后台报 ready 才能加载它;ZCode 把界面文件打进软件、窗口直接从本地加载(zai-org/ZCode@872ad96 `packages/desktop/src/main/desktopHostProcess.ts` loadWindow → `win.loadFile(renderer/index.html)`)。
  - 推导:「学 ZCode」= 界面不再依赖后台先起好;后台没好的那几秒,界面自己表达「还在连接」,而不是整页占位。
- 用户可观察的成功:冷启动双击后,窗口出来时就是工作台(侧栏、标题栏、页面框架),没有整页「正在启动」;后台就绪后数据自然出现,期间用到后台的功能有明确的「连接中」而不是报错或空白;后台起不来时仍有明确的出错提示并能退出。

## Scope

- in: Electron 外壳的冷启动路径(窗口首个页面从哪来)、工作台在后台未就绪期间的表现、打包进安装包的界面文件。
- in: 维持现有安全边界(ds-web 的 Host / 同站检查、外链跳转策略)不被削弱。

## Non-goals

- 不改后台本身的启动速度(Python 管家/网关/ds-web 的启动顺序与耗时)。
- 不改浏览器 / git-pull 方式打开工作台的路径(那条仍由 ds-web 直接发页面)。
- 不重做界面视觉。

## 验收边界与轮次预算

- 这一单承诺:
  1. 冷启动窗口的第一个可见页面就是工作台框架,不再出现整页「正在启动」;
  2. 后台就绪前,依赖后台的界面有可见的「连接中」状态,就绪后无需业主操作自动恢复正常;
  3. 现有功能(读写各页、聊天、图片、上传、更新提示、窗口按钮、外链)在新加载方式下行为不变;
  4. 后台起不来 / 版本对不上时,仍然弹出那一个错误框并退出(不留一个永远「连接中」的窗口);
  5. 安全边界不放宽。
- 不承诺:后台就绪时间变短;测试挡住任意未来的错误实现。
- 实质评审上限:2 轮(impact=high,每轮两家族)。第 2 轮主要核验修复;用完有阻断就保持未完成,
  不自动续轮,延期项留在 verify.md、不自动开新单。**每轮派发前先跑 `track preflight opendesign-instant-ui`。**
