## 对差异(B 卷改了我五处,其中一条我会直接发出去)

1. 🔴 **env 变量名不许写死 —— 这条我会栽**。B 卷实读发现:**Linux 那份配置引用的是
   `${MIMO_TP_KEY}`,不是 `${DS_LLM_KEY}`**(`config/nanobot.config.jsonc:15`)。
   重启逻辑要是硬编码变量名,**两台 git-pull 机器上网关必死**。
   ⇒ 从配置的 `apiKey` 字段里**读出它引用的是哪个 `${VAR}`**,再设那个变量。**采纳。**
2. 🔴 **外壳的启动流程必须改,否则引导页根本没机会出现**。今天 `start_backend` 是
   "缺 key 就整个 `die()`"(`ds_shell.py:170-178`)—— 那是在**开窗口之前**。
   B 卷指出正确形状:**ds-web 无条件先起(界面能开)、网关有 key 才起、保存 key 时再起网关**;
   `missing_env_message` 缺 key 那个分支随之退役。**采纳** —— 我 A 卷完全没想到这一层,
   而没有它这一单交付不出来。
3. **口令那件事的安全论证比我的准**:ds-web **已经有 Host 白名单**
   (`ds_web.py:688-698`)在挡远程页面;而 **8765(网关)必须继续要 token** ——
   那是 DNS rebinding 能绕过 ds-web 直连的**另一面**。
   ⇒ **两道屏障各守一面,别合成一道**。我 A 卷的"补来源检查"方向对,但要点是
   **别把 8765 的 secret 一起拿掉**(我原本就没打算拿,但没说清它为什么不能拿)。
   B 卷还点了两条残余风险,**采纳并写进文档**:①同机**另一个 Windows 账号**到 loopback
   现在能免密调聊天 API(建议顺带收紧 `<UserData>` 的 ACL);②将来谁把 ws 放宽到
   `0.0.0.0`,这套自动登录的防线就从"口令"变成"绑 loopback + Host 白名单"——
   **那是安全论证的迁移,不许当纯 UX 优化悄悄做**。
4. **判据从"扫我预期的那几面"升级成"扫整棵树 + 拦全部出站"**:
   在隔离 HOME 跑完整流程,断言 secret **恰好只在 `key.txt` 一处**、别处零命中;
   e2e 拦所有 client↔server 流量(body/header/URL)。
   **B 卷点破**:DSH 那份判据只查了浏览器侧三面(HTML/aria/console),
   **网络层拦截才覆盖"我没想到的那面"**。⇒ 采纳,并按它给的五条"会被什么骗过"补
   (变形/截断、扫不到的区域、只跑 happy path、白名单掩盖二次写入、判据自己的出口)。
5. **不许照抄 DSH 的"无 reload 就生效"**:他们是请求时惰性读凭据文件,我们是 env 注入,
   **做不到**。⇒ 判据改成断言**重连之后模型真的回了一句话**(冒烟问答),
   而不是"配置说 OK"。**采纳** —— 这正是"别把别人的结论当自己的前提"。

**B 卷提的、我判为不采纳/降级的**:它建议 git-pull 形态下由 **ds-web 自己重启网关**。
否 —— 那等于让 ds-web 变成第二个进程管理者(单实例锁就是防这个的),
而 git-pull 那两台是**我随时能上手的开发/自用机**,回一句"请重启一下"成本极低。
⇒ 仍按 A 卷:没有外壳就如实回 `manual`。

## 硬约束(先摆事实,方案要绕着它走)

1. **key 走环境变量进网关**:配置里是 `"apiKey": "${DS_LLM_KEY}"`,外壳从
   `<数据目录>\.openDesign\key.txt` 读出来塞进子进程 env(`ds_shell_core.py:794`)。
   ⇒ **网关只在启动时读一次**。业主在界面里填完 key,**网关必须重来一次才认**。
2. `Supervisor` 只有 `start` / `shutdown`,**没有 restart**(`ds_shell_core.py:289,315`)。
3. **key 不许写进配置文件**(现有判据 `test_ds_provision.a6` 咬着:配置会进日志、截图、
   我这边的收据)。⇒ 不能靠"把 key 写进 config 就不用重启"绕过第 1 条。
4. 今天前端**手输登录口令**换短票(`web/src/chat/connection.ts:79-96`),
   ds-web 只是透传代理、自己不碰口令。

## Approach

### 一、口令:ds-web 代签短票,前端永不持有长期凭据(proposal 已判)

- 新增 `GET /api/chat/ticket`:ds-web 自己读配置里的口令 → 调上游 `/webui/bootstrap`
  → **只把短票回给前端**。前端从此不问业主要口令。
- **同时上来源检查**(`Sec-Fetch-Site` / `Origin`),但**别把它说得比实际大** ——
  这是折完 B 卷之后我又实读一遍代码校准的:
  - `ds_web._host_ok()`(`:688-698`)已经在挡 **DNS rebinding**(Host 头白名单)。
  - 他随手打开的网页发普通 `fetch` 时,Host 头是 `127.0.0.1:<port>`、**过得了**那道闸;
    但**浏览器的同源策略不让它读到响应**(我们不发 CORS 头)⇒ **短票偷不走**。
  - 所以来源检查挡的是**剩下那一小块**:能被跨站触发的**带副作用的 GET**,
    以及"将来谁手滑加了宽松 CORS 头"。**它是纵深,不是唯一那道门。**
  ⇒ 仍然做(便宜),但**结论要写准**:拿掉手输口令之后,顶住远程页面的是
  **Host 白名单 + 同源策略**,不是这条新加的检查。**夸大自己在防的风险,和忽视它一样坏。**
- 手输口令那条路**保留但降级为兜底**(代签失败时仍可手输),不删 —— 删了就没有退路。

### 二、引导框:一个组件,两个入口(照抄 DSH 的形状)

- **首次打开**:ds-web 报 `configured: false` ⇒ 前端弹**模态框**(不是整页向导):
  选厂商(MiMo / DeepSeek)→ 填 API key →「保存并继续」。
- **设置里**:同一个组件再挂一次,用来改 key / 换厂商。**一份代码两个入口**。
- 🔴 **key 只写不回显**:存完之后接口只回 `configured: true` + 厂商名 + **末四位**,
  永不回原文;页面 HTML / aria / 控制台里都不许出现它(DSH 那份判据逐条断言,照抄)。

### 三、"填完就能用":外壳重启后端,而不是让他去重启程序

- 新增 `POST /api/llm/credential`:写 `key.txt`(0600 权限)+ 把选中的厂商写进配置的
  `providers.custom.apiBase` 与 `model_presets`(**这两样不是凭据,可以进配置**)。
- 写完之后要让网关重来:**复用外壳已有的那条本地通道** —— 单实例锁端口
  (`ds_shell.py:LOCK_PORT=18788`)现在已经在做"唤醒已运行的实例"的握手,
  给它加一条 `restart-backend` 消息即可。**不新开端口、不新造 IPC。**
- **没有外壳的形态(git-pull 那两台、开发机)**:通道连不上 ⇒ 接口如实回
  `restart: "manual"`,前端说人话「配置好了,请重启一下程序」。**不假装成功。**

### 四、厂商预设(值已实测,不许照抄本文件)

| 厂商 | apiBase | 默认模型 | 依据 |
|---|---|---|---|
| MiMo | `https://token-plan-cn.xiaomimimo.com/v1` | `mimo-v2.5` | 现行模板 `:25,:33` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-v4-flash`(可选 `-pro`) | **08-15 现拉 `GET /models` 实测** |

## Key trade-offs / risks

- **代签短票 = 本机任何进程都能驱动助手**。判断与理由在 proposal(口令本来就明文躺在
  他自己账户可读的文件里,手输挡不住本机进程)。**新增的那一份风险靠来源检查兜。**
- **重启后端 = 聊天历史断一次**。可接受(他刚装完,没有历史);但**不能在他聊到一半时
  被动触发** ⇒ 重启只由"他点了保存"这一个动作发起。
- **key.txt 权限**:Windows 上 `os.chmod(0600)` 语义不同(ACL 才是真的)。
  ⇒ 本单只做到"不放进配置、不进日志、不回显",**不声称文件级隔离**。这条写进真机清单。

## Alternatives considered

- **把 key 写进配置** —— 否,判据 a6 咬着,且配置会进日志/截图/收据。
- **让 ds-web 自己起网关** —— 否,那是外壳的职责,两个爹会打架(单实例锁就是防这个的)。
- **整页向导** —— 否,业主指名了 DSH 那套,DSH 是模态框;而且整页向导在"改 key"
  这个入口上很别扭。
- **继续让他手输口令** —— 否,理由在 proposal:那道手输挡不住本机进程,
  只是拿他的麻烦换我的心安。

## 🔴 key 的"允许存在的地方"(2026-08-16 补:攻题指出规格本身缺了这一节)

原来规格只写了「不回显原文、只回末四位」。**那是一句关于回显的话,不是一条不变量** ——
判据补了一堆泄漏面之后我才发现规格从来没说清"这把 key 允许在哪儿、待多久"。
两条攻题腿都指着同一处。补上,以后按这个判:

**允许存在的地方,穷举**:
1. 业主正在打字的那个输入框(**保存成功即清空,或整个表单卸载**);
2. **那一次** `POST /api/llm/credential` 的**请求体**(不许进 URL、不许进请求头);
3. `<数据目录>/.openDesign/key.txt`(一行,覆盖写,**不许追加**);
4. 外壳起网关时注入的**子进程环境变量**(变量名从配置读)。

**除此以外一律算泄漏**,包括:浏览器的 localStorage / sessionStorage / IndexedDB /
Cache Storage / cookie / `window.name` / 地址栏与 history / 浏览器密码管理器
(⇒ 输入框必须 `autocomplete="off"`);页面 DOM 与无障碍树;控制台;
服务端日志;**配置文件的任何字段**(不只是 `apiKey`);仓库里的任何文件。

**"变形之后"仍然算**:base64、URL 编码、分片、截断到还能认出来的程度 ——
唯一的例外是后端给的 hint(前 4 + 末 4,不超过 16 字符)。

**判据够不着、明账带走的**:React state / ref / closure 与 worker 内存里的副本;
WebSocket 帧(本单前端不经 ws 发 key);Windows 上 key.txt 的 ACL(见下文已接受项)。

## Test strategy (oracle)

主 agent 写,不外包。分四组:

1. **凭据不回显(照抄 DSH 那条,最硬)**:存进去之后,
   `GET` 任何接口的响应里、日志里、配置文件里都**不含 key 原文**;只回"已配置 + 末四位"。
   反向验:故意在响应里塞回原文的实现必须红。
2. **写对地方**:key 落 `key.txt`;厂商 apiBase/模型落配置;**配置里不含 key**
   (与 `test_ds_provision.a6` 同一条不变量,别写第二套期望)。
3. **来源检查**:带 `Sec-Fetch-Site: cross-site` / 外域 `Origin` 的请求**必须被拒**;
   同源请求照常通过(**双向验**,别造一个"永远拒绝"的闸)。
4. **降级诚实**:外壳通道连不上时,接口回 `restart: "manual"` 而不是假装重启成功。

**这个 oracle 能被什么骗过?**

- **骗法一:我只测了自己写的那条响应路径。** key 可能从**别的**口漏出去(健康检查、
  错误信息里带上下文、日志里打了请求体)⇒ 判据要**扫整份响应体 + 日志文件**找那个串,
  不是只看我预期的那个字段。
- **骗法二:来源检查只在新接口上。** 老的 `/api/chat/*` 代理口今天靠"不知道口令"挡着,
  代签上线后它们同样能被跨站调用 ⇒ 判据要问**代理口也拒跨站**。
- **骗法三:"不用重启"这句话是我自己说的。** 判据只能验"发出了重启请求";
  **真的重启完还能聊天**只有真机能答 ⇒ 写进真机清单,别在这儿声称。
- **骗法四:模型名/端点写死在判据里,和实现抄同一处。** ⇒ 判据的期望值**从配置模板读**,
  不在判据里第二次硬编码(否则两边一起错)。
