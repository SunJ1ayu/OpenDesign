### 落地规格(= 判据要钉死的东西)

#### A. 条目在卡内的排序 `orderItems(items, today)`(新纯函数)

**两轨不混排**,有 due 的整体排在无 due 的前面:

1. **硬轨(有 due)**:`due` **升序** —— 过期最久的最靠前 → 今天 → 未来。
2. **软轨(无 due)**:记录日期 `date` **升序**,**最久的在前**。
3. `date` 为 `null` 沉到软轨最底(旧行没日期,不许冒头)。
4. **稳定**:同键保持传入序。5. 纯函数,不改传入数组。

#### B. 项目卡的排序 `orderProjectCards(groups, today)`(**改签名**)

旧签名 `(groups, stale)` 的 `stale` 就是那个坏指标,**本单删掉该入参**。

1. **档位**(取卡内最紧急条目):overdue `0` < today `1` < upcoming `2` < 无 due `3`。
2. 同档且有 due:按卡内**最早的 due** 升序。
3. 无 due 档:按卡内**最老的记录日期**升序。
4. **稳定**;`project`/`items` **原样带过**(同引用,不复制不重排组内);不改传入数组;
   空输入 `[]`;不为不存在的项目凭空造卡。

档位判定**复用既有 `dueStatus(due, today)`**,不自造第二份日期比较。

#### C. 「多久没动静」拆成两个不骗人的东西

同一个词现在被两处用着而含义不同 ⇒ **各自说实话,别共用一个词**:

- **项目卡徽标** → 新纯函数 `latestRecordAge(items, today)` = 今天 − 该项目未办结条目里
  **最新的记录日期**;一条都没日期 → `null`。**纯前端算,零后端改动**(条目本来就带 `date`)。
  文案 → **「最近记录 N 天前」**,**去掉底色药丸**,降到与「N 条未办结」同档小字,
  仅在 ≥ `STALE_AFTER_DAYS`(7,与后端阈值同源)时出现。
- **无未办结条目的那几行**(`staleNoCard`)→ 仍用后端 `stale`(**那些项目没有条目可算**),
  文案 → **「档案 N 天没更新」** —— 它测的确实就是这个。

#### D. 界面

- **撤掉 `.seg` 三个切换按钮**,只渲染项目卡。
- **阶段**从"第三个看法"降为**项目卡头上的标签**;修掉「阶段标题 13px/`--ink-2` 比它管着的
  项目名 14px/默认色**还小还淡**」这个反层级。
- 卡内**不再按空间分小节**,改走 A 的两轨;空间仍是条目行内标签(既有 space-chip)。

## Key trade-offs / risks

- **最大风险:上线当天硬轨是空的** —— 用户一条截止日都没设过,所以全部条目都会落在软轨。
  这是**已知且接受**的,第 ① 单紧接着补写入者。**判据必须覆盖"全部无 due"这个真实形态**,
  不能只测漂亮的混合夹具。
- **软轨"最久在前"刻意偏离 GPT-5.6 的"最新在前"**:依据是用户 08-01 说的打开动机
  「看今天做什么,**还有有什么忘记的事情**」——"忘了的"就是老的,倒序会把它们埋到底下。
- **删分支 vs 留死代码**:我先前对用户说过"先撤按钮、不删代码",**改成直接删** `stage`/`time`
  两个分支。理由=本项目栽够了"留着没人走的分支 = 会撒谎的死代码"。
  **已当面向用户说明**;恢复成本 = 一条 `git revert`,commit 号记在 tasks.md。
- 阶段标签假设"一个项目一个阶段"(项目级字段,成立)。

## Alternatives considered

- **GPT-5.6:严格急 = 只认截止日,并主张直接删掉「N 天没动静」。** 没全采:用户明确要
  "没截止日就按多久没动静"兜底。但它那条**实证**(见下)改写了本单的地基,是本轮最值钱的产出。
- **MiMo:「急」= 多久没动静。** **拒绝** —— 正是被下面这条实证证伪的指标。
- **DeepSeek:阶段做成组头副标题、静置只在软轨且 ≥15 天显示。** 形状(两轨不混排)采纳;
  阈值沿用既有 7 天(与后端同源),不新造一个 15。
- **GLM:单一"紧急性"视图 + 给前 5% 加红底。** 前半与结论同向;"前 5%" 对十几条的规模无意义,不采。

### 那条实证(GPT-5.6 提出,主 agent 已在代码里逐行验实)

`bin/ds_todo.py:119` 的 `stale` = 今天 − **档案页脚「最后更新」日期**;而
`ds_common.bump_last_updated` 的调用点包括 `append_change` / `set_change_status` /
**`set_due_date`** / `edit_change` / `log_communication` / `rename_project` / **`set_stage`** /
`add_ref` / `link_ref` / `update_ref`。
⇒ 它测的是「档案文件多久没被写过」,**不是**「这件事多久没人管」;**用户点一下截止日它就归零**。
而旧 `orderProjectCards` 的**第一排序键就是它**。

## Test strategy (oracle)

主 agent 亲写,执行腿逐字节 off-limits。

1. **`tests/test_todo_one_view.mjs`(新)** —— A/B/C 三个纯函数的完整契约,
   **含"全部条目无 due"这一真实形态**。
2. **`tests/test_todo_layout.mjs`(改写既有)** —— 它编码的正是**旧**排序语义,必须改。
   **改判据必须当场证明「不是放松」**:文件头写逐条对照表(哪些约束存活、哪些被替换、
   为什么替换、新集合在哪些维度上更严)。`idleProjectKeys` 一节**一字不动**。
3. **`tests/e2e/todo_one_view.e2e.mjs`(新)** —— 真 chromium + 真 ds_web:
   切换器不存在;两轨顺序在真 DOM 里成立;阶段标签在卡头且**字号 ≥ 项目名**;
   徽标**无底色**且文案是「最近记录」。
4. **护栏(不许因本单变红)**:`todo_batches`/`todo_layout`/`todo_rail`/`side_stage_groups`
   等相邻 e2e;`node --test tests/*.mjs` 全量;`pytest tests/` 全量;`npm run build`。

**这个 oracle 能被什么骗过?**

- **最可能的一种:排序数组全对,但页面上读不出来。** 卡头挤成三行、阶段标签换行、
  徽标降级后反而看不见、软轨全空时页面显得"什么都没有"—— 这些断言全绿也照错。
  **接得住的只有截图**(本项目连栽三次:07-24 `columnCount==="3"` 全绿而正文被压成竖排;
  08-01「知道了」被压竖排而 `scrollWidth` 断言 16≤16 是绿的)。**收尾必须截图看。**
- **第二种:夹具全是漂亮的混合数据**(有 due 有 date),而用户的真实档案**一条 due 都没有**。
  那样两轨里的硬轨永远测不到、软轨永远没被单独盯过。⇒ 判据里**必须有一整组"全无 due"用例**。
- **第三种:我把"证明不是放松"写成了自我安慰。** 对照表必须逐条指名旧断言,
  不许只写"新的更全面"。
