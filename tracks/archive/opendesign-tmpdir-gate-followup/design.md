# Design: opendesign-tmpdir-gate-followup

- Change: opendesign-tmpdir-gate-followup
- Status: done

- 规划双出:**不适用** —— 触发条件是「新写面 / 开放方向」。这单没有方向可选:
  它是一轮评审 12 条发现的收口,每条的位置和修法都已经被那份 diff 钉死了,
  产品代码零改动。真正需要判断的不是"往哪走",是"哪几条成立" —— 那是仲裁,写在 proposal。

## Approach

逐条仲裁 → 接受的分两类走:

1. **真洞(A)**:先写会红的判据(⑭),红检跑出**实得 rc=0**,再修。
   这条是全单唯一的行为改动,也是唯一一条"闸自己瞎了"的。
2. **其余七条**:全是**注释 / 诊断文案 / 报告可读性**,不改判定逻辑。
   它们的共同病根是一样的:**闸没说错话,但把人指错了门**——
   而一道指错门的闸,和一道不响的闸一样会让人去改无辜的那行代码。

判据侧另补两条(截断记号正反两面),都先单独 commit、先红检。

## Key trade-offs / risks

- **不收窄 ALLOW_WIDE 的匹配范围**(subdeepseek 判 MEDIUM,我不采纳):
  按内容认是上一版「行号会漂」换来的,收窄会重新打开"漏放行"的口子。
  改成**把冲突行号印出来**——保住宽匹配,同时让歧义一眼可诊断。
- **`_selfcheck=()` 这个修法有 bash 版本前提**:它依赖 ≥4.4 对空数组在 `set -u` 下的
  展开语义;更老的 bash 上同一个洞可能原样复活。更硬的写法是开跑前 `type -t mapfile`
  显式探一次。本轮**不改**(本机 bash 5.x,判据绿),但这是这道闸已知的边界。
- **判据自己会被骗**:见下。

## Alternatives considered

- **把 mkdir 失败继续混在"数法不管用"里报**(即不改 C):省 6 行,但会把人支到
  find/mapfile 那条死路上查一个只读挂载问题。不划算 —— 这单的全部主题就是"别指错门"。
- **README 里把"第四段"改成"第六段"**:治标。序号会随下一次插段再次过期
  (同一天已经栽了三次同类)。改成按**名字**指,插多少段都不会漂。

## Test strategy (oracle)

- `tests/test-tmpdir-leak-gate.sh` ⑭:`mapfile` 内建缺席时闸必须 **rc=2**(拒跑),
  夹具 `tests/.gatefixture/no-mapfile.bash`。**先红后绿,红收据在库里**。
- `tests/test_dead_assertions.py` 两条:长行**要有**截断记号(正面)、
  短行**不许有**(反面)。反面那条用**变异**证明咬得动(把 `clip()` 改成无条件加记号 ⇒ 红)。
- 仓库级总跑 `tests/run-all.sh` 六段。

**这个 oracle 能被什么骗过?**

- **骗过 ⑭**:一个实现只要"在 mapfile 缺席时非零退出"就绿,不必真的 rc=2 ——
  但 ⑧「命令自己 rc=1 时透传 1」把 rc=1 这条退路堵了,组合起来才钉死 rc=2 的语义。
- **骗过截断记号(正面)**:无条件给每行加记号 ⇒ 记号泛滥、真正被截断的那行反而认不出。
  **这正是本轮 subdeepseek 指出的缺口,已补反面判据。**
- **判据全绿、结果仍然错会错成什么样**:这单改的七条是**给人看的话**。
  断言只能问"这句话在不在",问不出"这句话有没有把人指对门"。
  接得住那种错的只有**下一次真出事时有人照着它去查** —— 所以每条修法都在原地写下
  「为什么这么写 / 改行为就得回来改这句」,让下一个读它的人(很可能是我)有据可依。
  A 那条不同:它是行为,红检收据就是硬证据。
