# Proposal: opendesign-owner-feedback(Track D:业主反馈流程)

- Date: 2026-07-16
- Status: open

## 背景(用户 07-16 反馈 #3)
设计师把业主的修改意见(微信长段原话)贴给 agent 后,期望:
1. **原文要存**(不丢证据、可追溯),但待办列表只显示总结过的短句(清爽);
2. agent 总结**确定性改动**成短变更行(省略客套/废话),逐条 append_change;
3. **摇摆不定/没拍板的**不入变更,原文贴回对话让设计师自己定,拍板后才落。

## 缺口
- SCHEMA 项目档案本有「## 沟通日志」段,但 **agent 没有写它的工具**(铁律:PKB
  只能经 ds_tools MCP 写;内置文件工具已关)→ 原文现在无处安放。
- AGENTS.md 无"贴长段业主原话"的处理规则(现规则 1 只覆盖单句口头改动)。

## 方案
- 新核心函数+MCP 工具 `log_communication(project, text, source?)`:业主原文**多行
  逐字**存入「沟通日志」段,每行加 `  > ` 引用前缀(结构注入免疫:^-/^##/^最后更新
  全部失锚);段缺失自动补建;bump 最后更新;locked_rw 同款锁。
- AGENTS.md:工具表加一行 + 新规则"业主反馈三步"(先存原文→确定项总结落变更→
  摇摆项贴回待拍板)。
- ds-web 0.18.0 → 0.19.0(部署回显;前端零改动)。

## 非目标
- 前端展示沟通日志/变更行关联原文(二期,等真实使用反馈)。
- 自动判定"确定 vs 摇摆"的硬规则(交给 LLM 判断 + 设计师兜底)。
