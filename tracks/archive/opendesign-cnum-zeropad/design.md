## Approach

> ⚠️ **2026-08-12 换过一次方向。** 原方案是"锚点里加 `0*`"(`C0*{num}\b`)。
> 派活前的攻题(`gpt-5.6-sol` 只读,记录见 `/root/aiwork/attack-logs/cnum-zeropad-attack.jsonl`)
> 把它按在地上打了:那是**再打一个补丁**,而且补得不全(见「五、攻题打掉了什么」)。
> 现在这版才是第一性的。

**一句话:写侧不再拼号码进正则,改成"用读侧同一份正则捕获号码、按数比对"。**

读侧一直是这么干的(`CHANGE_RE` / `HISTORY_NOTE_RE` 捕获 `(\d+)` 再 `int()`)。
写侧五处则是把目标号码**拼进** pattern(`C{num}\b`),于是"什么算 3 号"有了两套定义。
这一单把写侧那套删掉,只留读侧那套:

1. **`ds_todo` 出两个判定函数**,读写共用一份口径:
   - `change_line_num(line) -> int | None` —— 主变更行捕获到的号码;
   - `note_line_num(line) -> int | None` —— `## 变更历史` 备注行捕获到的号码。
   `note_line_re(num)`(写侧那份第二定义)**退场**,它就是这次的病灶。
2. **五处定位改成"先匹配、再 `int(捕获) == 目标`"**:
   `ds_tools._rewrite_change_status`(`set_change_status` **和删除按钮 `delete_change` 共用**)、
   `set_due_date`、`edit_change`,加 `_upsert_note` / `_delete_note`。
   命中多行仍走现有的 `len(hits) != 1` ⇒ `ambiguous_change`(fail closed,不变)。
   改写仍用同一个 match 的分组回填 ⇒ **C 号字节照旧不动**(BLOCK-2)。
3. **入口把目标号码归一成数**:`3` / `"3"` / `"03"` / `"C03"` 从此是同一件事
   (现在是拼进 pattern,所以 `"03"` 会去找 `C03` —— 攻题的 HIGH-1)。
4. **备注行命中时保留原行前缀字节**(到冒号为止,含全角冒号),只替换冒号后的值;
   只有**新插入**的备注行才写规范形式 `- C{num} 备注:`。
   ⚠️ 这一条是攻题 Q4 掰过来的:我原本要把 `- C03 备注:` 顺手规范化成 `- C3 备注:`,
   那会**同时破两条现成契约** —— ①"不擅自改业主档案"(主变更行明明保字节,备注行却重写);
   ② 0.83.0 的 no-op 契约(同值保存 ⇒ 不写、不 bump 最后更新)。

**顺带白捡的**:按数比对之后,**全角数字**(`C０３`,读侧 `\d`/`int()` 本来就吃)自动一起修好,
不用为它单开一条规则 —— 这正是"两套定义合成一套"的价值,而不是我原方案里再补一种字符。

## Key trade-offs / risks

- 🔴 **风险从"匹配太窄"变成了"匹配太宽"**:写侧现在认得读侧认得的一切。
  防线是判据 N 组:`C13` / `C30` 不许被 `3` 够到;歧义并存必须 fail closed。
- **`C03-1` / `C03.1` 这种带后缀的形状**:读侧 `C(\d+)\b` 本来就把它读成 3 号,
  改完之后写侧也一样把它当 3 号 —— **两侧一致**,而不一致才是这一单要消灭的东西。
  要不要禁掉这种写法是**另一个产品问题**(得业主点头),这一单只钉"两侧给同一个答案"(N7)。
- **档案里已经存在的脏数据**(同一条变更有 `C03` 和 `C3` 两行备注,bug 期间写出来的):
  修完之后第一次改/清备注就会按数归一掉。不做一次性迁移脚本(不擅自动业主档案)。
- **`int()` 吃全角数字是 Python 的既有行为**,这一单顺势用它,不新增字符表。

## Alternatives considered

- **锚点加 `0*`(原方案,已否)**:只覆盖前导零一种形状,全角数字仍漏;
  而且要在五处各拼一次号码,"两套定义"这个根因原封不动。攻题当场给出两个 HIGH 反例。
- **只修备注那处正则**(待办池原话的修法)。否掉:探针证明主变更行那条更严重
  (整条待办动不了,连删除按钮都点不动),只修备注等于留着四处同根同源的洞。
- **读侧改成不归一**(把 `C03` 当另一个号)。否掉:会让手写档案凭空多出一条待办,
  且与 `ds_lint` 的"编号唯一"检查打架。读侧是对的那一半。
- **一次性迁移脚本把 `C0N` 全部重写成 `CN`**。否掉:动业主真实档案,收益只有"好看"。

## 五、攻题打掉了什么(派活前,`gpt-5.6-sol` 只读)

记录:`/root/aiwork/attack-logs/cnum-zeropad-attack.jsonl`;任务书:`/root/aiwork/tasks/opendesign-cnum-zeropad-attack.md`。
**四条全部成立,两条 HIGH 直接改了方向和范围:**

1. 🔴 **HIGH — 入口归一一条都没被问到**:我的 15 条判据除一处外全传整数 `3`,
   所以"只改正则、不做入口归一"也能全绿;而传 `"03"` 时原方案会去找 `C03`,
   **在 `C3`/`C03` 并存的档案上会安静地改错一行**(A4 抓不到)。⇒ 补表驱动入参断言。
2. 🔴 **HIGH — 全角数字**:`parse_change("- [待确认] C０３ …")["cnum"] == 3`(实测确认),
   而 ASCII `C0*3` 够不着 ⇒ 同一个 bug 换个字符就复活,并且同样能骗过 A4。
   ⇒ 直接换成"捕获后按数比对",不再拼字符。
3. **MEDIUM — 漏了第五个写口**:`delete_change`(界面上的**删除按钮**)与
   `set_change_status` 共用 `_rewrite_change_status`,那里还有一处同型锚点。我的 scope 漏了它。
4. **MEDIUM — 规格自相矛盾**:主变更行保字节、备注行却要规范化,一面拒绝批量迁移
   说"收益只有好看",一面在单次编辑里做同样的外观迁移;还会撞坏 0.83.0 的 no-op 契约
   (同值保存却 bump「最后更新」)。⇒ 采纳它的改法:命中行保前缀字节,只换值。

## Test strategy (oracle)

判据全部落在 **`tests/test_ds_cnum.py`(新文件)**,纯 python 单元层,不起服务:
这一单的行为在 `ds_tools` / `ds_todo` 两个模块里就能完整问出来,起服务只会让判据更慢更钝。

**A 组 —— 复现形状,修之前必红**:
- `A1` 备注行手写 `C03`,改备注 ⇒ 档案里**只剩一行**备注、值是新的,
  且**那行的前缀字节保持 `- C03 备注:`**(不许顺手规范化;攻题 Q4)。
- `A1b` 同上但用**全角冒号**(读侧收两种)。
- `A1c` 脏数据归一:`C03` / `C3` / `C003` 三行备注并存 ⇒ 改完只剩一行;清空则一行不剩。
- `A2` 备注行手写 `C03`,清空 ⇒ 那行**没了**且 `changed_fields` 含 `note`
  (现在:静默 no-op、`ok:True`、行还在)。
- `A3` 主变更行手写 `C03` ⇒ **五个写口**都够得着:改状态 / 改正文 / 改截止日 / 加备注 /
  `set_change_status` / **`delete_change`(界面上的删除按钮,攻题发现 3)**。
- `A4` **表驱动**:`C3` 与 `C03` 并存时,入参 `3` / `"3"` / `"03"` / `"C3"` / `"C03"`
  **每一种**都必须 `ambiguous_change` 且档案逐字节不变(攻题 HIGH-1:只测整数 `3`
  的话,"只改正则不做入口归一"能全绿,而传 `"03"` 会安静改错一行)。
- `A5` **全角数字**(攻题 HIGH-2):`C０３` 单独存在时五个写口够得着;
  与 `C3` 并存时判歧义。读侧本来就把它读成 3(实测 `int("０３")==3`)。

**N 组 —— 不许误伤 / 不许修过头**:
- 修之前就绿:`N1` `3` 不碰 `C13`;`N2` 不碰 `C30`;`N2b` 清 C3 的备注不许删掉 `C30` 的;
  `N5` 读侧 `parse_change`/`parse_history` 行为不变(这一单不动读侧)。
- 修完才答得出:`N3` 认得 `C003`;`N4` 改状态后主变更行**除状态词外逐字节不变**
  (手写的 `C03` 不许被规范化 —— 和 A3 成对,单有 A3 是假绿);
  `N6` **no-op 契约不许破**(攻题 Q4):对着 `- C03 备注:老` 保存同值 `老` ⇒
  `changed_fields` 不含 note、页脚「最后更新」不 bump、文件逐字节不变;
  `N7` `C03-1` 这种带后缀的形状,**读侧和写侧给同一个答案**(都当 3 号)——
  钉的是"两侧一致",不是这种写法合不合法(那是另一个产品问题)。

**回归**:`tests/test_ds_todo.py`、`test_ds_tools.py`,以及 `tests/run-all.sh` 全套(含 e2e 总跑)。

**机械化**:判据先单独 commit 且必须红;`redcheck` 退回旧实现必须红在目标断言上;
修完跑变异测试证明判据咬得动(靶子至少三处:入口 `int()` 归一、五处按数比对之一、
备注命中行的前缀保留)。

**这个 oracle 能被什么骗过?**

- **业主真实档案的歪法不止这些。** 我的题面是我自己造的干净 markdown;他那份两年的档案里
  可能是 `- C3备注:`(少空格)、全角 `Ｃ`、`C 3` 中间带空格。这几种**明确不修**(non-goal),
  但判据全绿 ≠ 他的档案能用。接得住这件事的只有**真机 + 他自己的档案**。
  ⇒ 真机清单必须有一条:**让他去翻一条他手改过的备注/变更行**。
- **判据全绿但界面仍然坏**:断言全在 python 层,`/api/todos` → 前端那段没被问到。
  挡这个的是 `tests/e2e/` 总跑(已有的),不是本单新写的断言。
- **`_note_lines` 这类判据自己的辅助函数会撒谎**(首跑已抓到一次:`or` 两边是同一个
  半角冒号,全角行会从计数里溜掉)。所以 A1b 存在的意义不只是"多测一种",
  它同时是**对判据辅助函数的反查**。
