# Proposal: opendesign-per-vendor-keys

- Date: 2026-09-21
- Status: open

## Goal

每家厂商（现在是 MiMo、DeepSeek）的 API key 各存各的；在聊天框的模型按钮里能直接换到
任何一家已配好 key 的模型，不用再重新粘 key，换过去再换回来也不用。

## Motivation

业主 09-21 看了 ZCode 模型设置页的对照（artifact `ReEsjSRZ8MwAYPbjxfjnxJ`，第 4 条），
被问「你平时会在 MiMo 和 DeepSeek 之间来回换吗？」时答「会」，并选定这一条先做。

现状（代码核过，2026-09-21）：`bin/ds_credential.py` 的 `save()` 只存一把 key
（`<home>/.openDesign/key.txt`），换厂商必须粘新 key，旧的被覆盖；想换回来还得再粘一次。
聊天框的模型菜单（`web/src/chat/modelPicker.ts`）只列当前这把 key 的模型。

## 真问题(第一性)

- 用户原话:「会 先做换供应商这个吧」（上一句问的是「你平时会在 MiMo 和 DeepSeek 之间来回换吗？」，
  我在对照页里对这一条的描述是：「每家厂商各存各的，配好的都亮绿点，聊天框菜单里全列出来，点一下就换」）
- 真正要解决的是:换厂商这件事的成本 —— 现在每换一次都要找到另一家的 key 再粘一遍。
- 我在这中间翻译了什么:
  1.「点一下就换」是**我**在对照页里写的描述（照 ZCode 的样子），不是业主的原话；业主只确认了
    他会来回换、要先做这一条。「换的时候要等多久可以接受」他没说过。
  2.「绿点 / 左右两栏」是 ZCode 的外观，我在对照页「不该学」里已经写了两家时不上整页布局。
- 用户可观察的成功:
  - 两家 key 都填过之后，任何时候在聊天框的模型菜单里点另一家的模型，下一句话就由那一家回答，
    **不需要再去找、再粘任何 key**；
  - 换过去再换回来，原来那家照常能用；
  - 界面上显示的「当前模型」和真正在回答的那一家永远一致（换失败要明说，不许显示换成了、实际没换）；
  - 只填过一家的人（包括全新装机）体验不比现在差。

## Scope

- in:
  - key 按厂商分开存；旧的单把 key 在升级后自动归到它原本属于的那一家，业主不用重填；
  - 「AI 模型 key」卡片：每家显示有没有配 key（末四位提示），可以单独填/换某一家的 key，不影响另一家；
  - 聊天框的模型菜单：列出所有已配 key 的厂商的模型，按厂商分组，点了就换；
  - 装好的应用（外壳 `ds_shell`）这条主路径。
- 待方案挑战后定：换厂商时要不要重启后台（见 design.md 的两条路）。

## Non-goals

- 不加新厂商（仍是 MiMo / DeepSeek 两家），不做厂商目录、不做自定义端点；
- 不做「测试连接」按钮、「获取 key」链接、「能看图」标签（对照页第 1~3 条，另排）；
- 不改整页布局（不上 ZCode 那种左右两栏）；
- 不改 key 的安全不变量：key 原文永不进配置文件、永不回显、报错不带 key。

## 验收边界与轮次预算(要外审的单开工就写 —— panel 抽屉 4b)

- 这一单承诺:
  1. 两家 key 能同时存着，填/换一家不动另一家；
  2. 聊天框模型菜单能换到任何一家已配 key 的模型，换完下一句由那一家回答；
  3. 界面显示的当前厂商/模型与真正生效的一致；换不成功时明说，不静默；
  4. 老用户升级后原来那把 key 仍然生效、归在正确的厂商名下，不需要重填；全新装机第一次填 key 的流程照常；
  5. key 安全不变量不退化（原文只在 key 文件与那一次 POST 里出现）。
- 不承诺:
  - git-pull 部署（`bin/ds-nanobot.ps1`）与 Linux 开发机（`bin/ds-nanobot` + auth.json）上的多厂商切换 ——
    只承诺它们**不被弄坏**（照旧单厂商能用）；
  - 测试挡不住任意未来的错误实现。
- 实质评审上限:2 轮。第 2 轮主要核验修复;用完有阻断就保持未完成,
  不自动续轮,延期项留在 verify.md、不自动开新单。**每轮派发前先跑 `track preflight opendesign-per-vendor-keys`。**
