# Design: opendesign-chat-image-p2

- Change: opendesign-chat-image-p2
- Status: draft

> 不是开放架构分叉,不跑 panel-explore。verify 吃 **full 四审**:虽然没有新的写盘口,
> 但 ①动了项目发现(错了会让用户的真项目从列表里消失)②新开了一条"让 Windows 打开
> 目录"的分支 ③把网关给的 URL 塞进 `<img src>`。三条都够格。

## D1 排除结构目录:三层,第一层是用户声明的事实

`ds_workspace.project_folders()` 过滤掉:
1. `workspace.json.structuralDirs`(字符串单段名列表,用户/体检卡写入)—— **名字随便
   他起,叫「新文件」也照排**。这是根治"写死目录名"的那一层。
2. 回落:规则表 `inboxDirs ∪ archiveDirs ∪ sharedDirs` 里**确实存在于工作区根**的名字
   —— 让今天就能用,不必等用户先配置。
3. 都不中 → **不排除**(诚实)。用户把收件箱叫「新文件」又没声明,它就该出现在待建档
   列表里。宁可多列一个,不可猜错让真项目消失。

坏配置(非列表/非字符串/带路径成分)→ 忽略该层,不崩(与全仓"坏配置整体降级"同款)。

## D2 打开收件箱:open-folder 加 `{"inbox": true}` 分支

**路径永远由服务端 `_find_inbox` 解析,调用方给不了路径**;`inbox` 与 `key`/`sub`/`rel`
互斥(同给即 400,不猜意图)。其余闸(CT/体积/启动器)与既有分支共用。

## D3 收件箱搬去右列顶部

`InboxCard` 从 `CompanionColumn`(第三列)移到 `ChatColumn`(第四列)**头部之上**,
样式对齐左列 `.aside-head`(标题 + `打开 →`)。
**项目助手收起(»)时收件箱那一行仍在** —— 它不属于聊天,不该跟着消失。
于是:第三列 = 纯这个项目的东西;第四列 = 工作区级收件箱 + 项目助手。

## D4 历史回放渲染图

`hydrateFromThread` 保留 `media`;只认 `kind==="image"` 且 `url` 以 `/api/media/` 开头
(签名自带鉴权),补成 `http://127.0.0.1:8765` 绝对地址给 `<img src>`。
**任意外链一律拒**(回放数据虽来自本机网关,也不该让任意 URL 进 img)。
`ChatMessage.media` 统一成 `{src,name}`:本地发出时 src=data URL,回放时 src=签名地址;
出站信封那份仍是 `{data_url,name}`(协议要求),两者不混。
端口沿用前端既有的 8765 硬编码(`connection.ts` / `STOCK_WEBUI` 已有先例);
换端口的用户两处一起改,不在本单扩大。

## D5 聊天存图的名字:一层薄默认

`chatImageName(原名, {project?, at, index})`:
- 原名"有意义" → **原样保留**(从文件夹拖进来的 `客厅现场.png` 不许被改)。
- "没意义"(纯 16 位以上 hex / image / 未命名 / download / 屏幕截图 / 空)→
  `[项目短名 ]聊天图 YYYYMMDD-HHmm[-N].ext`。
- 日期用 8 位不加分隔:**与用户自己的项目夹命名同款**(`20260612 周宁 云栖佳苑…`),
  一个工作区里两套日期写法比多两个字符更难受(用户拍板加年份,格式我定)。
- 项目名先过一遍消毒(它是外部输入),`/ \ %` 与控制符剥掉。
- 提示里加一句「名字不合适?跟助手说一声就能改」——`stage_plan` 支持 rename 且是
  开放给 agent 的工具(**已核实,不是空头支票**)。

## Test strategy (oracle)

主 agent 亲写、先红检、先 commit:
1. `tests/test_ds_web_structural_dirs.py`:s01–s08(排除三层 + 坏配置降级 +
   `01-项目` 布局不回归)、o01–o05(inbox 分支:路径不由调用方给、拒绝路径零启动)。
2. `tests/test_chat_media.mjs` 追加 p01–p08(命名)、h01–h05(回放带图 + 只认签名 URL)。
3. e2e `chat_image.e2e.mjs` 扩:收件箱在右列、收起助手仍在、点「打开」调到 open-folder。

**这个 oracle 能被什么骗过?**

- 最可能的假绿:**排除逻辑写得太聪明**,把用户某个真项目当成结构目录排掉 ——
  用户不会来告状,他只会觉得"我那个项目怎么不见了"。s04 就是专门焊这条:
  没声明的自定义名**必须**照常列出来。
- 第二个:回放图的 `<img>` 断言全绿,但真机上图裂了(签名过期/端口不对/跨源被拦)——
  纯逻辑测不到,**必须对真 gateway 发一张图、切走、切回来亲眼看**。
- 第三个:命名判据全用我编的名字,而真机上的哈希名形态是我今天才第一次见到的
  (32 位 hex)。已把用户实机拿到的三个真名字写进判据。
