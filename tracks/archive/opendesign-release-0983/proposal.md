# 发 0.98.3:把 09-01/09-02 那刀锁扫描修复真正送到业主机器上

## 为什么有这一单

`opendesign-slow-lock-scan` 已归档(主裁 PASS):双击软件时的单实例锁扫描,
最坏情况从 **9047ms → 1502ms**。但它**只在代码库里** ——
当前发布的最新安装包 `win-installer-0.98.2` 是 **08-30** 打的(tag 指向 `f8485b3`),
机械核过 `git merge-base --is-ancestor 2299230 win-installer-0.98.2` = **否**:
**那个包里没有这刀**。而 `bin/ds_web.py` 的 VERSION 至今仍是 `0.98.2`。

⇒ 业主现在能下到的包,装上去感受不到那个改进。
这正是本机那条部署规矩要防的形状:**新文件躺在盘上 ≠ 部署了**
(GLM 抢购脚本浏览器里跑 v2.9 而 v3.0 在盘上,输掉过一次实盘;
 gateway 内存里跑 6.8 而装好的 dist 是 6.10,全 cron 崩)。

业主 2026-09-02 明确要求发新版。

## 做什么(三件,都很机械)

1. **bump `bin/ds_web.py` 的 VERSION → 0.98.3**。
   它是安装包版本号的**唯一来源**(`installer/build-installer.sh:47` 只读不写)。
   版本号只加第三位,不跳 0.99/1.x —— 1.0 留给业主拍板。
2. **跑 `installer/build-installer.sh`** 出 `OpenDesign-Setup-0.98.3.exe`。
   该脚本自带四道 fail-closed 闸(依赖闸 / 成品结构 / .nsi 静态 23 条 / 成品逐文件对字节数)。
3. **发 pre-release `win-installer-0.98.3`**,并**顺手修掉一个会过期的默认值**:
   `.github/workflows/windows-package-probe.yml` 的 `tag`/`asset` 默认值写死在
   `0.98.2`(四处)。那个文件自己的注释就写着"它会过期:08-30 发现还停在 0.97.0 ⇒
   **发新版时顺手改这里**" —— 这一单就是"发新版"那一刻,不改就是明知故犯。

## 为什么 impact=self(0 条外部评审)

- **代码零改动**:本单只动版本号字符串、CI 默认值字符串、与工件。
  真正的行为改动在上一单,已由 deepseek(BLOCK→5 条全改、后一轮 PASS)与
  moonshot(PASS)两个家族在**冻结后的树**上审过。
- 外部腿对"版本号数字对不对""tag 字符串写没写对"没有判断力;
  能挡住这类错的是**机械闸 + 真机回显**,不是第二意见。
- ⚠️ 真正的风险不在代码面,在**"发出去的包是不是真含那刀"** ——
  这是部署验证问题,收口条件写死在下面。

3. release 页面上挂着的资产名与 tag 都是 `0.98.3`;
4. 🔴 **业主真机装一趟并回显版本** —— 这一条只有他能做,**不装不算发完**。
