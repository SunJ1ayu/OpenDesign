# Proposal: opendesign-image-upload

- Date: 2026-07-26
- Status: open

## Goal

工作台里能**直接拖图进去**,落到收件箱,然后走已有的「扫描整理 → 确认执行」归档。
本 track 只做**网页拖拽**这一半;聊天发图另立一单(依赖同一个上传针孔)。

## Motivation

现在图只能靠设计师自己拷进文件夹 —— 工作台看得见图墙、却放不进图。这是唯一还挡在
日常使用路上的功能(其余队列要么等用户拍板、要么是收尾)。

## 真问题(第一性)

- 用户原话:「图片上传这一轮一起做」;落点选「落进收件箱,走现有整理流程」。
- 真正要解决的:**把"图进项目"这条路从"离开工作台去开资源管理器"变成"拖进来"**。
  注意它不是"上传"这个动作本身有价值 —— 价值在于**接上已经跑通的归档链路**
  (list_inbox → 建议 → stage → 人工确认 → apply)。
- 我在这中间翻译了什么:用户说"上传",我译成"落进收件箱,不直接写项目夹"。
  直接写项目夹会新开一条"网页能任意写工作区"的路,和 deploy-security 的
  「模型/网页不能直接改盘,一律暂存+人工确认」相抵。

## Scope

- in:`bin/ds_web.py` 新增 `POST /api/upload` 针孔 + 名字闸纯函数;
  前端 `web/src` 拖拽区(图墙 / 收件箱卡片);对应 oracle。
- out:聊天发图(另一单)、上传到指定项目/类目(**故意不做** —— 那才是"直接写项目夹")、
  非图片类型(dwg/pdf 等,等真实需求)。

## Risks

- **这是本项目第一个"网页给字节、服务端落盘"的口** —— 现存 12 个写针孔要么只写 PKB、
  要么是"暂存+人工批准"的移动。安全面最敏感 → verify 走 **full 四审**。
- 开发机 Linux / 真机 Windows 的落差:文件名语义(冒号→ADS、保留名、尾点空格被剥、
  260 长路径、大小写不敏感)在 Linux 上**全部假绿**。判据只能锁"闸有没有拒",
  真机行为进 UNTESTED 清单。
