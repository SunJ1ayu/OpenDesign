## Approach

跑一遍 `unittest discover -s tests`,过程中:

1. `sys.monitoring`(3.12 自带,**零新依赖**)的 LINE 事件记下 `tests/` 下**真正执行过的行**;
2. `ast` 把每个判据文件里的**断言语句**挑出来(`self.assert*` / `self.fail` / 裸 `assert` / `check(...)`);
3. 取差集:**断言在那儿、却不在执行过的行里 ⇒ 报出来**,退出码 1。

例外走 `tests/dead_assertions.allow`,一行 `文件:行号  # 理由`,**没写理由的一行不生效**。

挂载点:它**替代**总跑里的 `python -m unittest` 那一段(`run-all.sh` py-full),
一次跑、两个信号。单独当一段要多花 4 分半,而**慢到会被跳过的检查等于没有**。

## Key trade-offs / risks

- **行粒度 ≠ 语句粒度**(本单最大的风险,评审 F2 命中):`if got: self.assertIn(...)`
  写成一行时,LINE 事件在这一行的第一条字节码就触发了,断言没跑却被判成活的。
  ⇒ 修法不是提高粒度,而是**把这种行当场报出来**("这道闸对它是瞎的"),逼它拆成两行。
- **skip ≠ 死**(评审 F1/F3 命中):被 skip 的方法里的断言当然没跑过,
  但那是"这台机器上没条件问"。⇒ 单独归 ⏭️ 一档,印出来但不算红
  ——"SKIP 不是 PASS,但它是 exit 3 不是 exit 1" 由总跑那层管。
  代价:skip 成了一条新的豁免通道;但**skip 数本身被总跑统计并计入 n_skip → exit 3**,
  多 skip 一条是看得见的,不是无痕的。
- **`except` 里的断言整片豁免**:错误路径的兜底(`self.fail("并发把配置写坏了")`)
  健康时本就不该跑。这是**结构性后门**(把死断言塞进 `try/except` 就照不到),
  接受,理由:不豁免的话误报会让这道闸活不过一周。
- **放行清单按行号锚定**:文件一编辑行号就失效 ⇒ 条目不再匹配 ⇒ 重新报红。
  失效方向是安全的(往红里失效,不是往绿里)。

## Alternatives considered

- **coverage.py**:能给语句/分支粒度,但要装依赖,且两台 Windows 真机都要补装
  —— 这道闸的价值全在"每次总跑都跑",加装机门槛等于降低它被跑到的概率。没选。
- **字节码/分支粒度自己做**:能根治单行守卫问题,复杂度和维护成本远超收益。
  改成"当场报出来"后,这条路不必走。

## Test strategy (oracle)

`tests/test_dead_assertions.py`,**给判官造判官**:造一份临时判据目录当夹具
(靠 `DEAD_ASSERT_TESTS_DIR` 接缝),里面故意放一条一定不会跑的断言,问这道闸:

1. 真死断言要被抓到(且报告要**点名那一行的源码**,不能只给数字);
2. 活着的断言一条都不许误报;
3. 放行清单**没理由不生效**;
4. 它替代总跑那段 ⇒ 判据自己红了必须非零、`Ran N test` 汇总行原样透出;
5. 干净判据不许被判红(否则它就是噪音发生器)。

评审后补 4 条:单行守卫要报 / `assertRaises` 上下文不许误报(防修过头)/
skip 不算死但必须印出来 / **skip 不许把同一份里的真死断言一起豁免**(防新后门)。

**这个 oracle 能被什么骗过?**

它问的是"这道闸认不认得夹具里那条死断言",问不出**"仓库里真有的那 2200 条断言
它判得对不对"** —— 夹具全是我造的形状,我想不到的形状它就照不到。
这正是评审两条 HIGH 的来处:F2 的单行写法、F1 的 skip 场景,夹具里一条都没有。
接得住这种错的只有:①在**真仓库**上跑一遍看误报(已做:2200 条断言、0 误报);
②别人来攻题(已做:两条评审腿,DeepSeek 当场复现了 F1)。
