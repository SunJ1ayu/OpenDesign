Direction: 以“置顶是快捷入口、不移走原记录”为测试基线；按时间与按项目只是同一批对话的两种浏览方式。  
Core bet: 用户永远能找回、识别并继续正确的对话，项目归属随助手实际操作即时反映。  
How it works: 置顶区复制展示入口，原时间段或项目组仍保留该对话；改名、置顶状态重启后保留。  
Best at: 避免“置顶后找不到原位置”、多项目对话遗漏、切换视图后误以为聊天丢失。  
Sacrifices: 同一对话在多个位置可见，界面会有重复；需用相同名称、项目标识或置顶状态帮助用户辨认。  
Blind spots in the brief: 实际仓库只有说明黑盒测试的 README，且提供的 `review.diff` 为空；未定义项目删除后历史对话的保留规则、断网时本地数据与操作的边界、搜索覆盖范围。  
Smallest first step: 先用一组“1 条项目对话 + 1 条触及两个项目的普通对话 + 1 条未触及项目的对话”验收两种视图的归属、跳转和置顶重复展示。

## 1. 用户故事 + 验收标准

### 故事 1：按时间找回历史对话
Given 我有今天、昨天和更早的多段对话  
When 我在侧栏选择“按时间”并点击“显示更多”  
Then 我能按今天／昨天／更早看到全部历史对话，且不会因加载更多而丢失已显示内容。

### 故事 2：按项目找回项目相关对话
Given 我有项目对话、实际操作过项目的普通对话，以及未操作任何项目的普通对话  
When 我选择“按项目”并展开项目  
Then 我看到项目对话排第一，其余相关对话按时间排序；未操作项目的对话只在“其他对话”中。

### 故事 3：一段对话关联多个项目
Given 一段对话中助手先后实际操作了项目 A 和项目 B  
When 我切到“按项目”  
Then 这段对话同时出现在 A 和 B 下；点击任一入口都会进入同一段对话。

### 故事 4：管理常用对话
Given 我在任一视图中看到一段对话  
When 我通过“⋯”置顶或改名，并关闭后重新打开软件  
Then 置顶状态和新名称仍保留；置顶对话同时在“已置顶”和其原分组中可见。

### 故事 5：安全删除对话
Given 我准备删除普通、置顶或已改名的对话  
When 我选择删除  
Then 软件先要求确认；确认后该对话从所有视图、置顶区及关联项目下消失，取消则保持不变。

### 故事 6：正在项目页聊天时侧栏同步
Given 我正在项目页右侧的项目对话中聊天，且侧栏保持“按项目”  
When 助手成功对该项目执行可归属的操作  
Then 当前对话立即出现在该项目下，且不会因刷新导致当前聊天中断。

### 故事 7：服务不可用时仍可辨认状态
Given 聊天服务暂时无法连接  
When 我打开侧栏、浏览已有对话或发起依赖服务的新操作  
Then 已有本地可见内容不会被伪装成空数据；用户能看到服务不可用或重试状态，不能把失败误认为对话或项目已消失。

## 3. 探索式测试任务

1. 目标：验证“同一对话多处出现”不会让用户迷路。  
   重点关注：置顶区、时间分段、两个项目下的名称／状态一致性；从不同入口打开后是否都是同一聊天。

2. 目标：验证真实工作中项目页与侧栏同时使用的连贯性。  
   重点关注：项目助手连续记变更、改阶段、记沟通、读档案时，侧栏项目归属、排序和当前聊天是否及时稳定。

3. 目标：验证大量历史的可找回性。  
   重点关注：反复“显示更多”、跨今天／昨天边界、改名后查找、滚动位置和加载过程是否让人误以为历史丢失。

4. 目标：验证容易误操作的对话管理。  
   重点关注：窄侧栏下“⋯”点击目标、删除确认对象是否明确、取消删除后状态是否完全不变、长名称是否遮挡关键信息。

5. 目标：验证断网或服务恢复过程。  
   重点关注：已有数据可读性、失败提示是否可行动、恢复后新产生的项目关联是否只出现一次且归属正确。

## 4. 需要产品负责人拍板的疑问

1. 删除项目后，原先关联该项目的普通对话应进入“其他对话”、保留一个“已删除项目”分组，还是随项目不可见？项目对话本身是否一并删除？  
2. 服务离线时，侧栏能否展示本地缓存的完整历史和项目关联？“显示更多”、改名、置顶、删除哪些操作允许离线执行并何时同步？  
3. 搜索是否应检索全部历史、改后的名称、项目名称及项目关联；结果是否需要标出对话所在项目？  
4. 同时被置顶的多条对话按什么顺序显示：最近聊天时间、置顶时间，还是允许用户排序？
