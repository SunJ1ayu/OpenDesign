**Direction:** 以「对话—项目关联规则 + 双视图一致性 + 本地持久化（置顶/改名/视图切换）」为测试主轴，用 P0 主流程与组合/失败路径用例锁死用户可见行为，回归题面里未改动的侧栏能力（项目分堆、删除确认、点对话回首页续聊等）。

**Core bet:** 最大用户伤害来自「找不到对话、对话出现在错误项目下、置顶/改名丢失」和「按时间 / 按项目两套列表对同一对话说法不一致」，而不是 UI 文案细节。

**How it works:** 每条用例只写用户可点的步骤与可见结果；关联判定只测题面两类——助手对项目「动手」或即为项目对话；多项目则多行出现；仅口头提项目名归「其他对话」。持久化用「关软件再开」验收，不靠改配置文件。

**Best at:** 开发前对齐验收标准、给实现一条可执行的通过线，并覆盖题面要求的三类（失败路径、组合、跨功能）。

**Sacrifices:** 不测性能/大量历史数据、不测同步多端、不测「有人砸墙」式本地文件破坏；不验证助手内部是否「真的」读过档案，只验证用户侧是否按规则归类与展示。

**Blind spots in the brief:** 「动手」边界（例如只打开项目页未记账是否算）、项目删除后对话是否仍出现在「按项目」某处、聊天服务断开时列表是空白/缓存/错误提示、置顶在「按项目」展开项里是否仍显示原时间分段位置、自动标题与改名后的展示优先级均未在题面写死。

**Smallest first step:** 先写并评审 3 条 P0：默认「按时间」+「显示更多」能到最早；助手记账后该对话在「按项目」对应项目下立即可见；置顶+改名后重启仍在「已置顶」且标题为用户所改。

# 1. 用户故事 + 验收标准

**US-01 按时间浏览全部历史**  
- **Given** 用户有超过「今天/昨天」段的旧对话，且侧栏为「按时间」  
- **When** 用户多次点击「显示更多」  
- **Then** 分段为今天 / 昨天 / 更早，能一直翻到最早一条；每条可点回首页续聊；无「全部」无效入口误导  

**US-02 视图切换与记忆**  
- **Given** 用户曾选择「按项目」  
- **When** 用户关闭并重新打开软件  
- **Then** 侧栏仍为「按项目」；新用户或从未切换时为「按时间」  

**US-03 置顶区**  
- **Given** 用户通过「⋯」将某对话置顶  
- **When** 用户查看侧栏（任一时间视图）  
- **Then** 顶部出现「已置顶」区，该对话在其中；无置顶时不显示该区  

**US-04 对话菜单：改名与删除**  
- **Given** 用户在历史列表某条对话上打开「⋯」  
- **When** 用户改名或删除  
- **Then** 改名后列表立即显示新名称，重启后仍为该名；删除需确认，确认后列表中消失且无法再点开  

**US-05 按项目展开与项目对话顺序**  
- **Given** 侧栏为「按项目」，某项目下有多条关联对话含项目对话  
- **When** 用户展开该项目行  
- **Then** 项目对话排在最前，其余按时间；点项目名进项目页；点某条对话进首页续聊该对话  

**US-06 多项目关联**  
- **Given** 同一段对话中助手对项目 A、B 均「动手」  
- **When** 用户在「按项目」下展开 A 与 B  
- **Then** 两段列表均出现该对话（名称一致）；在「按时间」中仍只出现一次  

**US-07 其他对话**  
- **Given** 某对话从未让助手对任何项目动手，且不是任何项目的项目对话  
- **When** 用户查看「按项目」视图最下「其他对话」  
- **Then** 该对话仅出现在「其他对话」，不在任何项目展开列表中  

**US-08 项目小标（按时间视图）**  
- **Given** 某对话曾碰过项目（含项目对话）  
- **When** 用户在「按时间」的历史列表查看  
- **Then** 名称后仍有项目小标（与现行为一致或题面约定一致，见疑问项）  

**US-09 跨功能：新对话与搜索**  
- **Given** 用户从侧栏点「新对话」或从搜索进入某历史对话  
- **When** 完成操作  
- **Then** 首页聊天正确；侧栏列表状态与关联规则不矛盾（新对话在未动手前在「其他对话」或按时间正常出现）

# 3. 探索式测试任务（真机界面）

1. **双视图同一对话心智模型**  
   - **目标：** 30 分钟内只在「按时间」「按项目」间切换，追踪 5 条已知对话。  
   - **关注：** 是否出现「以为丢了」或「同对话两处标题不一致」；置顶与展开列表是否让人以为有两条会话。

2. **记账瞬间的侧栏**  
   - **目标：** 新对话 / 首页 / 项目助手三入口各试一次「第一句就记账」。  
   - **关注：** 「按项目」是否无需关页才出现；项目页右栏聊天时侧栏是否同步。

3. **破坏性用户路径**  
   - **目标：** 置顶 → 改名 → 删另一条 → 删项目 → 重启。  
   - **关注：** 崩溃、空白侧栏、孤儿对话、置顶区残留名称。

4. **断网与弱网**  
   - **目标：** 断聊天服务后浏览、置顶、改名、切换视图。  
   - **关注：** 是否用旧列表冒充在线；操作失败是否有可理解提示。

5. **长列表与折叠**  
   - **目标：** 多阶段多项目、每项目多对话，全展开。  
   - **关注：** 滚动、折叠状态、点项目名与点对话是否误触。

# 4. 需要产品负责人拍板的疑问

1. **置顶与列表关系：** 已置顶对话在「按时间」/「按项目」展开列表里是否仍保留原位置（即置顶区 + 原处各出现一次），还是只在「已置顶」出现？  
2. **项目删除后：** 仅曾通过该项目「动手」的对话，删除项目后是进入「其他对话」、仅保留在「按时间」，还是仍挂在已删项目名（幽灵行）？  
3. **改名空/超长：** 是否允许空标题；超长是截断显示还是拒绝保存？  
4. **「动手」判定：** 仅「读档案」未写入变更是否算关联；在项目页打开但未发消息是否算。  
5. **聊天服务断开：** 侧栏展示策略是最后一次缓存、明确离线空态，还是禁止操作并提示？  
6. **按时间视图项目小标：** 多项目关联时小标显示一个、多个还是仍只标「主要」项目？
