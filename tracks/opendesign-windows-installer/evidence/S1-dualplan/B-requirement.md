# 需求:把一个本地 Web 应用做成 Windows 桌面软件(安装器 + 外壳 + 应用内更新)

只读本目录。给方案,不要写实现代码。用中文回答。

## 现状(已经验证过的事实,不是假设)

一个个人用的本地应用,技术栈:
- Python 3.12,**免装版(embeddable)** —— `sys.path` 由 `python312._pth` 写死、
  默认不加载 site-packages、不带 pip/venv。**已在目标 Windows 机器上实测跑通**
  (119 个依赖全部有 Windows 轮子、3 个子进程服务全部起得来、31 项自检全绿)。
- 两个后台进程:一个 agent 网关、一个 Web 服务(监听 127.0.0.1:8766)。
- 界面是浏览器里的单页应用,由那个 Web 服务提供。**界面不重做。**
- 整包解开约 251MB(其中运行时 + 依赖 ~228MB),zip 79MB。
- 目前的用法:解压到 `F:\AI\OpenDesign`,跑一个 PowerShell 脚本起服务,然后自己开浏览器。

## 使用者(一个人,非程序员)明确要的

1. **正经安装器**:选安装路径、桌面图标、"开机自启"勾选框、能卸载。
2. **桌面软件的形态,不是弹浏览器**:自己的窗口、自己的任务栏图标、没有地址栏。
3. **常驻**:关窗口 ≠ 退出,后台继续跑;**右下角托盘**里才是真退出。
4. **应用内更新**:启动时查一次有没有新版 → 提示 → 他点一下 → 自己下载安装 → 提示重启。
   **不要后台静默更新**。更新源用 GitHub Releases(已经在用,不另搭服务器)。
   **更新失败必须能退回旧版**,不许把他卡在一个打不开的软件上。
   **他的数据(记忆、对话历史、工作区配置)更新时一个字节都不许碰。**
5. 首次打开时问 API key 和登录口令(**不在安装过程里问**)。
6. 安装包体积能小则小(目前 zip 79MB,其中约 32MB 是确定用不上的依赖)。

## 约束

- 构建环境是 **Linux**(我在 Linux 上给他产出 `.exe`),他的机器上没有任何开发环境。
- 目标机器:Windows 10 / 11,单人使用,**不保证有管理员权限的使用习惯**。
- 代码签名证书要花钱,暂时没有。
- 不引入需要用户额外安装的东西(比如"请先装 .NET / 请先装 Node")。
