# Proposal: opendesign-windows-installer

- Date: 2026-08-12
- Status: open

## Goal

把 OpenDesign 做成**一个 Windows 单文件安装器**:双击 `.exe` → 装完 → 开始菜单出现
图标 → 点开就能用。全程不装 Python、不装 Git、不开 PowerShell、不答向导。

## Motivation

现在的装机路径(`docs/install-windows.md`)是:装 Python + 装 Git → `git clone` →
`powershell -ExecutionPolicy Bypass -File install.ps1` → **最多四次人工问答**
(onboard 向导 / WebUI 口令 / 粘贴 LLM key / apiBase)。

后果:**只有我带着业主一步步走才装得上**。两台机器各装一次都要现场救火(7-04 首装
踩的坑写了整整一节 §7)。要给第二个设计师用,或者业主换机器,这条路都走不通。

  软件,都是一个"业主自己搞不定就卡住"的点。

## Scope

- in:免装 Python 运行时随包携带;119 个依赖预置进包、装机时**零联网**;
  `nanobot onboard` 向导用脚本替代(今晚已验证成立);安装器本体(在本机 Linux 上构建);
  开始菜单/桌面入口 + 启动器;卸载;**装完以后的更新路径**(现在靠 `git pull`,
  不带 Git 的包必须另有办法)。
- in:业主自己的 LLM key 和登录口令的录入位置(装机时问 or 首次打开时问)。
- in:**桌面外壳**(08-12 业主纠正后新增)—— 自己的窗口、自己的任务栏图标、没有地址栏,
  关掉窗口时后台服务怎么办。**界面本身不重做。**

## Non-goals

- **不做代码签名**。没签名的安装器会被 SmartScreen 拦一下(要点"仍要运行")。
  签名要买证书、是笔钱,单独一单、业主拍板。
- **不做自动更新**(后台静默升级服务)。本单只要求"有一条业主自己能走通的更新路径"。
- **不改 OpenDesign 任何功能、不重做界面**。界面还是现在这套(网页技术做的),
  只是**换一层外壳**:装进一个属于自己的窗口,而不是弹浏览器标签页。
  后台那两个服务(gateway + ds-web)一行不动 —— **S0 验的东西一点没白费**。
- **不支持 32 位 / ARM Windows**,只做 64 位 Intel/AMD(业主两台机器都是)。
- **不做 macOS / Linux 安装器**。
- **不动现有 `install.ps1` / `docs/install-windows.md`**。它们是我(部署者)排查用的
  手动路径,保留;安装器是**另一条**给业主走的路,两条并存。

## 已经摸完的底(2026-08-12 夜,全部我自己跑的机器结果)

1. **向导可被脚本完全替代** —— 探针 6/6,且用脚本生成的 config **真把网关启起来了**
   (3 个 MCP server 全连上、agent loop 起来)。日志在
   `/tmp/claude-0/-root/b5644742-.../scratchpad/gw.log`。
   顺带查出探针自己的一个假绿口:判据 C 只问了 `apiKey` 非空,而 `${DS_LLM_KEY}`
   这个**占位符本身就非空** ⇒ 补强成两问(设了 key 解析出真值 / 没设当场 fail closed
   且报错说得出人话),重跑两向全绿。
2. **119 个依赖全部有 Windows 现成轮子,0 个源码包** ⇒ 用户机器上不需要编译器。
3. **整包可完全离线装配**(`pip install --target` + 本地 wheel 目录,rc=0)⇒
   装机不联网。解开 355MB,轮子压缩态 67MB。
4. **官方免装 Python 3.12.10 embeddable(11MB)存在且版本与这批 cp312 轮子对得上。**
5. **安装器可以在本机 Linux 上构建**(NSIS 有 Linux 版)⇒ 我直接交付 `.exe`,
   业主不需要任何开发环境。

## 最大的未知(决定方案形状,只有真机能答)

**免装 Python(embeddable)和正常安装的 Python 不是一回事**:sys.path 由 `._pth` 文件
写死、默认不加载 site-packages、不带 pip/venv、缺若干标准组件。这一整套(119 个包、
3 个 MCP 子进程、native 扩展)能不能在它上面跑起来,**我在 Linux 上验不了,只能猜**。

⇒ 本单**第一件事是一个巴掌大的探路包(S0 spike)**,不是直接造安装器。猜错的话方案形状
要重来(退路:改带完整 Python 而不是 embeddable),那种情况下先造 150MB 成品是纯浪费。
