# Proposal: opendesign-dist-freshness-gate

- Date: 2026-08-24
- Status: open

## Goal

把「e2e 验的是不是当前源码的产物」这件事,从**猜时间戳**改成**比产物**,
并把它从一个场景挪到总跑入口,让 37 个前端 e2e 全部受这道闸保护。

## Motivation

08-24 接手时跑总跑,`llm_key.e2e.mjs` 红在它自己那道新鲜度闸上(「web/dist 比 web/src 旧」)。
查下来暴露三件事:

1. **闸报得对**(`c82dcbc` 改 `web/src/app.css` 晚于 `d704df8` 那次 dist 重建+提交),
   但那次改动是 **+5 行纯 CSS 注释**,build 会剥注释 ⇒ **产物零变化**
   (实测:重 build 后三个文件与 `web/dist` 逐字节相同,vite 内容哈希文件名亦未变)。
   ⇒ **它问的问题(时间戳谁新)不等于它要防的事(产物是不是当前源码所出)。**
2. **它只装在 1 个 e2e 里,而前端 e2e 有 37 个** ⇒ 其余 36 个裸奔。
   「你以为验了你改的代码,其实没有」正是这道闸存在的理由,而它只守了 1/37 的门。
   (同族:memory `guards-must-watch-the-right-door`。)
3. 时间戳这个指标本身就脆:`tests/mutation-window-chrome.sh:36` 用 `cp` 恢复原状 ——
   还原内容却把 mtime 设成当前时间,08-23 12:19 那次红检就是这么把闸顶红的;
   切分支 / 复制 / 解压同理。**而且它反过来会漏报**:src 真改了、dist 因某个无关动作
   mtime 变新 ⇒ 闸绿而产物是旧的。**漏报才是致命的那一面。**

## 真问题(第一性)

- 用户原话:「这个现在不做之后是不是也得做」/「确定是报警器误报吗,第一性原理查一下吧」/「开工吧」
- 真正要解决的是:**「我跑的这趟 e2e,验的到底是不是我改的那份代码」现在没人可靠地守着。**
  不是「修一个误报」—— 误报只是这道闸问错问题的一个症状,漏报是同一个根因的另一面,且更危险。
- 我在这中间翻译了什么:**我翻译错了两次,都写在这儿防止再犯。**
  - ① 第一次判成「假红 / 误报」,理由是「src 内容没变过」—— **问错了区间**
    (按日期筛,而该比的是两次提交谁在后)。被业主一句「确定是误报吗,第一性原理查一下」推翻。
  - ② 推翻后我提的修法是「闸改成比 src 内容哈希」—— **仍然错**:内容哈希把注释也算进去,
    改注释照样报警,和比时间戳同一个毛病。
  - ⇒ 两次都错在**拿「我觉得产物没事」去回答「报警器对不对」**,而没去问这道闸到底该问什么。
    自检句:**「报警器错没错」和「它指的事要不要紧」是两个问题。**

## Scope

- in: 新写一道**比产物**的闸,装在 `tests/e2e/run-all.sh` 入口:
  build 到**仓外**临时目录,与 `web/dist` 逐字节比对,不同则 BLOCK 并说清怎么办。
- in: `tests/e2e/llm_key.e2e.mjs` 里那道比 mtime 的旧闸**退场**(职责被接管,新闸更准更全)。
- in: 这道闸自己的判据 + 红检 —— 必须证明:真过期咬得住 / 只改注释不误报 /
  build 失败不静默放过 / 不污染工作树。

## Non-goals

- **不修 `tests/mutation-*.sh` 的 `cp` → `cp -p`(8 个脚本)。**
  新闸不看 mtime ⇒ 红检毁 mtime 对它**不再有任何已知危害**。那仍是「工具没恢复干净」的
  真 bug,但它与既有教训「红检会被字节码缓存骗」**方向相反**、必须实测才敢动,
  为一件已无已知危害的事冒这个险不划算 ⇒ **记进 `docs/backlog.md`,不在本单做。**
- 不改前端代码、不改产品行为、**不动 0.93.0 已发的包**(已实测其产物正确)。
- **不给 e2e 加「自动 build 修复」。** 闸要保留信号 —— 「你欠一次 build」这件事本身
  必须被看见,不该被工具悄悄抹掉。
