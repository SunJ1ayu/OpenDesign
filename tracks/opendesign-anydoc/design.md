# Design: opendesign-anydoc

- Change: opendesign-anydoc
- Status: draft

- 规划双出: 待跑 —— 这一单**碰权限面**(在特意砌起来的墙上开一条读的缝),
  正是"我以为理所当然"最容易出事的地方。按规矩:我先落盘(本文件),
  再让 `gpt-5.6-sol` 对**同一份需求**独立出一版(明令不许读本 track 的工件),然后对差异。

## Approach

### 两个工具,不是一个 —— "先列、再读"

这是"不会读错"的**机械**保证(不是靠助手守规矩):

1. `list_project_docs(project)` → 该项目 `01-资料` 里的文档清单
   - 每条:文件名、**文件名里写的日期**(能解析出来才给)、**文件修改时间**、大小、
     后缀是否支持、是否疑似扫描件。
   - **排序由代码做**(最新在前),不让助手自己比日期 ——
     08-04 栽过:助手心算日期算错,后来专门加了 `resolve_date` 让代码算。
2. `read_project_doc(project, file)` → 把其中一份转成 markdown 返回,**不落盘**。

**助手拿不到路径,也不许拼路径**:它给的是"项目 key + 文件名",
路径由代码从绑定关系(`bind_project` 已有)推出来。它想读别的项目就得先列别的项目,
而"哪个项目对应哪个文件夹"是绑定关系说了算,不是它猜。

### 缝要焊死的几条

- **只读。** 这一单不碰 `disable_builtin_file_tools.py` 的任何一行,不新增任何写口。
- **路径**:文件名里出现任何分隔符 / `..` / 绝对路径一律拒;解析后 `realpath`
  必须落在该项目的 `01-资料` 内(**沿用现有 `_resolve` 那条咽喉,不开第二条路径解析面**)。
  符号链接按现有规矩处理。
- **后缀白名单**:只认 taxonomy 里 `01-资料` 那张表上的后缀。
- **一次一份 + 长度上限**:返回超过上限就截断,并明确写"这是前 N 字,全文约 M 字",
  不许静默截断(静默截断 = 助手以为自己读全了)。
- **扫描件**:转出来几乎没字 ⇒ 明确返回"这份是扫描件/图片 PDF,读不出文字",
  **不许返回空字符串让助手自己发挥**。
- **转换失败**:明确报错,同上,不许静默返回空。

### 助手契约:读了必须报出处

回答里必须带"我看的是《XXX》(X月X日那份)"。

理由:用户的两个前置条件盖不住**最可能的那种读错** —— 不是跨项目,是
**同一项目里的多版本**(`合同.docx` / `合同最终版.docx` / `合同最终版2.docx`)。
日期能排出最新,**但最新不一定是生效的那份**,那个只有业主知道。
报出处 = 把看不见的错(读了三个月前的旧版报给你)变成一眼能看见的错。

契约那段**要短**(往契约里加长文已栽过两次,会压垮别的行为)。

### 装法

`bin/install.ps1:65` 那行加 `firecrawl-anydoc==<钉死版本>`。
不 vendoring:它是 Rust 编译的 wheel,入库等于维护两份平台二进制。

## Key trade-offs / risks

- **两台 Windows 各要重跑一次装机脚本**(现更新流程 git pull + 重启**不装新包**)。
  这是躲不掉的手工活,也是这个项目历来最爱卡的地方。
  按部署规矩:**盘上有 ≠ 装上了**,验收要让运行中的目标自己打印出它有这个能力。
- **我本地网络是关的**(自己立的安全规矩),所以**真转换库我这边一次都跑不了**。
  我能验的只有我们自己写的那一层。见下面 oracle 那节 —— 这是本单最大的判据风险。
- **助手自主读(乙方案)比按需读(甲方案)更容易把无关内容塞进对话。**
  用户明确选了乙且给了前置条件,方向照办;控制手段 = 先列再读 + 长度上限 + 报出处。
- **anydoc 才发布两个月、版本 0.1.x** ⇒ 版本钉死,不用浮动版本。

## Alternatives considered

- **甲:你说了它才读。** 我原本推荐的,更保守。用户否了,理由是"助手存在的意义
  就是不用你记着提醒它" —— 这个理由成立,记在这儿。
- **丙:界面上给按钮。** 要改前端,且多一次点击;用户没选。
  (将来如果乙读错太多,丙是退路。)
- **认领时自动转成摘要入库。** 明确不做,理由见 proposal 的 Non-goals。

## Test strategy (oracle)

分两层:

1. **我们自己那一层(本地能全验)**:路径越权(`../`、绝对路径、软链、跨项目)、
   后缀白名单、长度上限与"截断要说出来"、扫描件/失败的明确回执、日期解析与排序、
   绑定关系缺失时的行为。转换库用**替身**注入。
2. **真库那一层(本地跑不了)**:一条"真库在场时才跑"的判据 —— 本地它会 SKIP,
   而 **SKIP 是可见的**(总跑把 skip 计入 `n_skip` ⇒ exit 3 不算通过;
   死断言闸也会把它归 ⏭️ 单独印出来)。Windows 真机上它才第一次真跑。

**这个 oracle 能被什么骗过?**

**替身和真库不一样** —— 这是本单最可能的假绿,而且我刚栽过同型的:
0.76 那单"判据自己会造抖动:替身漏抄真 API 常量"。
具体会错成:替身返回 `str`、真库返回对象;替身对扫描件返回 `""`、真库抛异常;
替身不认某个后缀而真库认。**断言全绿而 Windows 上一打开就炸。**

接得住这种错的只有:① 替身的签名/返回类型**照抄真库的公开接口**并在判据里钉住;
② 那条"真库在场才跑"的判据在 Windows 上真跑一次;
③ **验收标准是业主机器上真打开一份真合同并报出出处**,不是我这边全绿。
