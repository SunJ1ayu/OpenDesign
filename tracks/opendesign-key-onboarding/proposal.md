# Proposal: opendesign-key-onboarding

- Date: 2026-08-15
- Status: open

## Goal

装完第一次打开,业主看到的是**一个能填 key 的引导框**,填完就能聊天 ——
而不是现在那句"缺大模型 key,请把 key 放进 …\key.txt"然后自己去找记事本。
同一个框以后在**设置**里还能再打开(改 key / 换厂商),两处**同一个组件**。

## Motivation

- S1c 装完打开会停在一句人话上(比英文报错强,但仍是**死路**:他得自己找文件、
  自己贴 key、自己重启程序)。业主 08-14 原话:「装完第一次打开时问」。
- 业主 08-15 追加:「**参考一下 deepseek harness 是如何配置大模型 api key 的
  好像是在设置里统一弄**」⇒ 形状照它,四条已实读记在
  `tracks/opendesign-windows-installer/design.md` 的 S1d 段。

## 真问题(第一性)

- 用户原话:「**我觉得继续往下做 key 引导页吧**」+ 08-14 的「装完第一次打开时问」
  + 08-15 的「在设置里统一弄」。
- 真正要解决的是:**"我装好了,怎么让它动起来"这一步现在需要我在场**。
  (与 S1c 同源:那一单解决的是"装不上要我在场",这一单解决"装完不会用要我在场"。)
- 我翻译了什么:业主说"填 api key 就可以" ⇒ 我把**登录口令**判定为"不该出现在他面前
  的实现细节"。**这条翻译如果错了,整单的形状就错了**(他也可能觉得"有个密码更安全")。
  ⇒ 已在下面「必须先判的一件」里把代价摊开,并给出我的判断。

## Scope

- in: **首次打开 = 引导框**(选厂商 → 填 key → 保存 → 直接能用,不重启)
- in: 两家厂商,值**已实测**(不是照抄):
  - MiMo `https://token-plan-cn.xiaomimimo.com/v1`,默认 `mimo-v2.5`
    (`config/nanobot.config.windows.jsonc:25,33` 现行值)
  - DeepSeek `https://api.deepseek.com/v1`,`deepseek-v4-flash` / `deepseek-v4-pro`
    —— **08-15 现拉 `GET /models` 核过**,老的 `deepseek-chat`/`deepseek-reasoner` 确已下架
- in: **同一个组件**在设置里再出现一次(改 key / 换厂商)
- in: 🔴 **key 只写不回显**:存进去之后界面只显示"已配置",页面 HTML / aria / 控制台
  里都不许再出现它(照抄 DSH 那条,它有判据逐条断言)
- in: **登录口令不再要业主手输**(见下面那件必须先判的)

## Non-goals

- 不做多厂商通用配置界面(只两家;第三家等他提)
- 不做模型切换 UI(nanobot 自带 `/model`,业主已知道)
- 不碰安装器本身(S1c 已交付;本单是应用内的事)
- 不做"填错 key 时的自动诊断"(先做到"填了就能用",错了的诊断另开)

## 🔴 必须先判的一件(S1d 规格自己写着"开工第一件事就是判这个")

**要做到"他看都不用看登录口令",就得让 ds-web 把口令交给自己的前端。**
今天的形状是:业主**手输**口令 → 前端拿它去 `/api/chat/bootstrap` 换一张短票
(`web/src/chat/connection.ts:79-96`;ds-web 只是**透传代理**,自己不碰口令)。

改了之后多出来的口子:**本机任何能访问 ds-web 端口的东西,都能拿到驱动助手的凭据**。
逐条摊开:

| 谁 | 今天 | 改完 |
|---|---|---|
| 他自己机器上的其他程序 | 拿不到口令(除非去读配置文件)…… | 能问 ds-web 要 |
| **同一台机器上任何以他身份运行的程序** | **本来就能直接读 `%LOCALAPPDATA%\…\.nanobot\config.json`** | 一样 |
| 他浏览器里打开的**别的网站** | 打不动(不知道口令) | 🔴 **可能打得动**(CSRF / DNS rebinding) |

⇒ **我的判断:做,但只交短票、不交口令;并且必须同时补一道来源检查。**

1. **不交口令**:ds-web 自己拿配置里的口令去签一张**短票**给前端
   (它现在已经在代理这个签发口了)。前端永远不持有长期凭据,轮换口令即全部失效。
2. **补来源检查**:拒绝跨站请求(`Origin` / `Sec-Fetch-Site`)——
   **这才是真正新增的风险**:他随便打开一个网页,那个网页可以往 `127.0.0.1:8766` 发请求。
   今天挡住它的是"不知道口令",拿掉这层就必须换成来源检查顶上。
3. **"让他手输口令"保护不了什么**:口令就明文躺在他自己账户能读的配置文件里,
   本机进程本来就拿得到;ds-web 只听 127.0.0.1。所以那道手输**挡的不是本机进程**,
   只挡"知道端口但读不了文件的人" —— 在单人桌面上这个人不存在。
   **⇒ 用"安全"当理由让他每次输密码,是拿他的麻烦换我的心安。**

**这一条是安全面改动 ⇒ lane 写死 full,不许降档。**
