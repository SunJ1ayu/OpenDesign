# Proposal: 照 ZCode 重做模型设置(设置整页 + 模型列表 + 聊天框两级换模型)

- Date: 2026-09-24
- Status: open

## 真问题(第一性)

- 业主原话(09-24,装上 0.98.11 后):
  - 「问题还是很多啊，比如我填完api key为什么不能选择模型比如小米最新的v2，6呢」
  - 「zcode是怎么做的 你能不能好好看一下啊」「包括他们的前端设置页面排版」
  - 「不用分两步， 直接照zcode重做模型设置，其他的我晚一点总结给你」
  - 「严格按照zcode做，包括我们第一个开始聊天的页面，右下角点换模型之后弹出来的框的样式」
  - (对我提议的「从厂商拉取模型」按钮)「多做的按钮是你想做还是有人做了效果不错所以你也准备做」⇒ 我核实后撤回,本单不做。
- 真正要解决的是:模型清单写死在安装包里,厂商一出新模型(小米 09-22 发 v2.6-pro / v2.6-flash,服务端 `/v1/models` 已列)就用不上;
  设置只有一个「AI 模型 key」小弹窗,看不到每家有哪些模型、不能自己加、不能测。
- 我在这中间翻译了什么:
  - 「照 ZCode」= 以 ZCode 3.14.3 源码(`packages/ui/src/settings/model-provider-section/`、`ModelConfigSelect.tsx`)与第三方教程真截图
    (doc.dmxapi.cn/zcode.html,3.0.1)为准的**结构与交互**;视觉(配色/字体)沿用我们现有主题,不引入 Tailwind/radix。
  - 「严格」⇒ 设置从侧栏小弹层改成**整页**(左栏目 + 右内容,「返回工作区」),模型设置在其中;聊天框换模型改成 ZCode 的两级弹框。
- 用户可观察的成功:
  1. 设置 → 模型设置:左边厂商列表(状态小圆点),右边这家的详情:名称 + 已启用/禁用、Base URL、API Key(获取 API Key)、模型列表(测试 / 编辑 / 删除)+「添加模型」;
  2. 在小米那页「添加模型」填 `mimo-v2.6-pro`,点「测试」能通,聊天框里就能选到它,账单走小米;
  3. 「添加供应商」能加一个自定义供应商(名称、Base URL、API Key、模型),同样能测、能选;
  4. 聊天框右下角点模型:弹出厂商列表(当前那家打勾),移上去向右弹出这家模型(当前模型打勾),最底一行「管理模型」直达设置页。

## Scope

- in:设置整页(常规 = 现有弹层里的各项原样搬过去 + 模型设置);模型设置(内置五家 + 自定义供应商,每家模型列表可加/删/测/编辑上下文窗口,
  厂商启用/禁用);聊天框两级换模型弹框;内置清单补小米 mimo-v2.6-pro / mimo-v2.6-flash(服务端已核)。
- 后台:「每家有哪些模型」从写死清单改成「内置清单 + 用户登记」,沿用 kimi-glm 单磨稳的路由规矩(每份预设只发到主人那家)。

## Non-goals

- 「从厂商拉取模型列表」按钮(业主问后撤回:第三方插件最多 22 星、唯一反馈是 DeepSeek 404;各家接口不一)。
- 自定义供应商的 Responses / Anthropic Messages 两种 API 格式(nanobot 额外厂商只支持 OpenAI 兼容 chat completions,`api_type` 仅 providers.openai 可设)—— 发版说明写明。
- ZCode 的智谱套餐/体验套餐/用量卡、模型拖动排序、推理等级编辑器、「智能配置」远程下发。
- 没有外壳(git-pull / Linux)的装法:保持今天的单 key 行为,设置页照常打开但只管主槽那一家(design 细说)。

## 验收边界与轮次预算

- 承诺:上面「用户可观察的成功」1~4;**账单跟选中的那一家走**、已装好的机器更新后聊天照常、业主选好的模型不被本单改动换掉;
  已有配置(0.98.11 的五家、额外格、当前模型)升级后原样出现在新设置页里。
- 不承诺:挡不住任意将来改写的判据缺口;手改配置文件才有的形状;0.98.11 之前就有的行为(如 #60 额外厂商换 key 回默认,另排)。
- impact=high(钱 / 跨模块 / 新写口)。实质评审上限 2 轮;题面只问本单引入的正常入口缺陷与承诺是否兑现;
  「锤子砸墙」类照报不算阻断;分裂评审由主裁按 split_resolutions 裁(业主 09-24 定)。
