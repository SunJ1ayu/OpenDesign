# 验收清单(QA 两家合并 + 主裁定稿,09-24)

来源:evidence/20260924-qa-design-subdeepseek.md(J/U/R/E 编号)、20260924-qa-design-subcursor.grok-4.7-high.md(S/TC 编号)。
测法:**py** = 后台判据(nanobot 加载器问真发出的端点/key/模型);**e2e** = 真 chromium + 真 ds_web;**node** = 纯逻辑;**UAT** = 业主真机;**已有** = 已被现有判据钉住。

## 需求空白 → 主裁定(照 ZCode + 已定规矩;不需业主拍板)
- Q1 状态点(DS#1、Grok Q3):绿「就绪」= 已填 key + 后台已拿到 + 启用;黄「未就绪」= 没填 key 或已保存等重启(详情区写「已保存,正在重启后台…」);灰「已禁用」。
- Q2 显示/隐藏(DS#2、TC-08/S9):眼睛只管**正在输入的新 key**;已存的 key 永远只显示首尾几位,输入框为空(换 key = 重新粘贴)。
- Q3 测试按钮花不花钱(DS#3):向这家发一句最短请求(max_tokens 16);按钮提示写明「会发一句很短的请求」。
- Q4 重启窗口(DS#4、TC-15):存 key 后详情区提示「已保存,正在重启后台…」,重启完成前这家不进换模型菜单;「测试」不等重启、直接用存下的 key。
- Q5 清空 key(DS#5、TC-20):不提供「清除 key」;空着保存 ⇒ 报「API key 是空的」,原 key 与当前模型不变。
- Q6 老装法(DS#6、TC-26):模型设置顶部说明「这台机器是老装法,只能用一家:存哪家的 key 就用哪家」;不显示「添加供应商」。
- Q7 刷新(DS#7、Grok Q1):重新向后台取一次列表与状态(重启完成后点它变绿);不改任何数据。
- Q8 自定义供应商改名 / 改 Base URL / 删除(Grok Q2):照 ZCode 都给;改 Base URL 同样查撞车。⇒ 后台补 update_custom_provider(判据先行)。
- Q9 design.md 的 Approach 段还写「禁用 = 等同没 key、当前回落」(Grok blind spot)⇒ 与 D3 冲突,改正文档(代码按 D3)。
