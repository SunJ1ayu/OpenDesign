# Proposal: 全新的非中文 Windows 装不上(一句成功提示卡死安装)

- Date: 2026-08-25
- 起因:**第一次把真安装包搬上云 Windows 机器跑**(`windows-package-probe`,run 32801760571),
  不是推理、不是业主报障。

## 现象(云机器实测)

安装器 `/S` 静默安装**永不退出**;文件其实全铺好了(173MB);软件能打开,但只会说
「还没装好:找不到配置文件 …\.nanobot\config.json」;`127.0.0.1:8766` 起不来。

## 根因链 —— 每一环都在做正确的事,合起来是坏的

1. `ds_merge_config.py` **把配置写好了**,然后死在最后一句**成功提示**上:
   `print("ds_merge_config: 已合并 4 段进 …")` →
   `UnicodeEncodeError: 'charmap' codec ...`(英文 Windows 的 stdout = cp1252);
2. rc≠0 ⇒ `ds_provision.merge_template` 判定"配置合并失败"、抛 `Trouble`;
3. provision 的顺序是"先在 `.new` 上做完、最后原子换名",`finally` 删掉临时文件
   ⇒ `config.json` **从来没出现过**(这个顺序是对的:半份配置比没有更坏);
4. 安装器收到 2 ⇒ 弹「配置初始化没有成功(错误码 2)」;
5. **NSIS 的 `MessageBox` 在 `/S` 下照弹**(4 个全没 `/SD`)⇒ 没人点 ⇒ 安装器假死。

**一句成功提示,弄死了一次已经成功的合并。**

## 业主受影响吗

**目前不受**:他两台都是中文 Windows(cp936),"已合并"编得出来。
**但任何非中文 Windows 都装不上**,且现象是"安装程序假死",零线索。

## 改什么(两处,互相独立)

- **① 真因**:让这条链上的 Python 输出与控制台编码无关
  (`ds_merge_config.py` / `ds_provision.py` 各自把 stdout/stderr 重设成 UTF-8;
  并给合并子进程显式传 `PYTHONIOENCODING=utf-8`)。
  **一句提示不该有能力弄死一次成功的合并。**
- **② 防线**:`installer/OpenDesign.nsi` 的 4 个 `MessageBox` 全部补 `/SD`。
  **与①无关**:①修好了,下一个错误照样能把无人值守的安装卡死。
  默认值规矩:纯告知型 → `IDOK`;涉及可能删掉业主东西的选择 → `IDCANCEL`(保守那一侧)。

## 不改什么

- provision"先临时文件、最后原子换名"的顺序:**它是对的**,别顺手动它。
- 业主手动安装的体验:两处改动他都应该感觉不到。

## 这一单最该留下的一句

链上每一环都有判据盯着,**而"整条路走完之后 config.json 在不在"没有任何一条判据问过** ——
和 0.93「判据全绿、界面全白」是同一个病:**都在问退化,没人问"还在不在"。**
