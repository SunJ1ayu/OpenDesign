# Proposal: opendesign-tmpdir-leak

- Date: 2026-08-17
- Status: open

## Goal

本仓库的判据每跑一轮,就往 `/tmp` 留下几千个再也没人收的临时目录。
这个 change 让它们跑完自己收干净,并**加一道机械闸**,让以后再漏当场红。

## Motivation

2026-08-17 业主报「磁盘满了」。50G 盘用到 45G(94%),排查发现 `/tmp` 有
**205,666 个条目、6.5G**,几乎全是本仓库判据建的临时目录。

- 最早的 7-27,最新的就在排查当天 —— **不是历史遗留,是水龙头还开着**。
- 光排查当天那一轮 `run-all.sh --with-gateway`,就新增了约 1.7 万个。
- 每个只有 12~36K,但 20 万个 = 6.5G,吃掉整块盘的八分之一。

清理只是止血:清完 13G,照这个速度一两个月又会满回来。

## 真问题(第一性)

- 用户原话:「磁盘满了看一下什么可以清理」/「什么泄露 大白话说一下」
- 真正要解决的是:**不是"这次腾出空间",是"别再漏"**。业主要的是盘不会
  隔两个月就满一次、不用他再问一遍。腾空间是我给的第一层答案,他追问
  「什么泄露」正说明他要的是根因不是清扫。
- 我在这中间翻译了什么:把「清理磁盘」翻成了「修判据的临时目录泄漏」。
  这一步转译**是有风险的** —— 万一大头不是判据而是别的东西,后面全白做。
  所以先做了实测普查(见 evidence/),用 `/tmp` 里各前缀的实际堆积数
  证明大头确实是判据,而不是靠我读代码猜。

## Scope

- in: 46 处 `mkdtemp` 调用点(21 个 python 判据文件 + 2 个 node e2e 文件)补上清理
- in: 一道机械闸 —— 判据跑在隔离的 TMPDIR 里,跑完必须剩 0 个,否则红
- in: 闸接进 `tests/run-all.sh`,且**不新增跑时**(见 design)

## Non-goals

- 不改任何被判据测的产品代码(`bin/`、`web/` 一字不动)
- 不动那 60 个已经收干净的调用点
- 不清理业主机器上别的东西(spike/build 目录等,业主本轮明确说不动)
- 不加定时清理 cron —— 那是治标,且会掩盖闸的红
