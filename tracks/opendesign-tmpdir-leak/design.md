# Design: opendesign-tmpdir-leak

- Change: opendesign-tmpdir-leak
- Status: draft

- 规划双出: 不适用 —— 不是新写面,也不是开放方向。产品代码(`bin/`、`web/`)一字不动,
  改动全在判据侧,且方向只有一个能立住的(见 Alternatives)。

## Approach

三件事,顺序不能换:

### 1. 一道行为闸:`tests/tmpdir-leak-gate.sh`

把一条命令跑在**空的临时台面**上(`TMPDIR/TMP/TEMP` 三个都指过去),跑完数台面上剩几个。

**为什么是"数台面"不是"扫代码"** —— 这条是这一单最值钱的决定,因为扫代码那条路
我先走过,**当场翻车两次**:

| | 扫代码判的 | 实测 | 真相 |
|---|---|---|---|
| `test_ds_web_upload.py` | 干净(文件里有 addCleanup) | 漏 3678 个 | `_mkdist()` 把目录当参数直接传进去,没人接没人收 |
| 31 个 `.mjs` e2e | 漏(文件里没 rmtree) | 各剩 1 个 | 是上次跑崩的残渣,实际收得干干净净 |

病根:**「文件里出现过清理代码」回答不了「这一处建的目录有没有被收」**。
行为闸问的是能被机器直接量出来的那个问题,而且**没法靠改断言蒙混** ——
想让它绿只有一条路:真把目录收干净。

### 2. 补上 47 处清理

- python 44 处 / 21 文件 → `self.addCleanup(shutil.rmtree, X, ignore_errors=True)`
  (仓库里 60 处已经收干净的就是这个写法,照抄不发明新的)
- node e2e 2 处 / 2 文件 → `process.on("exit", () => rmSync(X, {recursive:true, force:true}))`
- shell 1 处 → `tests/e2e/run-all.sh` 的 `E2E_HOME` 加 trap

### 3. 接进 `tests/run-all.sh`,且**不新增跑时**

`run-all.sh` 自己的文件头写着「**慢到会被跳过的检查等于没有**」,08-15 还实证过一次
(S1b 两条判据默认 skip,两天没被任何总跑叫起来)。所以不新开一段跑 512 秒,
而是把闸**套在现有各段外面** —— 各段本来就要跑,套上去零额外开销。

## Key trade-offs / risks

- **最大的风险不是漏改,是"补清理时把判据本身改坏"。** 给判据加 `addCleanup` 有可能
  改掉它的隔离语义(例:某条判据本来靠目录残留跨用例传状态)。那种坏**测试还是绿的**,
  只是测得更少了 —— 正是本机规矩里最忌讳的"改考卷让自己及格",哪怕不是故意的。
  接法:改完比对**用例数与断言数必须逐字节不变**(376 node / 1277 python),
  且 `dead_assertions.py` 报的死断言数不许增加。数字一动就是改坏了。
- **底噪必须实测,不能假设。** 已测:段① node 单测 0、段③ MCP 闸 0、段④ 前端构建剩 1 个
  `node-compile-`(Node 自己的编译缓存,固定名复用,全普查只有 1 个 ⇒ 不累积)。
  段②⑤ 见 evidence。**断言是"剩 0",不留余量** —— 留了余量,漏就藏在余量里长。
- **`--allow` 是这道闸唯一的放水口。** 目前只放行 `node-compile-`,理由写在调用处。
  每加一条都要说清为什么它"该被留下",不是"暂时先放过"。放行清单当垃圾桶用,闸就废了。
- **总跑日志目录不是漏。** `run-all.sh` / `e2e/run-all.sh` 全绿时 `rm -rf` 日志目录,
  红了故意留着给人看。普查里 `ds-all-` 78 个 = 78 次跑红,是**故意保留**。
  闸套在段外面,看不见它们,天然不会误报 —— 这点是查过代码确认的,不是撞运气。

## Alternatives considered

- **只加个 cron 定期清 `/tmp`** —— 否。治标,而且**会掩盖闸的红**:漏照样发生,
  只是被定时任务扫掉、没人再看见。业主追问「什么泄露」,他要的是别再漏。
- **静态扫代码(grep mkdtemp 附近有没有清理)** —— 否,上表两次翻车实测证伪。
  且它是模式匹配,弱模型改个正则就能让它绿;本仓库两次栽在"用正则找 JSX 标签边界"。
- **每个判据文件各自加一条自查断言** —— 否。47 处要写 47 遍,写漏一处就是个洞,
  而且新写的判据默认不带 —— 等于把"记得加"重新交回给人。闸挂在总跑上,新判据自动被罩住。
- **把闸单独做成第六段跑一遍全量** —— 否。多花 512 秒,撞上"慢到会被跳过的检查等于没有"。

## Test strategy (oracle)

主 agent 亲自写,不外包(改动面本身就是判卷层,见下方"为什么不派出去")。

1. **闸的红检 + 对照组**(证明它咬得动、又不乱咬):
   - 干净判据 `test_ds_organize` → 必须绿(不误报)
   - 漏的判据 `test_ds_web_api` → 必须红,且报出的前缀能指到调用点
   > 只跑"红"那一半不够:一道见谁都红的闸和一道永远绿的闸一样没用。
2. **闸自己的判据** `tests/test-tmpdir-leak-gate.sh`(七条,钉死退出码透传):
   命令红了要透传命令的 rc,不能被闸的 1 盖掉 —— 盖掉的话"判据挂了"会被误读成
   "判据漏目录",修错方向。本仓库**四次**栽在"管道吃掉 rc 造出假绿收据",
   而这道闸正好是个包装,是同一种病的高发处。
3. **修完的验收**:`tests/run-all.sh --with-gateway` 五段全绿,**且**
   用例数/断言数与修前逐字节一致(376 / 1277),死断言数不增。

**这个 oracle 能被什么骗过?**

- **骗法一(最可能):把判据的隔离语义改坏,而闸和总跑都还是绿的。** 闸只问"目录收没收",
  不问"这条判据还测不测得出原来那件事"。极端例子:把某条判据整个删掉 —— 不漏了,也绿了。
  接法就是上面那条**用例数/断言数不许变**,加 `dead_assertions.py` 的死断言数不许增。
  这三个数是这道闸看不见的那一面。
- **骗法二:`--allow` 当垃圾桶。** 往放行清单里塞前缀,闸就哑了。这条**机器接不住**,
  只能靠 review 盯:放行清单现在只有 1 条(`node-compile-`),多一条都要在 verify 里说清理由。
- **骗法三:业主眼里的成功和闸的绿不是一回事。** 闸绿只证明"判据自己跑完收干净了";
  业主要的是"盘不会再满"。这两者之间还有一段:**别的东西也可能漏**(gateway、
  playwright、别的项目)。所以收口时要额外给一条**盘面事实**:清理后可用空间,
  以及跑完一整轮总跑后 `/tmp` 的净增量 —— 净增量约等于 0 才算真答了业主的问题。
  (断言全绿但业主照样丢东西/丢空间,本仓库 0.87.0 那单栽过 20 条路线。)

## 为什么不派出去(派给的理由,提前落这儿)

这一单的**改动面 100% 是判卷层**。而派活规矩里"oracle / 判据文件对执行腿 off-limits"
在这儿直接失效 —— 要改的就是判据文件本身,闸①"它有没有动判卷"问不出任何东西,
因为它碰的每个文件都是判卷。

考虑过 Sonnet 腿(不是排除了 codex 就跳到"我自己干"):**技术上可行**,
拿"用例数/断言数不许变"当收货闸就能罩住。没派的实际理由是**这 47 处的改法我已经
逐处知道了**(前缀→调用点的映射是实测出来的),写任务书 + 走三道闸的开销大于活本身。
