# Proposal: opendesign-note-source

- Date: 2026-08-11
- Status: open

## Goal

**备注只有一个真相源:业主的档案文件。** 待办页不再靠"浏览器这次打开的临时记忆"
显示备注(刷新就没、换台电脑就没),改成和工作区一样从档案读;
同时把"这次编辑到底改了没有"这个判断**收敛到后端一处**,前端不再自己判一遍。

## Motivation

0.83.0 刚修完"清空备注存不掉"(track `opendesign-note-clear`)。业主看完那一单的
说明后问了一句:**"那其实现在的修法是在打补丁吗,没有根据第一性原理对吗"** ——
他说对了一半,而剩下那一半正是这一单。

上一单留下的三处形状(verify 里 F5 + Accepted deviations 都记了账):

1. **待办页的备注根本不是从档案读的**。`/api/todos` 的载荷里没有 `note`,
   待办页显示的备注来自 `TodoPage` 里一份只活在当前网页会话的 `noted` 映射
   ⇒ **刷新一下、换台机器打开,待办页上的备注就不见了**(工作区那侧从档案读,看得见)。
   同一份数据,两个页面两套真相源。
2. **"变没变"有两个地方在判**:前端 `buildEditRequest` 判一次(决定发不发请求)、
   后端 `edit_change` 判一次(决定写不写文件)。同一个道理写在两处 —— 上一单的
   四审 LOW-1(写同值备注也假 bump 页脚)就是这条缝里长出来的。
3. **`note=""` 的含义靠约定跨三层传递**。它今天是对的,但它靠人的记性活着。

## 真问题(第一性)

- **用户原话**:「我觉得还是直接按第一性原理整理掉」
  (上一句是「那其实现在的修法是在打补丁吗,没有根据第一性原理对吗」)
- **真正要解决的是**:同一条备注,**在哪儿看都该是同一个答案,并且刷新之后还在**。
  他不关心"会话级映射"这种词;他会遇到的是"我明明写了备注,第二天打开待办页没了"。
- **我在这中间翻译了什么**:把他那句"按第一性原理整理"翻译成了
  **①单一真相源 + ②单一判定处**这两条,而**没有**顺手把"陈旧编辑保护"和
  "写文件的崩溃原子性"也塞进来 —— 那两条我在同一次对话里单独问过他,
  他明确选了"先做真相源统一,做完再决定要不要接着做"。**范围是他划的,不是我猜的。**

## Scope

- in: `/api/todos` 的载荷带上持久 `note`(与 `/changes` 同源、同一份读侧解析)。
- in: 待办页删掉 `noted` 会话映射,备注一律以服务端为准(刷新后仍在)。
- in: "变没变"只由后端判 —— 前端不再做等值比较来决定发不发请求;
  写口契约从"动作型"改述为**状态型**(请求描述的是你想要的最终样子)。
- in: `## 变更历史` 的**读侧解析挪到共享层**,让 `ds_todo` 和 `ds_tools` 用同一份
  (直接 import 会撞 `ds_tools → ds_todo` 的既有依赖方向,环闸会红)。

## Non-goals

- **不做**"陈旧编辑保护"(`expected_note`,防止保存时悄悄盖掉别人刚改的)—— 业主明确
  说先不做,在 `docs/backlog.md` 排队。
- **不做**档案写入的崩溃原子性(临时文件 + `os.replace`)—— 同上,老账,单独一单。
- **不做**手写前导零 cnum(`- C03 备注:`)那条读写不齐 —— 上一单四审记的账,
  要动的正是刚对齐过的那对正则,值一次独立的红检,不搭车。
- **不碰**待办页的"看原文"(`edited` 映射)—— 那是另一个功能,同样是会话级,
  但它显示的是**改之前的旧正文**,天然只对本次会话有意义,不属于本单。
- **不改**助手那侧:`edit_change` 仍然不进 MCP 工具表(上一单 verify 的 M1 墓碑)。
