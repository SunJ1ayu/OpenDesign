# Proposal: dead-assertion-gate

- Date: 2026-08-07
- Status: done

## Goal

一道机械闸:跑一遍 python 判据,把**写在那儿、却一次都没被执行过的断言**当场报出来,
并把它挂进总跑(替代原来的 `python -m unittest` 那一段,一次跑、两个信号)。

## Motivation

2026-08-06 实事故(`tests/test_ds_web_upload.py`):

    st, d = _post(...)              # 文件太大 → 服务端在读 body 前就掐断连接
    if d:                           # ← d 永远是 None
        self.assertIn("收件箱", ...) # ← 这一行一次都没执行过

判据绿、总跑绿、四审前三层全看不见 —— 因为**每一层看到的都是"通过"**。
同一个文件里早就有一条注释警告过这种写法,我照样又犯了一遍 ⇒ 规矩靠记不住,得靠机器看。

## 真问题(第一性)

- 用户原话:**这一单没有一句对应的用户原话**。它来自 08-06 深夜和用户复盘"工作流是不是到头了"
  排出的下一步清单里的第 1 件,措辞是我复盘后写的:"让『判据其实没跑』变得机械可见"。
  ——这一格不许拿我自己的话冒充用户的话。
- 真正要解决的是:**"绿"这个信号本身不可信**。三道闸查的都是"它改了什么",
  没有一道查得了"这条断言到底有没有被问出口"。
- 我在这中间翻译了什么:把"断言没被问出口"翻译成**"断言所在的那一行从没执行过"**。
  这个转译是本单一切风险的来源(行粒度 ≠ 语句粒度),评审当场就打在这上面(见 verify F2)。

## Scope

- in: 新增只读检查器 `tests/dead_assertions.py` + 它自己的判据 + 放行清单;
  `tests/run-all.sh` 的 python 段换成它。

## Non-goals

- 不改任何产品行为(纯判卷防线,产品代码一字未动)。
- 不追求"抓全所有没跑的代码" —— 只盯断言,没执行的 `else: pass` 不管。
- 不引入任何新依赖(`sys.monitoring` 是 3.12 自带,不用 coverage.py)。
