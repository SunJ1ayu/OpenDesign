# Proposal: 应用内更新第二刀 —— 按下去就装好(并自己报出新版本号)

- Date: 2026-09-08
- Status: open(**未开工** —— 由 `opendesign-in-app-update`(第一刀,0.98.4,主裁 PASS)
  收窄时拆出;那一单只交付「只查不装」)

## Goal

第一刀做到"软件自己发现有新版、说一句、给个下载链接"。**业主仍然要自己去点链接、
下 43MB、双击重装。** 这一单把剩下那半截去掉:他点「更新」→ 下载 → 校验 → 收摊 →
静默装 → 重新起来 → **新起来的进程自己在 `/api/health` 报出新版本号**。

🔴 **收口判据是最后那半句**,不是"安装器退出码 0"。
(CLAUDE.md「在使用现场验证」:盘上有新文件 ≠ 部署了。这个项目为这条栽过两次。)

## 真问题(第一性)

- 用户原话(第一刀那单原样抄过来):把「打开浏览器 → 找到 GitHub 仓库 → 翻 releases →
  下 43MB → 双击重装」这五步手工活去掉。
- 真正要解决的是:**业主不该知道 GitHub 是什么。** 第一刀把"他不知道有新版"解决了;
  这一单解决"他知道了也得干五步手工活"。
- 我在这中间翻译了什么:第一刀我把"更新"翻译成了"通知";这一单不许再翻译 ——
  他说的是**装好**。

## 已经知道的地雷(第一刀查证过,不是推测)

1. 🔴 **`.nsi` 自己在注释里写着**(`installer/OpenDesign.nsi:92`):程序在跑的时候文件
   锁着,`RMDir /r` 删不掉会**悄悄跳过** ⇒ 边跑边更新 = **一半新一半旧,一声不吭**。
   任何做法都必须先把跑着的东西收干净(外壳 + 托盘 + ds_web + nanobot)再替换文件。
2. **安装布局是平铺覆盖**(`OpenDesign.nsi:113-117`),没有版本化组件、没有指针。
   `opendesign-windows-installer` 里写的「版本化组件 + 指针在这一单落地」**至今没落地**。
   想只下增量那一层,等于先做一次安装布局重构 —— 要先决定做不做。
3. **信任根只有一条:HTTPS 到 github.com + GitHub 给的 `digest`(sha256)。**
   它挡得住"下坏了/下半截/中间人换包",**挡不住"GitHub 账号被盗后换资产"** ——
   我们没有代码签名证书。这是明账,不假装有。
4. **已有一条不用麻烦业主的验证路径**:`.github/workflows/windows-package-probe.yml`
   能把真安装包搬上云 Windows 机器。这一单的端到端应该照它的形状做。

## Scope

- in: 下载 → sha256 校验 → 备份 `$INSTDIR` → 收摊(确认端口/进程真没了)→ 静默装 →
  拉起 → `/api/health` 回显新版本号才算成功 → 成功删备份 / 失败换回备份
- in: Windows CI 端到端(e1 真更新成功 / e2 改坏一个字节要拒装)
- in: 第一刀留下的 backlog(下面「继承的账」一节,逐条)

## Non-goals

- 不做增量/差分更新(先把全量装对;要不要版本化布局是这一单里先拍的一个板)
- 不做自动静默更新(**必须他点**;开机自己换掉软件不是这个产品该有的行为)
- 不碰代码签名证书(要花钱、要业主拍板)

## 继承的账(第一刀原样搬过来,一条不许丢)

**A. 只有业主能验、而第一刀结构上验不到的**
- 🔴 **S6:那行下载链接 `<a target="_blank">` 在 pywebview 外壳里到底开不开浏览器
  ——从来没有人验过。** 第一刀装上 0.98.4 时线上最新就是 0.98.4,软件只会说"已是最新",
  **那条路走不到**。⇒ **本单发版那天,业主真机清单的第一条就是它**
  (他手上的 0.98.4 会第一次真的说"有新版")。同时验蓝点 `●` 显不显眼。

**B. 判据自己的洞(第一刀收口那晚撞上的)**
- 🔴 `tests/e2e/project-thread.e2e.mjs` 的夹具是 ds_root 里那两个项目文件,**没进仓**
  (`.gitignore:23` 排掉了整个 `projects/`)。它连的是外面起好的 ds_web、够不着人家的
  DS_ROOT ⇒ 夹具只能靠机器上碰巧有什么。**换台机器新克隆必红,且报错里一个字都不提夹具。**
  它长年被 SKIP(要活 gateway),这个洞从没露过头。
  ⇒ 正解:让它自己用 `/api/projects/create` 造夹具。机制与临时办法已写在
  `tests/e2e/README.md` 第 3b 步。

**C. 第四轮 panel 的 4 条 LOW(接受不改、原样搬过来;第二刀本来就要动这块)**
- `notesSummary` 跳 setext 标题时**没把下面那行下划线一起吃掉**:1~2 个字符的
  `==` / `--` 会被当正文印出来(≥3 个字符时 `HORIZONTAL_RULE` 兜住了)。
- **多行 setext 标题只跳最后一行**,前半截照印。
- **列表项紧贴 `---` 时,第一条要点被当成 setext 标题吃掉**(GitHub 渲染成正文)。
- **资产名漂移只有注释级契约**:`bin/ds_update.py:35` 的 `ASSET_RE` 与
  `installer/build-installer.sh:146` 的产物名之间没有机械绑定
  ⇒ 给 `EXE=` 那行加一条机械断言。
  (它管不到的是"在 GitHub 网页上手改资产名",那一幕没有任何机械防线。)

**D. subkimi 的观察,核过属实,但第一刀故意不改**
- `asset` 字段在第一刀范围内**没有任何消费方**(界面下载行只用 `release_url`)。
  放宽 `pick_latest`(不要求有安装包)能让"没有安装包的 release 被静默跳过"这一类消失,
  但代价是可能把业主指向一个下不动的东西。**第二刀真要下载了,这个取舍必须重新拍一次板。**

## 先要拍的板(开工前)
