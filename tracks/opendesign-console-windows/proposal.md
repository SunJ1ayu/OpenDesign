# Proposal: 打开软件不该冒出黑窗口

## 业主原话(2026-08-17,装完 0.89.0 之后)

> 为什么打开这个软件还会跳出命令行呢 这个应该算 bug 吧
> 就是出来一个命令行的黑窗口有点像 powershell

追问后确认:**两个**黑窗口;**关掉一个没反应,关掉另一个界面就报"断开连接"**。

## 这不是难看,是危险

那两个窗口是**活的进程**:一个是网关、一个是工作台。业主随手关掉其中一个,
就等于杀掉一条腿 —— 他已经亲手复现过一次(关掉网关那个,聊天当场断)。
无边框窗口这一版刚把"唯一的出口"焊死在右上角三个按钮上,
结果旁边还杵着两个**一关就坏事**的窗口。

## 根因(一句话)

外壳自己是**没有控制台**的 `pythonw.exe`,却用 `python.exe`(控制台程序)起腿。
**一个没有控制台的进程去起控制台程序,Windows 会为它新开一个控制台窗口。**
`_spawn()` 的 `creationflags` 只设了 `CREATE_NEW_PROCESS_GROUP`,没有 `CREATE_NO_WINDOW`。

网关自己拉起的那 3 个 MCP 工具服务**不在此列** —— nanobot 用的 MCP 库
(`mcp/os/win32/utilities.py`)自己设了 `CREATE_NO_WINDOW`。所以恰好是两个,
和业主数到的一致。

## 不修成什么样(第一性,业主 08-17 明确要求:别出屎山)

**不是**"哪儿冒窗口就往哪个 `Popen` 上补一个标志"。那是按症状打补丁:
补完这两处,下一个写 `subprocess.run(...)` 的人照样漏,而且**漏了没有任何东西会响**
—— 这正是这个仓库已经吃过一次的亏(ctypes 的 `argtypes`:一处写对了、另一处漏了,
四审才逮到)。

真正的不变量是:

> **这是个 GUI 程序。它发起的任何子进程创建都不许弹出控制台窗口。**

⇒ 修法两件,一件是代码结构,一件是防线:

1. **平台标志只有一个所有者**。`ds_shell_core` 里一个常量/函数说了算,
   调用点不许各自决定。
2. **一道机械闸**扫 `bin/` 下**所有** `subprocess` 创建点,逐个问"带没带这套标志",
   带不了的必须写进豁免名单并说明理由。形状照抄仓里已经在用的
   `tests/test_win_ctypes_decls.py`(**不造第二套机制**)。

## 不做

- 不把腿换成 `pythonw.exe` 起。`CREATE_NO_WINDOW` 是更窄的手术刀:
  进程在任务管理器里仍叫 `python.exe`(业主的真机清单 C1/C3 就是数这个名字的),
  而且 `taskkill` 那条兜底路**没有 pythonw 可换**,还是得靠标志。
- 不用 `DETACHED_PROCESS`(整个脱离控制台,副作用比要解决的问题大)。
