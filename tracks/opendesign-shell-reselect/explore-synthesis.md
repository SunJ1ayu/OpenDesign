## 逐条对账

### 一、他们指出、而我漏了的（这是 panel 的主要价值）

**① 4/4 腿都判定：我把"技术选型"当成了"验证问题"的解法。**
gpt-5.6 说得最直接：*"只换 C#，但仍然没有可反复运行的 Windows 环境，依旧是在盲飞；
这种情况下我反而不建议迁移。"* MiMo / DeepSeek / GLM 各自用不同的话说了同一件事。
**⇒ 接受，且它比腿说的更严重（见②）。**

**② 「我没法在 Windows 上跑一遍」不是物理法则，是一件我一直没修的基础设施。**
GLM 原话：*"这句话本身是 brief 最大的盲点——无论换不换壳都该先修它。"*
**我当场去核，两条实测（2026-08-25）**：

- 这个仓库是 **public** ⇒ GitHub Actions 的 `windows-latest` runner 对公开仓**免费**；
- 仓库里 **`.github/workflows` 一个文件都没有** —— 这一年**一次 CI 都没建过**。

再回头对这一年真正烧掉真机的三件事：**0.89 开机崩溃、0.90 窗口栏整块没画出来、
0.93 界面全白** —— **三件全都是"装上、打开、截一张图"就能看出来的**。
它们烧掉的不是"动画好不好看"这种只有人眼答得了的问题，而是**"界面还在不在"**。
> 这正是我自己在 native-frame 那一单记下的教训（真机清单 C 组五条全问退化，
> **没有一条问"界面还在不在"**），今天在**工具链层面**又犯了一遍同一个形状。

**③ 「自绘按钮」也许根本不必要**（gpt-5.6 提法最准：*"是产品要求，还是只要求视觉融合？"*）。
gpt-5.6 给出一条我完全没想到的第三条路：**保留系统的 caption controls，但把标题栏
"扩展"进客户区** —— 视觉上和无边框几乎一样，而最小化动画、Snap、DPI、多屏、
拖动全部**永远免费且永远正确**，因为它们仍归 Windows 所有。
**⇒ 接受为待定选项，但需要业主拍板（见最后一节）。**

### 二、我标了、他们没标的（沉默不是放行，仍然成立）

- **重写会丢掉"只有真机才教得会的知识"**（我的自述第 4 条）。四条腿没有一条认真算过
  `ds_shell.py` 里那一年份的真机修复被清零的代价。DeepSeek 只顺口提了一句
  "如果事后发现使用者根本不想要无边框，这步就白重了"。
- **业主是非程序员、且是唯一使用者**。GLM 的 PWA 方案要业主接受"启动变两段式、
  关窗≠退出要解释一次"；MiMo 的 Tauri 方案要业主承受一次完整的形态更换。
  这些成本**记在业主账上**，而四条腿都只算了开发者的账。

### 三、他们标了、但错了的（驳回，附证据）

**🔴 DeepSeek 与 GLM 各自独立提出：「无边框窗口这个需求找不到需求方，
可能只是开发者的审美，brief 没有任何证据」。——证伪。**

`git show 684574d`（0.89.0）的提交正文里记着业主 2026-08-16 的原话：

> 「左上角出现的 opendesign 标题和我们本来有的前端 opendesign 冲突了，
> 为什么不能不要外面那个框，只留我们原来的前端仅仅加上右上角的缩小放大和退出按钮」

需求方就是业主，一字不差。**两条腿独立命中同一个点、而且都错** ——
这正是「多腿共同错误」的形态，也是裁决权不能交给它们的理由。
> 但它们那半句仍成立：业主抱怨的是**标题重复**，而"整个框拿掉"是**我**选的解法。
> 这一半没被证伪，转入下面的产品问题。

**🟡 MiMo：「包体从 167MB 降到约 10MB 量级」——不成立。**
换壳只换外面那层，**164MB 的 Python 运行时原样还在**。gpt-5.6 明确写对了这一条
（*"包体不会突然变小"*）。MiMo 把"Tauri 成品 exe 几 MB"错当成了"整包几 MB"。

**🟡 DeepSeek：「Electron 自带 Chromium ⇒ 白屏那类环境故障整类消失」——证据不足。**
0.93 白屏的**根因至今未定案**（native-frame 那一单的明账）。把它归因成
"系统 WebView2 缺失/错版"是一个**未经证实的推论**——那次三行启动日志齐全、零报错，
"没装上/抛异常"整族已被排掉。**不许拿一个没定案的根因去论证任何方案。**

## 主 agent 的裁决

**决定一:外壳现在不换。pywebview 留着。**

理由不是"当初选得对"（当初那张表确实漏了最贵的一行），而是三条：
1. 0.96/0.97 刚把最小化动画拿回来，**痛点当下已经不痛**；
2. **换壳的收益在"没有 Windows 验证通道"之前基本买不到** —— 4/4 腿一致，
   gpt-5.6 甚至直接说"这种情况下我反而不建议迁移"；
3. 换壳要重写约 2,300 行，其中含一整年的真机修复，而**重写本身要烧掉好几轮真机往返**
   —— 花的正是这个项目最贵的那种货币（GLM 说得对：稀缺的不是工时，是验收往返）。

**决定二:真正要投的是「Windows 验证通道」,它独立于选型,而且应该先做。**

下一单（`opendesign-windows-ci`，未开工）：用 GitHub Actions 的 `windows-latest`
把「打包 → 装 → 启动 → 截图 → 存下来」跑成自动的。目标**不是**验"动画好不好看"
（那仍然只有业主答得了），而是**"界面还在不在"** —— 白屏、窗口栏没画出来、
开机崩溃这三类**曾经各烧掉一趟真机验收的故障，全部落在截图能答的范围内**。

**决定三(触发条件,写死):**

出现下面**任意一条**，就正式重开外壳选型，不再在 pywebview 上继续绕：

1. **再有一趟真机验收因为窗口层的问题白跑**；
2. pywebview 发布 7.0（WinUI3 后端）—— 那时要重新评估"留下"的代价；
3. Windows 验证通道建成之后，**窗口层仍然是唯一验不了的一层**。

重开时的**领跑候选是 gpt-5.6 那一版**（WinUI 3 + WebView2 + 原生扩展标题栏），
不是我原来那版（WinFormedge + 真 frameless）—— 因为前者把最贵的那部分
（非客户区行为）交还给了系统，而不是换一个语言继续自己实现它。

## 留给业主的一个产品问题(只有他能答)
