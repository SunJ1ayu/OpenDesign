## 方向

**改成 C#/.NET 的 WinUI 3 + WebView2 原生宿主；但不把 Python 应用重写成 C#。**

更关键的是：放弃真正的 `frameless` 窗口和网页自绘 caption buttons。改成“视觉上无边框”的原生扩展标题栏，让 Windows 保留对最小化、最大化、关闭、拖动、Snap 和系统动画的所有权。WinUI 3 已正式提供这条路径，系统 caption controls 仍由 Windows 处理。[Microsoft 标题栏文档](https://learn.microsoft.com/en-us/windows/apps/develop/title-bar?tabs=winui3)

职责这样切：

- WinUI 宿主拥有 HWND、标题栏、WebView2、任务栏、托盘、单实例激活、最外层 Python 进程和更新交接。单实例可直接走 Windows App SDK 的 `AppInstance`。[官方实例管理文档](https://learn.microsoft.com/en-us/windows/apps/develop/launch/multi-instance-apps)
- Python 继续拥有 ds-web、助手、MCP、文档、端口、配置、key 语义和内部进程监督。
- 原生宿主只拉起一个 headless Python 入口；Python 再管理自己的子进程。
- 首次填 key 仍是网页流程，不值得复制进 XAML。

这不是把 [ds_shell.py](/root/.openclaw/workspace/projects/design-studio/bin/ds_shell.py:372) 逐行翻译成 C#，而是重新划定 seam：**Python 不再碰 HWND，C# 不理解 nanobot 业务。**

## 核心赌注

赌的不是“C# 比 Python 稳”，而是：

> Windows 的非客户区和应用生命周期，应该交给 Windows 的一等框架，而不是穿过 Python → pythonnet → WinForms → ctypes/Win32 四层间接控制。

它最擅长解决的正是这里烧掉一年时间的问题：最小化动画、还原、Snap、DPI、多屏、焦点和句柄重建都处于同一个原生窗口模型中。WebView2 本身也是 WinUI 3 的正式控件，而非 pywebview 的后端实现细节。[官方 WebView2 文档](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/webview2)

## 要牺牲什么

- 增加 C#、Windows App SDK、XAML 和 Windows 构建链。
- 窗口右上角不再能完全由网页随意绘制；要接受 Windows 对 caption controls 的尺寸、命中区和部分视觉约束。
- Python 与宿主之间需要一个窄而明确、带版本的控制接口。
- 包体不会突然变小：164 MB Python 运行时仍然存在。
- WinUI 3 自身也有部署和版本兼容成本。

这里最值得牺牲的是“按钮必须由网页亲手画”。如果这一点不可让步，真正困难的非客户区控制就会被重新引回来，换框架的收益会大幅缩水。

## brief 的盲点

最大的盲点是：**你把技术选型当成了验证问题的解法。**

只换 C#，但仍然没有可反复运行的 Windows 环境，依旧是在盲飞；这种情况下我反而不建议迁移。原生宿主和 Windows 验证环境是不可拆开的一个方向。微软现在也明确给出了 WinUI UI 自动化以及 WebView2 接 Playwright 的测试路径。[官方测试建议](https://learn.microsoft.com/en-us/windows/apps/develop/testing/)

另外还没问清：

- “自绘按钮”是产品要求，还是只要求视觉融合。
- 两台机器具体是 Windows 10 还是 11、DPI、多屏和任务栏布局是什么。
- 更新的签名、失败回滚、数据版本兼容和更新中断由谁负责。
- WebView2 允许导航到哪些 origin，原生桥是否只向可信本地页面开放。
- 宿主崩溃、Python 崩溃、睡眠恢复和系统注销时，谁拥有最终生命周期。

星标、语言数量和包体是次要指标；真正缺失的比较行是“平台行为由谁负责、在哪里验证”。

## 最小第一步

建立一条带交互桌面、能留日志、截图和录像的 Windows 验证通道，然后只做一个 WinUI 3 垂直探针：

- 加载现有 `127.0.0.1` 页面；
- 使用原生扩展标题栏和系统 caption controls；
- 连续验证首帧不白、缩小/还原/最大化、边缘缩放、Snap、任务栏身份；
- 覆盖两台目标机器对应的 Windows/DPI 条件。

先不迁托盘、更新和 Python 监督。这个探针能稳定重复通过，才说明核心赌注成立；验证方式不应再是“发安装包给使用者口头回话”。
