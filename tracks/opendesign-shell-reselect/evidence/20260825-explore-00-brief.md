# 开放设计问题：这个桌面应用的"外壳"该由谁来当

用中文回答。只给方向，不写实现代码。

## 它是什么

OpenDesign：一个室内设计师**一个人**用的本地软件。界面本质是一个单页 Web 应用，由本机
Python 服务提供（`127.0.0.1:8766`）。助手大脑、文档处理、MCP 工具链全是 Python。

"外壳" = 把那个网页装进一个看起来像正常 Windows 软件的窗口里：无边框窗口 + 自绘的
最小化/最大化/关闭按钮、任务栏图标、托盘、单实例锁、后台进程看护、首次填 key、应用内更新。

## 已核实的事实（不是估计）

- **只跑 Windows**。使用者两台机器都是 Windows，没有 Mac/Linux 需求。
- 现在的外壳 = **pywebview 6.2.1 + pythonnet 3.0.5 + pystray 0.19.5**（Python 侧）。
- `bin/ds_shell.py` **1,234 行**，其中 **168 行**含 ctypes/Win32 符号（直接捅 Windows 底层）；
  `bin/ds_shell_core.py` 1,093 行。应用侧 `bin/ds_web.py` 2,569 行。
- 整包解开约 **167 MB**，其中约 **164 MB 是 Python 运行时**（免装版 embeddable + 119 个依赖）。
- GitHub 星标量级：Electron ≈ 12.3 万，Tauri ≈ 11 万，pywebview ≈ 6.0 千。
- pywebview 作者本人在 issue 里说：WinForms 那层对无边框窗口有已知限制，正解是换 WinUI3、
  要等还没发布的 7.0；旧的 win32 实现"太难维护，没打算复活"。

## 一年下来的实际代价（这条是这份 brief 的核心事实）

**开发和打包都在 Linux 上做，开发者无法在 Windows 上运行任何东西。**
唯一的验证路径 = 打一个安装包发给使用者，让他装上、肉眼看、口头回话。

于是"无边框窗口 + 最小化动画"这一件事，花掉了：**5 个版本（0.92→0.96）、2 趟白跑的真机
验收、1 次界面全白的事故**。这一层**没有任何自动化考卷验得了**（WinForms / WebView2 /
pythonnet / .NET 全是 Windows 独有），静态判据只能证明"手段没写错"，证明不了"用户看得到"。

## 当初选 pywebview 的理由（2026-08-13 记在案）

| 选项 | 当时的判词 |
|---|---|
| pywebview + pystray ✅ | 复用包内 Python，不引第二套运行时/工具链 |
| Electron | +150MB 和一整套 Node 工具链 |
| Tauri | 成品只有几 MB，但要 Rust 工具链，Linux→Windows 交叉编译很痛 |
| C# + WebView2 | exe 极小，但引入第二种语言和第二条构建链 |

那张表里**没有"窗口控制"这一行**，而后来烧掉的正是这一件事。
