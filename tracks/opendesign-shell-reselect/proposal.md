# Proposal: 桌面外壳选型重估（opendesign-shell-reselect）

> 立单时间 2026-08-25。**起因不是出了新故障，而是 08-24 的一次对话把当初选型的两个输入
> 证伪了，而那次重估当时只活在对话里、没进任何工件**（2026-08-25 我在仓里搜「重估」零命中）。
> 这一单存在的第一目的就是：**让它不再只活在对话里。**

## 当初的决定（2026-08-13，track opendesign-windows-installer 的 A1）

选 **pywebview + pystray**，理由四条，其中两条是拿来否掉 Electron / Tauri 的：

| 选项 | 当时的判词 |
|---|---|
| pywebview + pystray ✅ | 复用包内 Python，不引第二套运行时/工具链 |
| Electron | +150MB 和一整套 Node 工具链——我们正在为砍 32MB 费劲，方向相反 |
| Tauri | 成品只有几 MB，但要 Rust 工具链且从 Linux 交叉编译到 Windows 很痛 |
| C# + WebView2 | exe 极小，但引入第二种语言和第二条构建链 |

## 08-24 被证伪的两条

**① 「Electron +150MB 太大」——这个理由基本不成立了。**
现在的包解开约 167 MB，其中约 164 MB 就是 Python 运行时。我们一直背着一个和 Electron
同量级的运行时，只是它叫 Python 不叫 Node。当初那句「我们正为砍 32MB 费劲」，
是拿一个 164MB 的底子去嫌弃 150MB。

**② 那张表里根本没有「窗口控制」这一行——而那正是后来烧掉的地方。**
Electron / Tauri 自己实现窗口外壳，无边框 + 原生动画是开箱即用。这项成本在选型时看不见，
现在量出来了：**5 个版本（0.92→0.96）、2 趟白跑的真机验收、1 次界面全白的事故**，
全花在这一件事上。

## 今天仍然成立的

- **Tauri 那条是真的**：打包在 Linux 上做，交叉编译到 Windows 确实痛，而且是**每次发版
  都要付的长期税**，不是一次性工作量。
- **换壳不是「换个库」**：`ds_shell.py` 1,234 行 + `ds_shell_core.py` 1,093 行——托盘、
  单实例锁、后台进程看护、首次填 key、更新流程，以及一整年攒下的真机修复，
  得连同一整条新构建链重写一遍。
- **C# + WebView2 今天看更亮**：WinFormedge（C# + WinForms + WebView2，MIT）是目前找到的
  **唯一同栈做成了无边框 + 原生动画的实现**——即这条路有现成、能用的参考。

但它的两个输入后来都变了，而我一直没回头看，直到业主问「为什么当初选了 pywebview」。
