**Direction:** 
基于室内设计师业务动线的「多栏隔离状态机与输入时序全链路」黑盒测试设计。基于零代码黑盒测试台（`/tmp/aiwork-review-workspaces/subcursor.WvmfhDUu/repo/README.md`），将输入框从静态控件视为复合状态机（草稿态、输入法合成态、菜单展开态、流式思考/输出态、中断与结算态），围绕室内设计师的典型桌面交互场景展开端到端验证。

**Core bet:** 
输入框改版的核心风险不在于单点 UI 变化，而在于 Windows 桌面端输入法（IME）按键截获冲突、流式生成的毫秒级中断竞态（Race Condition）、以及三处聊天栏（首页/项目/待办）多任务并发下的状态错乱。通过全状态机路径覆盖，能在代码开发前锁定 90% 以上会导致用户丢草稿、误触发指令、界面卡死及账目状态混淆的恶性体验缺陷。

**How it works:** 
1. 建立「按键/事件输入流 -> 菜单/前缀处理 -> 流式/后台任务 -> 终止/渲染」的全链路状态机测试模型；
2. 全面覆盖主流程、失败路径（各种极限时序停止）、组合场景（三栏并发操作、带图选技能、输入法混合打字）与回归影响（原有拖图/粘贴/历史回放）；
3. 交付结构化用例表、探索式测试 Charter 及阻碍开发的 PO 决策清单。

**Best at:** 
快速截获 Windows 平台特有的 IME 候选框与悬浮菜单事件冲突、窄侧边栏界面文字溢出、打断生成时的前后端状态脱节。

**Sacrifices:** 
不做白盒代码插桩与底层 IPC 通讯监听，不做强行修改配置文件或破坏环境的「砸墙」破坏性测试，所有测试均以室内设计师视角的桌面交互为基准。

**Blind spots in the brief:** 
1. **项目助手/待办助手占位文字**：题面只规定首页占位字改为「聊设计、找参考;输入 / 选技能」，未说明原本为「问这个项目,或「记一下…」」的项目助手占位字如何统一；
2. **问候语时间刻度区间**：早/中/下/晚/夜深了未给出确切的小时界限；跨时间点无操作时是否自动刷新未定义；
3. **不可逆动作停止后的认知混淆**：若正在执行记账时停止，后台记账已完成但前端只显「已停止」，设计师容易误以为未记上而重复提交；
4. **错误提示非原话时的确切文案**：后台改写的固定英文不再标「原文」，具体改为标什么未指定；
5. **多行草稿下的 `/` 与前缀替换规则**：已有换行时在第二行打 `/` 是否触发；已有内容时选技能是插入全文首部还是当前行首。

**Smallest first step:** 
冻结「中文输入法按键映射矩阵」与「0ms-流式中-流式末按停止的时序竞态矩阵」，并立即交由产品负责人裁定 5 个需求盲点。

## 1. 用户故事 + 验收标准 (User Stories & Acceptance Criteria)

### US-01: 「+」菜单选择技能与添加图片
- **As an** 室内设计师，
- **I want to** 点击输入框左下角的「+」菜单选择图片上传或预置的 3 项业务技能（记一下 / 整理文件夹 / 找参考图），
- **So that** 我无需手动输入复杂固定句式或在界面上到处找功能入口。

- **AC-01.1 (展开菜单)**
  - **Given** 输入框处于正常可输入状态，
  - **When** 用户左键点击「+」按钮，
  - **Then** 弹出下拉菜单，第一项为「图片（也可拖进来 / Ctrl+V）」，下方为「技能」组（记一下、整理文件夹、找参考图），且原「✎ 记一下」按钮不再存在。
- **AC-01.2 (点选技能追加前缀与光标)**
  - **Given** 输入框中为空或已有普通草稿文字（如「厨房改开放式」），
  - **When** 用户在「+」菜单中点击「记一下」，
  - **Then** 菜单关闭，输入框开头补上「记一下:」，原有文字保留在后面（显示为「记一下:厨房改开放式」），且光标自动定位在文本最后，支持直接打字。
- **AC-01.3 (前缀互斥替换)**
  - **Given** 输入框中已有技能开头（例如「帮我扫描整理这个文件夹:D:\图纸」），
  - **When** 用户在「+」菜单中切换点击「找参考图」，
  - **Then** 输入框原有前缀被完整替换为「找参考图:」，保留后续内容（变为「找参考图:D:\图纸」），不会出现「找参考图:帮我扫描整理这个文件夹:」叠加情况。
- **AC-01.4 (图片选项交互)**
  - **Given** 「+」菜单处于展开状态，
  - **When** 用户点击「图片」，
  - **Then** 唤起 Windows 系统的标准选图文件对话框，选中图片后成功挂载到输入框上方预览区。

### US-02: 输入框打 `/` 快速检索与选择技能
- **As an** 习惯键盘盲打的设计师，
- **I want to** 在输入框打 `/` 呼出技能列表并通过中文检索、方向键和回车直接应用，
- **So that** 我双手不离开键盘就能迅速切换对话意图。

- **AC-02.1 (触发与关闭)**
  - **Given** 输入框内容为空或光标位于行首，
  - **When** 用户键入 `/` 且后面未输入空格，
  - **Then** 在输入框上方立即弹出包含 3 项技能的浮层列表，支持键盘 `↑` `↓` 移动高亮；按 `Esc` 键可关闭浮层，保留输入的 `/`。
- **AC-02.2 (拼音/文字即时过滤)**
  - **Given** 技能浮层已弹出，
  - **When** 用户接着输入「参考」，形成「/参考」，
  - **Then** 列表仅过滤保留「找参考图」一项；若输入无匹配字（如「/水电」），浮层自动隐去，此时按 `Enter` 视为普通消息发送或输入，不报错。
- **AC-02.3 (确认使用技能)**
  - **Given** 技能浮层高亮选中了某技能（如「整理文件夹」），
  - **When** 用户按下 `Enter` 或 `Tab` 键，
  - **Then** 刚才输入的「/xxx」被整段替换为「帮我扫描整理这个文件夹:」，浮层关闭，光标停留在冒号之后。
- **AC-02.4 (中文输入法无冲突)**
  - **Given** 用户开启微软拼音或搜狗输入法在 `/` 后打拼音（如打「cankao」），
  - **When** 用户按数字键或空格选字时，
  - **Then** 输入法完成汉字上屏，技能浮层根据上屏汉字做过滤，输入法选词的 `Enter` 不会误触技能选择或消息发送。

### US-03: 模型按钮展示「厂商短名 · 模型名」
- **As an** 配置了多家 AI 服务的设计师，
- **I want to** 在模型切换按钮上清晰看到当前是由哪家厂商与具体哪个模型在提供服务，
- **So that** 我一眼便知扣的是哪张卡/哪个套餐的钱，以及当前模型是否擅长当前任务。

- **AC-03.1 (官方供应商短名提取)**
  - **Given** 用户在设置中选择了内置供应商模型，
  - **When** 停留在聊天界面查看模型按钮，
  - **Then** 按钮展示格式严格为「厂商短名 · 模型名」，括号及括号内说明被去除。例如：`MiMo(小米)` 配合 `mimo-v2.5` 显示为 `MiMo · mimo-v2.5`；`GLM 套餐(Coding Plan)` 配合 `glm-5.1` 显示为 `GLM 套餐 · glm-5.1`；`DeepSeek 官方` 配合 `deepseek-v4-flash` 显示为 `DeepSeek 官方 · deepseek-v4-flash`。
- **AC-03.2 (自建供应商全名原样展示)**
  - **Given** 用户在设置中通过「添加供应商」自定义了名称（例如「工作室月付专线」），
  - **When** 选中该供应商下的模型（如 `custom-3.5`），
  - **Then** 按钮完整显示为 `工作室月付专线 · custom-3.5`。
- **AC-03.3 (窄侧栏截断与提示)**
  - **Given** 在项目助手或待办页面的窄侧边栏中，按钮文本由于超长无法完整展示，
  - **When** 界面渲染时，
  - **Then** 文字优雅省略显示（如 `工作室月付... · cus...`），鼠标悬停（hover）展示完整名称的 Tooltip，且绝对不能把右侧的发送/停止按钮挤出可视区域。

### US-04: 流式生成中的「■ 停止」控制与状态反馈
- **As an** 正在提问的设计师，
- **I want to** 在模型跑偏、长篇大论或耗时过长时一键中止回复，
- **So that** 能够即刻释放界面并继续追问，不浪费时间与 Token。

- **AC-04.1 (按钮状态转换与即时中止)**
  - **Given** 用户点击发送 `↑`，模型进入处理中（无论是在「正在思考」动画阶段，还是文字正在一段段输出），
  - **When** 按钮变成「■ 停止」且被用户点击，
  - **Then** 思考动画或文字流立刻截断停下，按钮即刻恢复为 `↑` 图标，输入框解除锁定恢复可输入状态。
- **AC-04.2 (停滞内容与提示气泡)**
  - **Given** 回复生成了一半时被用户点击「■ 停止」，
  - **When** 回复停止，
  - **Then** 已经输出的文字原样保留在聊天流中，下方紧跟一行灰色小字「已停止」；严禁在界面中产生诸如 `/stop` 的指令气泡或后台英文提示。
- **AC-04.3 (刷新与重开持久化)**
  - **Given** 某段对话曾被手动点击「■ 停止」，
  - **When** 用户切换到其他项目再切回，或完全重启 OpenDesign 客户端，
  - **Then** 历史消息中该条回答截断处仍清晰标注中文「已停止」，状态不丢失、不恢复成加载态。
- **AC-04.4 (后台已有动作的原样保留说明)**
  - **Given** 助手正在执行「记一下」落账或「整理文件」动作时用户点击停止，
  - **When** 停止生效，
  - **Then** 界面仅停止后续语言汇报并显示「已停止」，已经完成的账本记录或文件操作不受逆向破坏。

### US-05: 首页问候语按时间变
- **As an** 打开 OpenDesign 的设计师，
- **I want to** 在不同时段看到贴合时令作息的问候文案，
- **So that** 软件显得温和、人性化。

- **AC-05.1 (时段文案映射)**
  - **Given** 首页处于新建空白对话状态，
  - **When** 本地系统时间处于不同时段时，
  - **Then** 问候大字呈现对应的文案：
    - 早晨时段显示：`早上好，今天想聊点什么?`
    - 中午时段显示：`中午好，今天想聊点什么?`
    - 下午时段显示：`下午好，今天想聊点什么?`
    - 晚上时段显示：`晚上好，今天想聊点什么?`
    - 深夜时段显示：`夜深了，今天想聊点什么?`
- **AC-05.2 (输入卡占位符)**
  - **Given** 首页输入卡处于未输入状态，
  - **When** 观察文字框，
  - **Then** 占位符清晰显示为「聊设计、找参考;输入 / 选技能」。

### US-06: 错误提示小字与后台系统通知汉化（两处小修）
- **As an** 遇到网络或调用异常的设计师，
- **I want to** 看到清晰自然的中文错误描述与系统通知，
- **So that** 我不会被生硬的英文或误导性的「原文」标签困扰。

- **AC-06.1 (非厂商原话的标注替换)**
  - **Given** 模型调用发生错误且后台返回的是经过系统加工的固定说明（例如欠费、余额不足、无可用通道），
  - **When** 气泡展示粉色中文出错说明时，
  - **Then** 下方补充小字不再标记「原文:…」，而是标记为「详情:…」（或产品裁定的中文非原话标签）。
- **AC-06.2 (厂商真实原话保留「原文」)**
  - **Given** 模型 API 直接抛出厂商原始报错（例如 HTTP 500 JSON raw message），
  - **When** 错误气泡渲染时，
  - **Then** 小字继续标为「原文: {原始报文}」。
- **AC-06.3 (后台系统提示消息全面汉化)**
  - **Given** 触发了后台任务停止或状态变动，
  - **When** 消息回显到聊天流，
  - **Then** 严禁出现英文系统消息，必须全量显示为中文（如：原 `Stopped 1 task(s).` 变为 `已停止 1 项任务。`；原 `No active task to stop.` 变为 `暂无运行中的任务可停止。`；原 `Background task completed.` 变为 `后台任务已完成。`）。

## 3. 探索式测试任务 (Exploratory Testing Charters)

### 任务 1: Windows 中文输入法全场景「按键争用与草稿防丢」极限探索
- **任务目标**：排查室内设计师在全键盘盲打时，第三方输入法（微软拼音、搜狗输入法、微信输入法）与 `/` 浮层按键捕获的底层争用问题。
- **重点关注**：
  - 在拼音打到一半（未按空格上屏、处于 Composition 状态）时强行按 `Esc`、`Backspace` 或鼠标点击它处；
  - 极快手速输入 `/cankao` 连续按回车，是否会发生拼音未完成就误发空指令；
  - 复制带格式文字、包含空格/换行的图纸路径直接粘贴到 `/` 后面，浮层的响应与过滤鲁棒性；
  - 使用撤销键（`Ctrl+Z`）能否正确撤销技能前缀替换，而不损坏后续已打好的设计需求。

### 任务 2: 真实设计场景下的「三栏并发多任务与急停」混沌测试
- **任务目标**：模拟设计师真实高压工作流——同时在「项目助手」记改动、在「首页」让 AI 整理几百兆图纸目录、在「待办页」查材料参考图。
- **重点关注**：
  - 三个栏位各自发起长时间任务，在不同阶段交替点击「■ 停止」，观察主进程与各 Webview 之间是否发生 Token/任务句柄串扰；
  - 验证停止后，项目助手里的账本是否被脏写，以及被停止整理的文件夹是否留下一半被锁定的临时状态；
  - 频繁在三个侧栏间切走切回，检查每个栏位的输入框草稿、图片附件及停止状态是否完整保留。

### 任务 3: 模型流式输出与断网时钟的「临界毫秒级竞争」对抗测试
- **任务目标**：探测模型生命周期各个毫秒级瞬态下的停止健壮性。
- **重点关注**：
  - **0ms 发射即停**：在按下发送的一瞬间（网络握手包刚发出、界面刚由 `↑` 变为 `■` 的首帧）立即点击停止；
  - **思考转文字临界**：在「正在思考」圆圈消退、第一个字符刚刚落盘界面的瞬间点击停止；
  - **网络中断叠加**：拔掉网线/断开 Wi-Fi 的同一秒按下停止，验证界面是优先展示「已停止」还是抛出粉色错误，且按钮必须保证恢复为 `↑`，绝不能出现永久 Loading 死锁。

### 任务 4: 桌面多 DPI 缩放与极致窄栏排版视觉破坏测试
- **任务目标**：室内设计师常用 4K 高分屏或笔记本外接显示器（常见 125%、150% 系统缩放），检验全新模型长短名按钮及「+」菜单的物理排版。
- **重点关注**：
  - 自定义一个长达 20 个汉字的供应商名称，配合一个带长版本号的模型名，在项目助手窄栏中拉动窗口宽度；
  - 检验「+」菜单是否会被窗口边缘遮挡或倒翻至可视区域外；
  - 检验发送图标 `↑` 和停止图标 `■` 在系统大字体/高缩放下是否发生像素级错位或换行下陷。

## 4. 需要产品负责人 (PO) 拍板的疑问

1. **项目助手与待办助手的输入框占位文案定义**：
   - 首页占位文字已明确为「聊设计、找参考;输入 / 选技能」。但项目助手原为「问这个项目,或「记一下…」」，待办助手亦有上下文。这两处的占位文字本次是否同步调整为「问这个项目;输入 / 选技能」与「问待办事项;输入 / 选技能」？
2. **五段问候语的具体时间阈值划分**：
   - 目前缺少时间切分标准，建议采用设计师作息标准，需 PO 确认界限：
     - `早上好`：06:00 ~ 11:00
     - `中午好`：11:00 ~ 13:30
     - `下午好`：13:30 ~ 18:30
     - `晚上好`：18:30 ~ 23:30
     - `夜深了`：23:30 ~ 次日 06:00
   - *跨时段停留处理*：若设计师在 11:29 打开首页挂起，至 11:31 回到窗口，文案是否即时自动刷新？
3. **非厂商原话的出错提示小字统一用词**：
   - 题面指出后台封装的固定英文报错「不再标『原文』，改标别的说法」。请 PO 明确该说法是采用「详情:」还是「系统提示:」？
4. **后台不可逆操作（记账/挪文件）被中途停止时的体验闭环**：
   - 题面明确「停的那一刻后台动作可能已经做完，只是助手不再汇报」。但在室内设计业务中，「记一下」落账如果已经写入后台账本，但聊天窗口只冷冰冰写着「已停止」，设计师很容易认为该条改动没有生效而再次补录，导致账目重复。前端在检测到动作实际已落库时，灰色小字是否应更精准地提示为「已停止汇报（后台操作已记入变更账本）」？
5. **多行草稿中的 `/` 指令触发界定**：
   - 当设计师在输入框中粘贴了一大段带换行的施工量说明，并在第 3 行行首键入 `/` 时，是否应当弹出技能菜单？如果弹出并确认了技能，是将前缀追加到全文最顶部，还是当前光标所在行的行首？建议规则为：**仅当整篇文本以 `/` 开头时才触发**，避免多行编辑时的按键干扰。
