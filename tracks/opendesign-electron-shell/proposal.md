# Proposal: opendesign-electron-shell

- Date: 2026-09-21
- Status: open

## Goal

把 OpenDesign 的桌面窗口从 pywebview 换成 Electron,窗口与三按钮照 ZCode 的做法;后台(网关 nanobot、工作台 ds-web、
MCP 工具)与界面内容不变。

> ⚠️ **范围待业主重新拍板(2026-09-21 夜)**:业主确认过的转述是「窗口、托盘、安装包、自动更新四样全换成 ZCode 那一套」
> + 「换壳那一版手动装一次(A)」。独立方案挑战两家(不同家族、互不知情)**一致**建议只换窗口+托盘、
> 安装包与自动更新留现有那套,且主 agent 逐条核实后同意(见 design.md「独立挑战与核实」)。
> 这触碰业主已确认的目标 ⇒ 按 panel 4c ③ 回去问他,**他答之前不写实现判据、不动产品代码**。

## Motivation

- 窗口层这一年白跑业主真机三次(0.89 开机崩 / 0.90 窗口栏没画出来 / 0.93 打开全白),
  「pywebview 注入时机」栽四次;缩放边/贴边/动画靠 ctypes 手补(`bin/ds_shell.py` `WindowApi`),
  那一层 Linux 上一行都跑不到。
- 08-25 裁决「不换」时写死的重开条件③已成立:Windows 云验证通道(`windows-package-probe` /
  `windows-update-e2e`)建成之后,窗口层仍是唯一只有业主验得了的一层。
- 业主 09-21 拍板换。

## 真问题(第一性)

- 用户原话:
  - 「我觉得我们得换 Electron,你先看看我们的 opendesign 项目怎么迁移来一个 plan」
  - 「我觉得都一起换了吧,参考一下 zcode 这一段前端代码」
  - (agent 转述「窗口、托盘、安装包、自动更新全部换成 ZCode 那一套」后)「可以」
  - (A 手动装一次 / B 旧版自动更新过去)「可以就选a」
  - 旁证:08-16「只留我们原来的前端仅仅加上右上角的缩小放大和退出按钮」;08-25「不一定我们自己画」;
    08-30「还是按正常成熟的软件工程做吧,安装包大不是问题」。
- 真正要解决的是:窗口这一层别再让业主白装、别再靠手补,改成业界成熟做法;以后改窗口/更新相关的东西,
  在他装之前就能被机器看见对不对。
- 我在这中间翻译了什么:「都一起换」→ 四样全换(他答了「可以」,但他不是程序员);
  「参考 zcode 这一段前端代码」→ 三个按钮照 ZCode 自己画(Windows `frame:false` + 前端按钮)。
- 用户可观察的成功:装上新版,打开能看见界面;缩小放大有动画、能贴边、能拖边缘;关窗进托盘、托盘退出、再双击叫回;
  他的档案、key、对话都在;之后的版本自动更新照常(打开软件不被更新卡住)。

## Scope

- in(确定的):Electron 主进程 + preload;窗口与三按钮照 ZCode;前端窗口栏与启动上报改接 preload;
  外壳 Python 侧去掉窗口/托盘,留下管后台那一半;云 Windows 探路包与回归。
- 待拍板:安装包与自动更新换不换(见上);换壳那一版怎么上业主的机器。
- 具体架构在 design.md。

## Non-goals

- 界面内容、后台服务、助手行为不改。
- (若维持四样全换)不做旧版 → 新版的自动迁移(业主选 A:手动装一次)。
- 不上 macOS/Linux 桌面包(Linux 开发机仍用浏览器开 ds-web)。
- 不做代码签名(要花钱,另议)。

## 验收边界与轮次预算

- 这一单承诺:① 新安装包在干净的云 Windows 上能装、能打开、界面出来、三按钮与托盘行为正确、退出不留后台进程;
  ② 业主按说明卸旧装新后,资料/key/档案都在;③ 从换壳版起的下一版能经自动更新装上(云 Windows 实测);
  ④ git-pull 与 Linux 浏览器形态不坏;⑤ 业主真机 A0「界面出来了吗」。
- 不承诺:动画手感(只有业主答得了,但要他看一眼);测试挡不住任意未来错误实现。
- 实质评审上限:2 轮(impact=high,每轮两个家族)。**每轮派发前先跑 `track preflight opendesign-electron-shell`。**
