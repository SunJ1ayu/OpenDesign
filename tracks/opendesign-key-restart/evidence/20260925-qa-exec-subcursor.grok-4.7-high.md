两份设计里的 P0 已经列出来了。接下来对照 Windows 探针和端到端跑次的原文，看每条实际覆盖到哪。
Direction: 请业主在自己的 Windows 安装包上，眼睛看着聊天页，把「存另一家、先不换模型就再发一句」和「把正在用的 key 改成错的再发一句」走完。

Core bet: 云端探针已经证明请求打到哪一家、带哪把 key；这一单还没被眼睛看过的，是那句提示和右下角按钮。probe-5 的 live 组全程是同一条 websocket、网关进程一直是 2268，fresh 组约 2 秒把聊天服务拉起来并发出了第一句。浏览器断言也对上了任务里的三种提示。缺的是真窗口里这几句话有没有照实出现、按钮有没有一直在。

How it works: 已能跟小米聊天时，只在设置里保存 DeepSeek 的 key，先不换模型。画面上应是「已保存，马上可用：在聊天框右下角就能换到这家的模型。」按钮名字仍是小米，下一句仍打到小米。再把正在用的小米 key 改成一把错的，提示还在时就发一句：这一句应失败，按钮仍停在小米。这两步都用业主自己的安装包，看提示原文和按钮，不再看进程号。

Best at: 补上两份设计里最贵、又没人走到的 P0：存别家不会把当前这句改走，以及错 key 不会静默继续用旧 key。probe-5 只做过「好 key + 先切换再发送」（DeepSeek …6789ab，换回小米后是 …543210，不是原来的 …456789）。

Sacrifices: 自动更新、定时任务、流式写到一半去存 key、全新安装只加自定义供应商、故意让聊天服务起不来，都不放进这一步。修之前的 probe-3 / probe-4（240 秒起不来）不能当作修好的包的失败路径。

Blind spots in the brief: 全量记录 `20260925T014105Z-01-run-all.txt` 第 30 行是 e2e 42 通过 / 0 失败 / 2 跳过，跳过的是要真网关的 `new_chat.e2e.mjs` 和 `project-thread.e2e.mjs`，与本单无关；同一份记录第 32–34 行因为「有跳过」把总跑标成未完成，不能当成这单的界面失败。Windows 日志只记回包是 `live` 还是 `requested`，没有提示原文，也没有按钮截图。浏览器里的聊天服务是替身，能看提示和菜单，不能证明下一句真的扣到哪家。

Smallest first step: 在一台已经能跟小米聊天的 Windows 安装包上，打开设置保存一把 DeepSeek 的 key，不要点换模型，读完那句提示，立刻再发一句，确认按钮名字仍是小米、这一句仍是小米在答。

## 2. 缺陷

无。

已跑到的三句提示和 Windows 上的请求对得上，没有看到说假话或步骤走不通：

- 存另一家：浏览器 A3 要求提示里有「右下角」，并且没有「重启」「下一句」「稍等」。probe-5 第 9 行回包是 `live`，第 18 行进程仍是 2268。
- 改正在用的那家：浏览器 K1「改正在用的那家的 key:提示说下一句就用新 key,不提重启」。probe-5 第 15–16 行下一句小米带的是新 key …543210。
- 聊天服务没在跑：浏览器 G1「提示正在准备聊天服务,不提重启」。probe-5 第 24–28 行回包 `requested`，随后网关起来，第一句打到小米。

源码老装法那句「请手动重启」没有出现在这两份 e2e 的 `check` 里，也没有对应的失败记录。

## 3. 需要业主在真机上亲自走的几步

1. 已经能跟小米聊天时，打开设置，只给 DeepSeek 粘贴一把 key 并保存。看提示是不是「已保存，马上可用：在聊天框右下角就能换到这家的模型。」先别换模型，看右下角按钮还在不在、名字是不是仍是小米，再发一句，确认还是小米在答，页面上没有「连接不上」。
2. 接着在聊天框右下角换成 DeepSeek 的一个模型再发一句，看按钮名字有没有变成这个模型，这一句是不是 DeepSeek 在答。
3. 把正在用的小米 key 改成一把明显错的，提示还在时马上发一句。这一句应失败，按钮仍停在小米，失败文字里看不到完整 key。
4. 把小米 key 改回一把能用的，提示还在时马上再发一句，确认能收到回复，按钮名字不变，也不用退出重开。
5. 找一台刚装好、一把 key 都没有的 Windows 安装包，给小米保存第一把 key，人留在软件里等。看提示是不是「已保存，正在准备聊天服务，稍等片刻即可开始对话；若稍后仍连不上，请退出 OpenDesign 再打开。」几秒后应自己能发一句，不用退出再打开。
