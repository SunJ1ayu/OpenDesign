# Proposal: 静默安装撞见非空目录应当拒装,而不是把业主的东西留给卸载去删

## 事实(实测,不是推理)

云机器 run 32811517481(`.github/workflows/windows-nonempty-probe.yml`,
判读规则写死在脚本头部、看结果之前):

```
/S /D=一个非空目录  →  退出码 0、40s **装进去了**,没有任何拦截
装完                →  业主原有的文件还在、内容没变
静默卸载            →  **业主的文件没了**(RMDir /r 整棵删)
```

## 为什么会这样

`CheckDirEmpty` 挂在 MUI 目录页的 **leave 回调**上(`installer/OpenDesign.nsi:82`),
NSIS 在 `/S` 下跳过所有页面 ⇒ **这个函数根本不会被调用**。
而 `/SD` 只在静默下起作用 ⇒ 它那句 `/SD IDCANCEL` 在唯一生效的模式里是**惰性**的。

后果链是 `CheckDirEmpty` 自己的注释早就写明的:
「G6 那个哨兵挡不住这一种 —— 装完之后哨兵文件就在那儿了,它会说"是我们的"」
⇒ 卸载段 `IfFileExists $INSTDIR\ds\bin\ds_shell.py` 认门通过 ⇒ `RMDir /r "$INSTDIR"`。

## 业主现在受影响吗:不受

他是**双击装**的 ⇒ 走目录页 ⇒ 那个框会弹 ⇒ 拦得住。
撞得上的是**无人值守安装**:我们自己的 CI、以及将来任何批量部署。
这是**存量**口子(0.98 之前就是这样),不是 `opendesign-fresh-install-fix` 引入的。

## 打算怎么修(待 design 定案)

在 `/S` 路径上补一次同样的检查(`${If} ${Silent}`),撞见"非空且没有哨兵"就
**拒装并给非零退出码** —— 无人值守时不许替业主承担他没同意的数据风险。
> 注意别把我们自己的 CI 探针弄红:全新 runner 上目标目录不存在 ⇒ 空 ⇒ 放行;
> 覆盖安装有哨兵 ⇒ 放行。

## 收口标准

**不是本机判据绿**。要发一版,再跑一次 `windows-nonempty-probe`,
看到 PHASE 3 变成"拒装 + 非零退出码"、PHASE 7 变成"业主的文件还在"才算数。

## 由来

track `opendesign-fresh-install-fix` 的 panel(2026-08-25):两条腿在
"CheckDirEmpty 在 /S 下可不可达"上给了**相反答案**,而三方(含我派发前的自审)
全是读源码推的、没有一方量过 —— 于是造了这支探针去量。
