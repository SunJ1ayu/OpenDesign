# Design: opendesign-due-picker

- Change: opendesign-due-picker
- Status: 已实现(0.56/0.57);工件 07-29 回填

> Panel hook — 仅当这是真·开放架构分叉时先跑 `panel-explore`。**本单没跑,也不该跑**:
> 用户已经把形态拍死了(「出现一个日历比较好,随便点就行了」),不是开放分叉,
> 只剩"弹在哪"这一个有唯一正确答案的问题。

## Approach

**位置逻辑与渲染分离**,这是本单唯一真正的设计决定:

- `web/src/duePicker.ts` —— 纯函数 `popoverPosition(anchor, size, viewport, gap)`,
  不碰 DOM。**抽出来的理由**:待办列表里**总有条目贴着屏幕底边**,翻转/夹取写在组件里
  就只能靠 e2e 一格一格试边界;抽成纯函数才能把边界一次列全(oracle 8 例)。
- `web/src/DuePicker.tsx` —— 浮层本体,只负责量尺寸、贴样式。

三个刻意决定:

1. **createPortal 挂到 `document.body`**。待办行与变更行都在 `overflow:auto` 容器里,
   浮层留在原地会被祖先裁掉 —— 跟"设了 padding 却被别的规则盖掉"是同一类病:
   **你以为它在,它其实被切了一半。**
2. **点一天就存、就关,不设"确定"按钮**。用户原话「随便点就行了」。
   反悔靠 Esc / 点外面(**都不写入**)与「清除」。
3. **两处共用同一个组件**(待办页 + 工作区变更栏)。用户要求「同一个东西一个交互」,
   所以工作区那个原生 `<input type=date>` 及其 CSS **删干净**,不留第二套 ——
   判据 G 段就是钉这个。

## Key trade-offs / risks

- **滚动即关闭**(不硬跟锚点)。风险:手感可能生硬。**e2e 接不住,只能真机看。**
- **窄视口下左边界优先**:日期数字在左半边,宁可右边露不全,也不让左半边跑出屏幕。
- **与右栏月历刻意不同款**:那个是"筛选"(点日期=只看那天到期的),这个是"修改"。
  同一个东西两个意思是乱的开始 → 这个有白底浮层+投影,那个嵌在栏里。

## Alternatives considered

- **「今天/明天/本周六」词快捷键**(主 agent 原提案:用户嘴里说的是"周六"不是"2026-08-01")
  → **用户明确否掉,选了纯日历**。**用户的选择覆盖主 agent 的偏好。**
- **复用右栏那个现成月历当编辑器** → 否。①你点左边、反应在右边,眼睛要跳,容易搞不清
  在给谁设;②那个月历现在的作用是**筛选**,一个控件两个意思。而且工作区没有右栏,
  那边还得另做一套 —— 直接违反"同一个东西一个交互"。
- **每次打开页面现调 LLM 概括**(这是 T4 的备选,记在这里免得丢)→ 否,太贵太慢。

## Test strategy (oracle)

- `tests/test_due_picker.mjs`(8 例,纯逻辑):边界一次列全。
- `tests/e2e/duedate_picker.e2e.mjs`(7 段,真 chromium + 真 ds_web)。

**分工刻意**:**翻不翻转是实现细节**,由纯逻辑 oracle 钉;e2e 只钉用户看得见的
「不管点哪一条,日历都得整个看得见」。**两边不重复编码同一个边界。**

## 这个 oracle 能被什么骗过?

**当时写下的答案 + 事后被验证的部分:**

1. **字形缺失**。断言只查元素在不在、位置对不对,**查不出那个字渲染成了豆腐块**。
   → **实际发生了**:空态触发键的 📅 在截图里就是 □。**截图抓到的,不是断言抓到的。**
2. **过渡动画中途值**。"压暗了"若写成 `opacity < 1`,量到的可能是动画中途的数
   → **实际发生了**:量到 0.92(终值是 0.45)。等于几乎看不出的压暗也能过。
   已改成等过渡稳定再钉 ≤0.7。**同一个根因第 N 次:数字对、结果错。**
3. **滚动手感**。e2e 不滚动 → "滚动即关闭"这个取舍好不好,判据完全接不住,**只能真机**。
4. **只验一种视口**(1440×900)。翻转后好不好看没人验。
