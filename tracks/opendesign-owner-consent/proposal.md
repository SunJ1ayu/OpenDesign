# Proposal: opendesign-owner-consent(危险动作要不要问业主 —— 做成业主自己的开关)

- Date: 2026-08-08
- 触发:anydoc 那单(0.80)当时定的是「先不做授权,做完单独问业主」。08-08 问了,
  业主的回答是:**「可以和其他危险操作一样,让用户选择弹或者都不弹,就像 Claude Code
  和 Codex 这些 agent 一样。」** —— 即不要我替他一次性拍板,要一个他自己能调的开关。

## 先说一条比"要不要弹"更要紧的:一条安全不变量已经过期

`bin/ds_tools.py` `set_workspace` 上方的注释(来自 design.md B5)写着:

> 此 root 只 scope **只读文件视图**(ds_web 文件/图墙 + open-folder),
> **不拓宽 LLM 能读并上云的内容**。

**0.80 之后这句不再成立**(2026-08-08 顺代码核对):

```
read_document / list_documents          bin/ds_documents.py:314 / 187
  → _project_docs_dir(project)          bin/ds_documents.py:60
  → ds_workspace.load_config(ds_root)   ← 读的就是 set_workspace 写的 workspace.json
  → ds_workspace.project_dir(cfg, key)  bin/ds_workspace.py:117
      ② 扫描新根下的文件夹名 == key
      ③ key 按 `-` 切 token,全部 token 为文件夹名子串且唯一命中也算
```

⇒ 助手改完根,**能按名字/模糊 token 命中新根下任意"像项目夹"的目录,读走里面
`01-资料` 的文档**,内容进对话即上云(MiMo API)。而 `set_workspace` 今天**零确认**。

完整链条:**一份被读的文档里藏一句话 → 助手改工作区根 → 读走工作区外的业主文档 → 上云。**
这不是理论推演,三步都是现成能力。写那条注释的时候它是真的;是 0.80 那单加了读文档能力
**没回头看它** —— [[记忆:把事实复制到第二个地方,只更新其中一个]]的又一例,
只不过这次第二个地方是**一条安全论证**。

## 提议

1. **业主同意闸**:`set_workspace` / `bind_project` 这类"扩大助手能看到的范围"的动作,
   执行前要业主点头。**点头这件事发生在网页上,不在聊天里**
   —— 照抄仓里已有的 `ds-approve` 铁律:「清单由工具从 plan json 渲染打印,不经模型转述」、
   「聊天里说"确认"不算数」。
2. **业主自己能调**(业主原话的核心):设置里选「每次问我」/「不用问」,默认**问**。
3. **开关本身必须是助手够不到的**:否则注入只要先把开关关掉,整道闸就是摆设。
   ⇒ 开关不能写进 `workspace.json`(`set_workspace` 自己就写那个文件),
   要单独一份、且**没有任何 MCP 工具能写它**;只能由业主在网页设置页改
   (ds_web 的 HTTP 口是人在浏览器操作,不是模型)。
4. **顺手修那条过期的安全论证**(代码注释 + design.md B5),并留下"谁改了读面就要回来重看
   这条"的钩子 —— 光修一句话,下次照样会过期。

## 不做(本单范围外)

- 不动 `ds_organize` 那条搬文件的线:它已经有更强的闸(`.approved` 只有人在终端能造,
  模型无工具可造),**不要用新机制去替换它**,那是把一道物理闸换成一道软闸。
- 不做"记住这次选择/本次会话不再问"(Claude Code 那种 per-tool 记忆)。
  先上两档,用几天看它到底弹不弹得起来,再谈。
- 不改 MiMo 上云这件事本身(那是产品前提,不是本单能解的)。
