# Design: opendesign-owner-consent

- Date: 2026-08-08

## 形状:照抄仓里已经验证过的那条线,不发明第二套

`ds_organize` 早就跑通了「模型只能提议、人才能批准」:`stage_plan`(零改动,只暂存)
→ 人跑 `ds-approve`(**唯一能造 `.approved` 的通道,模型无工具可造**)→ `apply_plan`。
本单把同一个形状搬到"扩大助手视野"这类动作上,区别只在**批准发生在网页而不是终端**
(业主是设计师,不该为了换个工作区去开命令行)。

```
助手调 set_workspace(root=D:\)
        │
        ├─ 开关=不用问 ──────────────► 立即生效(= 今天的行为)
        │
        └─ 开关=每次问(默认)
              ├ 不落盘,写一条 pending:config/pending/<id>.json(含**实际参数**)
              ├ 返回给助手:「已提交业主确认」——助手拿不到"已生效"
              └ ds-web 弹卡:【助手想把工作区根改成 D:\】同意 / 拒绝
                    └ 业主点同意 → ds_web 后端**照 pending 里记的参数**执行 → 标记 applied
```

三条硬性:

1. **卡片内容由 pending json 渲染,不经助手转述。** 助手在聊天里说什么都不算确认
   ——`ds_organize_server.py:40` 那句「聊天里说"确认"不算数」照搬。
2. **执行时用 pending 里的参数**,不是助手事后再传一次的参数(防确认后掉包)。
   pending 一次性:applied/rejected 之后同 id 不可重放。
3. **默认要问**(配置文件缺失/坏掉 = 要问)。fail-closed。

## 开关放哪:必须是助手够不到的地方

- ❌ `workspace.json` —— `set_workspace` 自己就写它,等于把锁挂在门里侧。
- ✅ `<ds_root>/config/consent.json`,**只由 ds_web 的 HTTP 设置口写**
  (那是业主在浏览器里点,不是模型);**任何 MCP 工具都不许写它**。
- 这一条要有机械判据,而且**不许手抄危险工具清单** —— anydoc 那单栽过一次
  (两条评审腿各自独立命中"手抄的清单漏了 stage_plan")。判据要从**工具表真相源**
  枚举全部 MCP 工具,断言没有一个能写 consent.json / pending 的批准位。

## 档位

两档,业主在设置页选:

| 档 | 行为 |
|---|---|
| **每次问我**(默认) | `set_workspace` / `bind_project` 走上面的 pending 流程 |
| **不用问** | 立即生效(今天的行为) |

不做 Claude Code 那种「本次会话别再问这个工具」——先上两档,看它实际弹几次再说
(改工作区根是装机/换机才做的事,预期一年弹不了几次;如果它天天弹,说明档位设计错了,
那时候再加)。

## 判据(oracle,主 agent 亲写)

- O1 **默认要问**:没有 consent.json ⇒ `set_workspace` 不落盘、产生 pending。
- O2 **不落盘是真的**:pending 期间 `workspace.json` 逐字节未变;`read_document`
  仍解析到旧根(**这条才是本单要防的东西,不是"有没有弹窗"**)。
- O3 **确认后照 pending 参数执行**;助手中途再调一次别的参数不影响已 pending 的那条。
- O4 **一次性**:applied/rejected 之后同 id 重放 = 拒绝。
- O5 **模型碰不到开关**:从工具表真相源枚举全部 MCP 工具,逐个断言写不了
  consent.json 与 pending 的批准位(**枚举,不是手抄清单**)。
- O6 **关掉开关后**回到今天的行为(立即生效),且关开关只能走 ds_web 的口。
- O7 **过期注释的回归闸**:`set_workspace` 头上那条"不拓宽 LLM 能读"的论证已经假了。
  修文字不够 —— 加一条判据钉住**真正的不变量**:任何时候
  「read_document 能读到的根」⊆「业主确认过的根」。
  哪天有人再加一个读面,这条闸会红,而不是靠下一个人记得回来看注释。

## 风险与边界

- **这道闸挡不住的**:业主自己点了同意。它把"文档里藏一句话就能得手"变成
  "得骗过业主眼皮底下的一张卡"。
- `bind_project` 同理但影响面更小(只把一个项目名指到一个已在根内的文件夹)。
  同一套流程,不单独设计。
- `ds_organize` 那条线**不动**:它现有的终端闸更强,用软闸替换它是降级。


## 装包前向兼容(2026-08-08 业主问「以后做成 Windows 安装包会不会冲突」)

**不冲突,而且这机制已经在跑**:`bin/ds_web.py` 针孔④ `/api/intake/approve`
(`ds_web.py:191 / 1256`)注释原话——「浏览器里人点按钮 = **人工确认本体,替代终端
ds-approve**」。就是收件箱卡上的「确认执行」。本单是把这条已被判据锁死的针孔
用到"改工作区范围"上,不是发明第二套。

装包时:webview 套壳 ⇒ 一行不用改;原生窗口 ⇒ 重画一张卡,后端针孔照用。
唯一会变的是**怎么通知业主**(今天=下次打开工作台看见;装包后可加托盘/系统通知),
那是外壳的事,后端不动。

**为此现在就写死两条**(否则装包必返工):

1. **待确认状态落盘**(`config/pending/<id>.json`),不许放浏览器内存 / 前端 state
   —— 装包后很可能没有开着的页面,那张卡要能等到业主下次打开。
2. **前端只带 pending id,不带"要执行什么"**。执行参数一律从落盘记录读。
   否则换外壳要重写这套逻辑,且开一个"确认后掉包"的洞。

**装包时必须重新验的一条**(现在成立不代表那时成立):
今天"模型碰不到批准口"靠三件事撑着 —— ① ds_web 只绑 `127.0.0.1`(design D2);
② Host 白名单挡 DNS rebinding(`ds_web.py:658`,07-13 盲评加的);
③ 模型没有 exec / 网络能力(`ds_merge_config.py` 把 `tools.exec.enable`、
`tools.file.enable` 合成 false)。**装包一旦引入新外壳、新端口或任何远程访问,
这三条要逐条重验。**

## 有意偏离一条现有原则(说明,不藏着)

本仓现行原则:**网页只批"工作区内"的事,工作区外的留给 CLI,面越窄越好**
(`ds_web.py:1258`)。按这条,"改工作区根"是最"外"的动作,该留给命令行。

但 `set_workspace` 存在的理由就是「让用户不碰 JSON、不找开发者就能接到自己的项目
文件夹」(`ds_tools.py:805` 注释)—— 真留给 CLI 等于废掉这个工具。

**拍板:网页可以批,但默认必须批,且卡片要明写影响面**
(例:「同意后,助手将能读取 `D:\` 下所有项目的资料文档」)。
偏离的代价是这道闸挡不住"业主自己点了同意";它把"文档里藏一句话就能得手"
降级成"得骗过业主眼皮底下的一张卡"。
