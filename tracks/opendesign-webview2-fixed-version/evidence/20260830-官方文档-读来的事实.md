# Fixed Version:官方文档读到的事实(2026-08-30)

来源:https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution
(文档 `ms.date: 2024-06-27`,页面 `updated_at: 2026-07-15`)
+ 一轮针对 `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` 的检索。

> **这一份全是"读来的",不是推来的。** 我 08-30 上午跟业主讲 Fixed Version 时
> 凭的是记忆,而上一轮调研**一份工件都没留** —— 这个文件就是补那笔账。

## 定了的事

1. **内核是微软的,我们只是自带一份副本。** 官方原话:
   "You download a specific version of the WebView2 Runtime and then package it with your app."
2. **体积:"The Fixed Version binaries are over 250 MB and will make your app package larger
   by that amount."** ⇒ 我之前说的「+250MB」属实。
3. **更新责任转移**:"The WebView2 Runtime on the client isn't automatically updated.
   Instead, you periodically update the WebView2 Runtime that's packaged and distributed
   together with your updated app." ⇒ 和我跟业主讲的一致。
4. **拿包的方式**:从 WebView2 下载页取 package,用 `expand {包} -F:* {目标目录}` 解开。
   官方明说**不要用资源管理器解压**(会生成错的目录结构)。
   下载页只提供"最新和次新大版本里补丁最多的那一版",**要自己存档**。
5. **`NewBrowserVersionAvailable` 确实存在**,挂在 `CoreWebView2Environment` 上。
   官方对常青模式的原话:新版自动下到客户端,**程序重启后才切过去**;要用新版必须
   释放旧环境对象或重启。⇒ 我 08-30 跟业主讲的这一段属实。

## 🔴 两条我完全没想到、会直接咬死我们的

### A. Win10 + Fixed Version ≥120:不跑 icacls 就用不了

官方原文:"On Windows 10 devices, starting with Fixed Version 120, developers of
**unpackaged Win32 applications** using Fixed Version are **required** to run the
following commands, for Fixed Version to continue to work."

```
icacls {Fixed Version path} /grant *S-1-15-2-2:(OI)(CI)(RX)
icacls {Fixed Version path} /grant *S-1-15-2-1:(OI)(CI)(RX)
```

原因是 v120 起渲染进程跑在 App Container 里。**Win11 不受影响,Win10 受影响。**

**为什么这条对我们特别危险**:我们正是"unpackaged Win32 app"(NSIS 装的普通程序),
而 `opendesign-native-frame` 的清单里写着**业主公司那台 F: 可能是 Win10**。
⇒ 安装器必须跑这两条 icacls,否则**在他公司那台机器上装完直接起不来**。
这是一条"本机判据永远绿、真机必炸"的路线。

### B. `GetAvailableBrowserVersionString` 可能看不见我们自带的内核

检索到的已知问题:该 API **不认** `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER`,
只报"已安装"的运行时版本。

**为什么这条对我们特别危险**:很多壳(很可能包括 pywebview 的 EdgeChromium 后端)
会**先探测"这台机器有没有 WebView2"再决定能不能起**。如果它走的是这个 API,
那么在一台**没装过常青运行时**的机器上,我们明明自带了内核,它仍然会判定"没有" ⇒ 拒绝启动。
⇒ **P0 探针必须在"没有预装运行时"的机器上验**,不能只在装过的机器上验(那会给假绿)。

## 我们这条栈上的正确接法(待 P0 验证)

pywebview 的 EdgeChromium 后端走的是 **WinForms 的 WebView2 控件**。官方给 .NET 的路子有二:

- `CoreWebView2CreationProperties.BrowserExecutableFolder`(设在 WebView2 元素的
  `CreationProperties` 上);或
- `CoreWebView2Environment.CreateAsync(browserExecutableFolder: ...)` 配
  `EnsureCoreWebView2Async`。

环境变量 `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` 在官方文档里出现在 **WinUI** 那一节的示例中。

⇒ **"设个环境变量就行"是我推的,官方在 .NET 路径上推荐的是前两种。**
P0 要量的正是:环境变量这条捷径在 pywebview 上到底成不成立;
不成立就得够到 pywebview 的 WebView2 控件对象去设 `CreationProperties`。

## 其它约束

- **Fixed Version 不能从网络位置 / UNC 路径跑**(官方 Known issues)。
- Fixed Version **不写注册表**(常青模式那两个 `pv` 注册表键的检测法对它无效)。
