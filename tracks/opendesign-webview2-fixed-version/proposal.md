# Proposal: 自带固定版 WebView2 内核(不再让微软在业主脚下换内核)

- Date: 2026-08-30
- Status: open

## Goal

把 WebView2 从「常青模式」(内核由微软后台自动更新)换成 **Fixed Version**:
安装包自带一份**指定版本的微软 WebView2 运行时**,启动时指着它用。
换什么版本、什么时候换,由我们随发版决定。

## Motivation

2026-08-25 业主装 0.98.0 后白屏,08-30 他答「重启后可以了」,且
`C:\Program Files (x86)\Microsoft\EdgeWebView\Application` 从「101 + 107 并存」
变成「只剩 107」。**最可能的解释是微软在他开着机的时候把内核换到一半。**
(⚠️ 站得住,不是铁证 —— 第二个嫌疑人「我们每次现建临时档案」重启一样清掉,分不开。)

这不是我们选错了技术栈:Tauri、桌面版 Outlook 用的都是 WebView2,
微软自己的 issue 区里 #3375 / #3191 / #1042 都是同类白屏,Tauri 白屏 issue 上百条。
**差距在于别人锁了版本或做了兜底,我们两样都没有。**

## 真问题(第一性)

- 业主原话:
  - 08-30:「我最后决定一下 还是按正常成熟的软件工程做吧 安装包大不是问题」
  - 08-30:「我的问题时内核锁住我们之后还需要更新内核吗，这个内核是微软的还是我们自己写一个内核」
  - 08-25:「opendesign项目我验收了,打开全是白的什么都没有了」(0.93 那次,至今无根因)
- 真正要解决的是:**「我打开软件,它得开得出来」** —— 而现在有一个我们完全不控制的
  第三方组件会在任意时刻在他脚下被替换,替换失败我们零感知、零日志、零提示。
- 我在这中间翻译了什么:
  业主说的是「按正常成熟的软件工程做」,我把它翻译成了 **Fixed Version 分发**。
  这个转译要说清楚它的**代价**才算诚实:锁住之后,**安全补丁变成我们的责任**
  (常青模式下微软自动送)。业主已被明确告知并接受(见上面第一句原话)。

## Scope

- in: 打包时把指定版本的 WebView2 Fixed Version 运行时装进安装包
- in: 启动时让外壳指向自带的那份内核(而不是系统那份)
- in: **前提探针先行** —— 这条路在 pywebview 这层走不走得通,开工前必须量(见下)
- in: 内核版本写成**唯一来源**(和 `VERSION` 一样),升级有据可查
- in: Windows CI 上端到端验:打包 → 装 → 启动 → **截图看见界面**
- in: 老机器上的**升级路径**(0.98 装过常青版,升上来不能炸)

## Non-goals

- **不自己写内核。** 内核是微软的,我们只是自带一份副本。
- 不做自动内核更新(内核跟着我们发版走,不单独升)
- 不在本单做「白屏时说人话 + 补日志 + 固定 storage_path」那三条 ——
  它们仍然要做,但那是**另一单**(地板档),不能因为锁了版本就当不需要
  ⇒ 本单归档时必须把那一单开出来,别让它跟着埋掉
- 不碰前端、不碰窗口动画(`opendesign-native-frame` 那一单的账不并进来)

## 开工前必须先量的前提(design-uncertainty = high)

**P0:pywebview 这层够不够得到 Fixed Version。**
官方有一个不改代码就能指向固定内核的机制(环境变量),
但**我没验过它在 pywebview / EdgeChromium 后端这条路上成不成立** ——
这是**推来的,不是读来的**,不许当既成事实往下走。

- 探针没绿之前不许写实现(继承 `opendesign-native-frame` 的 P0/P1 规矩)。
- 这一步需要 Windows ⇒ 走 `.github/workflows` 那三条已经建好的 CI。
- 退路(若环境变量不成立):改 pywebview 那层的启动参数。方向不变,工作量变大。

**P1:体积与装机时间的真实数字。**
「+250MB」是从官方文档读来的,「大概 300MB」是我估的。
业主说「安装包大不是问题」,但**给他一个真数字**再确认一次,而不是拿估算收口。

## 收口标准(不是本机判据绿)

1. Windows CI 端到端:装 → 启动 → **截图里真的有界面**;
2. `/api/health` 回显的 version 是新版(继承「在使用现场验证」规矩:
   盘上和运行时对不上 = BLOCK);
3. **证明内核用的是我们自带的那份**,不是系统那份 —— 要有一条机器打印的证据,
   不能靠"我看代码是这么写的";
4. 业主真机装一趟(只有他答得了)。

## 风险

- 🔴 **安全补丁责任转移到我们身上。** 业主已知情并接受。
  缓解:内核版本进唯一来源 + 随发版升 + 升完必过 CI 端到端。
- 🟡 这是**发布面**改动(动安装包 + 动启动路径)⇒ impact = high,外部评审 2 腿。
- 🟡 升级路径:业主机器上已经装过常青版 0.98,升上来的行为要单独验。
