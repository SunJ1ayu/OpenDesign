## A. 同一句话说两遍,断线后两条都得在(本版主角)

**为什么要验这个**:重连之后,工作台要把"服务端记下的"和"你本地刚发出的"合起来。
以前它靠**看文字是不是一样**来认消息 —— 于是你把同一句话说了两遍、中间正好断线,
第二遍会被当成第一遍**直接消失**。现在每条消息带了自己的身份号,不再靠猜。

1. 打开工作台,在聊天里发一句话,比如「**这个玄关柜再改一下**」,等助手回完。
2. **把 gateway 停掉**(制造断线):
   ```powershell
   powershell -ExecutionPolicy Bypass -File D:\AI\OpenDesign\bin\start.ps1 stop
   ```
3. 趁着它显示「正在重连…」,**再发一遍一模一样的那句话**(「这个玄关柜再改一下」)。
   - [ ] **该看到**:这句话出现在屏幕上(第 2 条),不是消失、也不是报错。
   > 如果这时候它**没上屏、而是给了你一句"还没发出去"的提示** —— 那也是对的,
   > 见下面 B 组(取决于断得多干脆)。**把你实际看到的哪一种告诉我。**
4. 把服务起回来:
   ```powershell
   powershell -ExecutionPolicy Bypass -File D:\AI\OpenDesign\bin\start.ps1
   ```
5. 等它自己回到「已连接」(不用你点任何东西),然后看聊天记录。
   - [ ] **该看到**:那句一模一样的话**两条都在**。
   - [ ] **不该看到**:只剩一条(你说过的话被吃了),或者变成三条四条(重复)。
   - [ ] 顺带看一眼顺序:读起来别别扭(比如你刚说的那句被排到很久以前那几条中间)。

## B. 发不出去的时候,别骗你说发出去了

**为什么要验这个**:连接刚断、界面还没反应过来时,你点发送,以前那句话会**照样贴上屏**,
你以为说过了,其实一个字都没送到助手那儿。

⚠️ **先说清楚:这一组有两种正常结果,不是只有一种。**浏览器对"断"的反应分两档 ——

| 你怎么断的 | 浏览器立刻知道断了吗 | 你会看到 |
|---|---|---|
| **停掉 gateway**(服务在本机,连接被干脆关掉) | 知道 | 那句话**不上屏**,给你一句提示 |
| **拔网线 / 关 Wi-Fi**(连接只是没人应答了) | **不知道**,要过一阵才发现 | 那句话**照常上屏**,但助手不会回你 |

第二种不是 bug,是浏览器还以为连着(这一版拦不住它;它靠 A 组那套"重连后对账"兜)。
**你要做的只有一件事:把你实际看到的是哪一种,连同你怎么断的一起告诉我。**

1. **停掉 gateway**(上面 A 组第 2 步那条命令),**立刻**在聊天框打一句话点发送:
   - [ ] **该看到**:这句话**没有**出现在聊天记录里,而是给你一句提示,
         大意是「这句话还没发出去,等它连回来再点一次发送」。
   - [ ] 那句提示**是人话**吗?(如果里面出现了英文报错、代码之类的东西,原样抄给我)
   - [ ] 你打的字**还在输入框里**吗?(该在——不然还得重打一遍)
   - [ ] 如果那条**带了图片**:图片还挂在输入框上吗?(该在,不用重新选一次)
2. 把服务起回来,等它自己回到「已连接」:
   - [ ] **那句提示自己消失了吗?**(该消失——连上了还挂着提示会让你以为还没好)
   - [ ] 这时候**再点一次发送**,那句话正常发得出去。
3. (可选)**拔网线**那种断法照上表第二行,看到的应该是"上屏但没人回";
   等你插回网线、它自己连上之后:
   - [ ] 那句话**还在**屏幕上吗?(该在——不该凭空消失)

> 这一组不一定每次都撞得准。试两三次就够,**别为它花太多时间** —— A 组才是这一版的主角。
