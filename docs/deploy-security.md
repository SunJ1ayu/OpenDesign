# 部署到他人机器:凭证与边界方案(只方案,不代码)

- Date: 2026-07-03(track opendesign-windows-prep T7)
- 适用场景:OpenDesign 装到部署者(用户)以外的机器上,典型 = 别的设计师的 Windows 电脑。
- 状态:**决策已全部拍板(2026-07-03,见 §5)**,方案按拍板结果更新;剩装机执行。

## 0. 信任模型(先说清防谁)

这套安全设计**防的是模型越权,不防机主**:

- `ds-approve` 闸、`DS_ORGANIZE_ROOTS` 白名单、`.approved` 标记、词表校验——全部是
  "MiMo(模型)绕不过"的约束,目的是模型永远不能未经人批准动文件。
- 机主(电脑的主人)改 config、扩白名单、开新目录——那是**配置行为,不是攻击**。
  机器是他的,文件是他的,他有权。方案里不存在"防机主改配置"的目标,也别用
  "绕过"这类词描述机主的正常配置操作。
- 真正要防机主的只有一样:**部署者自己的东西**(API key、回传通道),见 §1、§3。
  ⚠️ D1 拍板(机主自备 key)后,部署者在目标机上**没有 key 了**;这一条实际只剩
  "不留回传通道"(§4/§6)。
- ⚠️ **"模型绕不过"的前提 = nanobot 内置危险工具关死**(2026-07-17 intake track 审出):
  nanobot 默认 `tools.exec.enable=true` 且 `restrictToWorkspace=false`——exec 开着,
  模型可跑任意命令直接创建 `.approved`/搬文件,上面所有闸都是纸的。config 模板与
  `ds_merge_config.py` 现已强制 `file`、`exec` 双关(产品不用 exec,提醒走内置 cron
  工具);装机后可在 config 里核对这两行。内置 `web` 工具保留(GET-only + SSRF 拦内网,
  够不着本机针孔),exec 的内网 URL 守卫与此无关——洞在文件系统不在网络。

## 1. API key:机主自备(BYO)

> **✅ 用户拍板(2026-07-03,D1)**:"用户自己买 LLM、自己接大模型,我们不管这个。"

- 部署者**不发放、不登记、不买单**:装机时机主提供自己申请的 LLM key + 端点。
  任何 OpenAI 兼容端点都行(MiMo/GLM/DeepSeek/Kimi…,nanobot 原生支持换脑),
  config 模板留填空位,安装说明教机主"去哪买、填哪里"。
- 原方案(部署者发独立限额 key + 登记表 + 爆炸半径管理)**整体作废**——没有部署者的
  钱包就没有要防的爆炸半径;额度、吊销、账单都是机主与 LLM 厂商之间的事。
- **注入方式**:key 放机主本机 `%USERPROFILE%\.openDesign\key.txt`(或预设环境变量
  `DS_LLM_KEY`),`ds-nanobot.ps1` 启动时读入,config 引用 `${DS_LLM_KEY}` 不硬编码。
- 连带效应(§3):对话经**机主自己的账号**上云,"经部署者账号"那层告知义务消失。

## 2. WebUI 口令与 config

- WebUI 必须设口令(nanobot onboard 支持),防的是**同一局域网/同一台机器的其他人**
  随手打开聊天页看到业主数据——不是防机主。
- config(含白名单、key)属于机主可改的本地文件。部署时给一份**带注释的默认 config**,
  白名单只开约定目录;机主要扩,是他的决定,文档写清楚"扩到哪,agent 就能提议整理哪"。

## 3. 云上行边界(⚠️ 与北极星承诺的正面冲突,必须决策)

北极星卖点是"**本地部署,业主数据不上云**"。但大脑是云 LLM API——事实是:

> **文件在本地,对话在云上。** 机主(设计师)跟 agent 说的每句话、agent 读进上下文的
> 每段业主档案,都会发到 LLM 厂商的云端做推理。

这不是实现瑕疵,是当前架构的固有属性(换任何云 LLM 都一样,除非上纯本地模型)。

> **✅ 用户拍板(2026-07-03,D0)**:可接受。"只有聊天数据上云可以接受,毕竟客户资料还是
> 在用户本地。"范围界定:文件本体永远本地;但对话内容 + agent 读进上下文的档案片段会
> 经云推理。
>
> **✅ 用户拍板(2026-07-03,D2)**:**不需要专门告知**。"他们会用大模型的 API,应该都
> 知道。"叠加 D1(机主自备 key)后成立:key 是机主自己申请、自己填的,"对话经云"是他
> 接入大模型时的已知事实,且走的是他自己的账号,不再经部署者——原"README-owner 一页
> 告知文书"作废,降级为安装说明里保留一句事实陈述("AI 读过的档案内容也会随对话经过
> 你的 LLM 账号上云"),不做专门文书。
>
> **✅ 用户拍板(2026-07-03,D3)**:**不打码,照记**。"门牌号肯定得记,毕竟是个人助手,
> 可以存本地。"电话/门牌号等敏感字段完整入档(本地文件);agent 读到它们时会随对话经
> 机主自己的云账号,属 D0/D2 已接受范围。原缓解选项①作废;②合规端点=机主选什么脑是
> 他自己的事;③纯本地模型维持 P-later。

## 4. 反向隐私:对方的数据不回流部署者

部署者这边的习惯(云机自动备份、日志收集)**不能带到目标机**:

- 目标机上不装任何"回传到部署者"的备份/遥测;机主数据的备份是机主自己的事
  (文档里教他备份到自己的盘)。
- 排障需要日志时,**机主主动发**,部署者不留常驻通道。
- LLM 云端侧的对话记录(§3)是无法本地消除的例外——D1 后走机主自己的账号,由他自管。

## 6. D4 白名单默认(部署者代拍,2026-07-03)

用户不确定该圈哪些目录,授权部署者决定。定为:

- **默认 = `${USERPROFILE}/Desktop` + `${USERPROFILE}/Downloads`**(分号分隔)。
  理由:桌面和下载是设计师乱文件的重灾区(文件整理工具的主战场),范围窄、
  不含系统目录、不含业主档案以外的隐私盲区,符合原"宁窄勿宽"原则。
- 机主要 agent 管别的盘/目录(如 `D:/项目归档`),在 config 的 `DS_ORGANIZE_ROOTS`
  里追加即可——这是机主的配置权(§0),安装说明写清楚加法。
- 空字符串 = 全拒 的安全默认保持不变(模板已预填默认值,删空即关死)。

## 7. 更新与排障流程(D5 落地)

- 机主遇 bug → **手动**把日志/截图发给部署者(目标机不装任何常驻回传/遥测,§4 不变);
- 部署者在自己机器上修复 → 推到 GitHub 仓(分发通道;建仓时机=第一版可安装的
  Windows 包整理好之后,用户 2026-07-03 定的顺序)。
  ⚠️ **该仓现为公开仓**(2026-08-02 核实:`SunJ1ayu/OpenDesign` visibility=PUBLIC;
  本文档 07-03 写作时假定的是私有仓)。见 §8;
- 机主 `git pull` / 重跑安装脚本拿到更新。业主数据与机主 config 不进仓,更新不碰它们。

## 8. 仓库公开后的复核(2026-08-02)

本文档 §1–§7 成文于 07-03,当时假定分发走**私有仓**。08-02 核实仓库实际是**公开**的,
故按"公开"重新过了一遍。**结论:私有性不是任何一条安全结论的承重墙**——因为敏感数据
从一开始就不靠"仓库私有"保护,而靠"根本不进仓"。

**没有变的(已实测核对)**:

- **业主数据不在仓里**。`.gitignore` 锚定仓根挡掉 `/projects/*`、`/clients/*`、`/refs/`、
  `/organize/`、`index.md`、`config/workspace.json`;仓内只有 `projects/.gitkeep` 占位。
  全历史扫过:没有密钥/token/凭证类文件(`nanobot-tokens.md` 是 CSS 设计变量,不是密码),
  唯一出现的手机号是测试占位号 `13800000000`。
- **机主的 key 不在仓里**(§1:`%USERPROFILE%\.openDesign\key.txt`,config 用 `${DS_LLM_KEY}` 引用)。
- **§0 信任模型**(防模型越权、不防机主)与仓库可见性无关,一条不动。
- **§4 反向隐私**(不留回传通道)也不受影响:公开的是代码,不是任何一台目标机的数据。

**变了的**:

1. **安装不再需要登录 GitHub**(`docs/install-windows.md` 已同步更正)。对装机是简化。
2. **代码、文档、以及 `tracks/` 里的整个开发史现在全网可见**——包括评审记录、
   踩坑复盘、真机反馈。这些是工程内容,但写的时候是按"只有自己看"的口吻写的。
3. ⚠️ **未决**:仓内 26 个文件(测试夹具 / `docs/workspace-taxonomy.md` /
   `config/workspace.example.json`)用的是**真实楼盘名 + 楼栋房号**做样例,
   例如 `20260612 周宁 龙腾世纪 12#1802`、`融侨外滩D区1#2604`、`云山名城-2302`。
   没有姓名、没有电话,但**"某户的具体门牌"加上仓主身份 = 可推断某位业主的住址**。
   这条与 D3(敏感字段照记)不冲突——D3 说的是**本地档案**记全,这里是**公开仓**里的
   样例数据,是两回事。**处置待用户拍板**(改回私有 / 把样例换成虚构楼盘 / 接受现状);
   注意换名要动 e2e 断言里写死的字符串,属判据文件,须主 agent 亲自改。
