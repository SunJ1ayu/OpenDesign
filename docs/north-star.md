# OpenDesign 北极星 + 非目标(一页纸,不是 PRD)

> 2026-07-01 定调、07-02 补落盘。作用 = 新想法的裁判标准,不是功能规划。
> 想加东西先过这页;过了就走 track(proposal→design→verify),不写大 PRD。

## 北极星(一句话)

帮多项目、长周期的室内设计师**不忘事**:业主说过的每一句修改,都有编号、有状态、有下落;
到点该问的事,agent 先开口。

## 核心判断(推翻要有新证据)

1. **瓶颈是记忆,不是出图** —— 生成能力(3D/渲染)是挂件,记忆 PKB 是主干。
2. **本地部署,隐私优先** —— 业主户型图/聊天不上云;数据 = 本地 markdown,永远可 grep。
3. **换脑自由** —— 数据/脑/手/入口四层解耦;换 LLM 不伤记忆。
4. **人握硬闸** —— agent 可以提任何方案,动真东西(文件/将来更多)必须过模型碰不到的确认通道。

## 边界内(做)

- 设计项目记忆:业主档案、变更状态机、沟通日志、主动提醒(ds_tools + ds-todo)
- 受控文件整理:提方案→人批准→执行(ds_organize + ds-approve,07-02 拍板加入,人握硬闸)
- 将来:cad-to-3d 黑盒挂接(P2)、业主反馈闭环(P3)、效果图**挂接**(P4)

## 非目标(不做,想做先改这页)

- ❌ 效果图/渲染引擎自研 —— P4 只是挂接外部工具
- ❌ 报价、合同、CRM、进销存 —— 那是另一个 agent 的活,不塞进这个
- ❌ 文件自动分类智能 —— 归类判断是大脑(LLM)的活,工具只校验+执行
- ❌ 多用户 SaaS / 云端版 —— 单设计师本地部署,装别人机器也是单机各自部署
- ❌ 业主直接对话入口 —— P1 只设计师自己用;业主消息由设计师转述
- ❌ 全生命周期 SOP 固化 —— 阶段词表等真实流程/白皮书校准,不拍脑袋定死
- ❌ schema 大改 —— 挂起中,等多家私有课件横向对比 + 真实项目数据

## 新想法的三连问(加功能前自问)

1. 这是**记忆**的活(主干)、**手**的活(工具,要过确认闸)、还是**别的 agent** 的活(拒)?
2. 有真实使用场景撑腰吗,还是"为了完备"?(没场景 → 先记进想法清单,不动手)
3. PR 级大小吗?是 → 走 track;比这大 → 先回这页检查是不是方向漂移。
