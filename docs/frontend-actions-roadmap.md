# 前端"直接点击"改造 roadmap(2026-07-18 定)

起因:真机反馈"很多动作还要回聊天,太麻烦,该能直接点"。主 agent 通读前端 +
四审(submimo/subdeepseek/subglm/subkimi)独立勘察 + 主 agent 合并排序。

判据:一个动作是"直接点写口"还是"预填/dispatch 进聊天绕一圈"。铁律不破——
每个新点击=只读墙上开一个**受控写针孔**(CT=json 强制/路径闸/复用 ds_tools 核心/
需人工确认的仍走确认),照 /api/changes/edit、收件箱确认针孔先例;绝不前端直改 markdown。
"产出内容型"(记业主原话/自然语言查询)保留聊天入口,只补快捷旁路。

## 已是直接点(无痛,别动)
变更改状态(StatusPicker→/api/changes/edit)· 待办状态/正文/备注就地编辑 ·
收件箱"确认执行" · 打开文件夹 · 开图墙 · 删对话 · 导航/选项目。

## 🥇 P0 先做(高频×低成本)
1. **变更记录行内"+记一条"** — 变更面板顶部快捷输入 → 新针孔 `POST /api/changes/add`(append_change)。日常最高频。
2. **未建档文件夹一键建档** — 名字已在 UI 显示却要回聊天复述(GLM:"最荒谬的摩擦")→ "建档"按钮 → 新针孔 create_project。
3. **收件箱"扫描整理"按钮** — 确认能点、触发却要回聊天(能力不对称)→ InboxCard 加按钮 → 新针孔触发扫描暂存。

## 🥈 P1 再做
4. 变更正文就地编辑(复用现有 editChange 针孔,后端零成本;抽 TodoPage 编辑组件共享)。
5. 收件箱方案单条纠偏(跳过/改目标,DeepSeek 补)。
6. 项目↔文件夹关联(bind_project 针孔,下拉选替代聊天打字)。

## 🥉 P2 以后
7. 切阶段(状态 chip→下拉,set_stage 已存在)· 8. 参考图标签/备注就地改 · 9. 变更修改历史在 UI 可见(数据已返回,界面未渲染,Kimi 补)。

## 🧱 单独大件(另立项,非本次"变点击")
- **图片上传能力**:工作台/聊天都没有上传图,"登记参考图"因此受阻(Kimi 补)。是"总参考库"线的地基,价值高工程大。
- 当前状态编辑(需先加核心写工具,Kimi 补)· 项目改名/删除 UI(改名低频/删除需确认闸)· 切模型现强制回终端。

## 💬 留在聊天(四审一致)
记业主原话的自由描述 · "这周哪些没确认"类自然语言查询 · 整理方案的复杂自然语言修改。
