# 真机验收清单 0.85.0(J 组)——「手改过的档案,现在也改得动了」

> 前置(和以前一样,少一步就白测):
> 1. `git pull`
> 2. **重跑 `bin\install.ps1`**,看到「已同步助手契约」才算数
> 3. 起 `bin\start.ps1`(先 stop 再起)→ 浏览器 Ctrl+F5
> 4. 打开 `/api/health`,**version 必须是 0.86.0 或更高** —— 盘上和运行时对不上就是 BLOCK,别往下测
>    (08-15 改的:这份清单要验的东西是 0.85.0 交付的,但版本号后来因为 Windows 安装器
>    bump 到了 0.86.0。**现在 pull 下来只会是 0.86.0**,看到 0.85.0 反而说明没 pull 成功。)

这一单只改了一件事:**读和写用同一套规则认变更编号**。
以前你手写成 `C03` 的条目,界面上看得见,但点什么都说"找不到"。

---

## J1 —— 核心:手写编号的条目现在能操作了

在任意一个项目档案里,**手动**加一行(注意编号故意写成 `C03` 这种带 0 的):

```
- [待确认] C03 2026-08-01 客厅刷白
```

保存,刷新工作台。然后逐个点:

- [ ] **J1a** 改状态(待确认 → 进行中):**成功**(以前:报错/没反应)
- [ ] **J1b** 改正文:**成功**
- [ ] **J1c** 设一个截止日:**成功**
- [ ] **J1d** 加一条备注,刷新页面后备注还在:**成功**
- [ ] **J1e** 点删除:**成功**(这条以前也点不动)
- [ ] **J1f** 上面几步做完,回去看档案文件:那一行的编号**仍然写着 `C03`**,
      没有被偷偷改成 `C3`(我们不动你写的字)

## J2 —— 备注"清空了还在"

档案里手写一条(编号带 0):

```
## 变更历史
- C03 备注:老备注
```

- [ ] **J2a** 在工作台上把这条备注**清空并保存** → 刷新后**真的没了**(以前:删了还显示旧的)
- [ ] **J2b** 换成:改成新备注 → 档案里**只有一行**备注(以前会变成两行)

## J3 —— ⭐ 最值钱的一格:拿你自己的真档案试

我的判据用的全是**我自己造的规整档案**。你那份两年的真档案里,手写的行可能长得更歪。

- [ ] **J3** 翻一条**你很久以前手写/手改过**的变更或备注,在工作台上改它一下。
      改得动 → 好;改不动或者报错 → **把那一行原样发给我**(这一格只有你能答)

## J4 —— 不许误伤(确认这次没弄坏别的)

- [ ] **J4a** 正常的条目(编号是 `C7` 这种)改状态/改正文/删除,**一切照旧**
- [ ] **J4b** 待办页、项目页显示正常,数字没错乱

## J5 —— 两个"故意不让你干"的地方(遇到了不是 bug)

- [ ] **J5a** 如果某条编号写成了 `C03-1` 这种**带后缀**的,**改正文**会被拒绝
      (改状态/截止日/删除/备注仍然可以)。原因:改完那一行会读不回来、编号会丢。
      **遇到了告诉我**,要不要支持这种写法得你定。
- [ ] **J5b** 如果档案里同时存在 `C3` 和 `C03` 两条(重号),所有操作都会被挡住并提示冲突。
      这是故意的(宁可不写),你手工把重号改掉即可。
