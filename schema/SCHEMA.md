# SCHEMA — 字段规范

> 改字段先改这里,再改文件。脚本 `bin/ds-todo` 依赖两处格式,标 ⚠️。

## clients/<业主>.md
```markdown
# <业主称呼>(如:张伟 / 翡翠湾1801业主)

- 联系方式: <微信/电话>
- 关联项目: [[<项目slug>]]
- 预算区间: <如 全包 30-35万>
- 风格偏好: <如 原木/侘寂,忌纯白>
- 关键约束: <如 有小孩需圆角、要养猫、老人房在一楼>
- 决策习惯: <如 太太拍板/需全家商量,回复慢>

## 备注
<自由文本:性格、雷区、历史沟通要点>
```

## projects/<项目>.md
```markdown
# <项目slug>  (如 翡翠湾-1801)

- 业主: [[<业主>]]
- 阶段: <阶段词表之一>
- 地址/户型: <如 翡翠湾2期1801,三室两厅 118㎡>
- 开始日期: YYYY-MM-DD
- 当前状态: <一句话:卡在哪/等什么>

## 变更记录              ⚠️ ds-todo 解析此格式,勿改前缀
- [待确认] C1 2026-06-20 主卧衣柜改推拉门
- [已完成] C2 2026-06-18 客厅吊顶改平顶,等业主看效果
- [已关闭] C3 2026-06-15 阳台封改开放(业主放弃)

## 沟通日志
- 2026-06-20 微信:太太提主卧衣柜想改推拉门,先生没意见
- 2026-06-18 现场:确认客厅吊顶平顶方案

---
最后更新: 2026-06-20    ⚠️ ds-todo 解析此行(超期判断)
```

## 规则
- **变更行**严格 `- [状态] C编号 日期 【空间】内容`,状态在词表内,否则 `ds-todo` 漏算;
  `【空间】` 可选(1-16字,如【玄关】,由 append_change 的 space 参数写入;旧行没有=未标注)。
- **沟通日志的业主原文条目**(log_communication 写入):头行 `- 日期 业主原文(来源):`,
  原文每行前缀 `  > `(引用块,多行逐字保真;空行为裸 `  >`)。引用前缀同时是安全机制:
  原文里的伪变更行/伪 `## ` 段头/伪 `最后更新` 全部失锚,勿手工去掉前缀。
- **不删变更行**:取消用 `[已关闭]`,保留追溯。
- slug 用可读名(`翡翠湾-1801`),`index.md` 与文件名一致。
- `最后更新:` 每次改动都顺手更新——它是"超期未跟进"提醒的依据。
