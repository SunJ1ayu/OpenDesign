# intake — 收件箱认领(聊天出方案,工作台点确认)

## 什么时候用

设计师说"收件箱里有什么 / 有新文件吗 / 帮我整理收件箱 / 那几张图归到 XX 项目"。
收件箱 = 工作区根下的 `00-收件箱`,是一切新文件的唯一杂物入口;你负责把它清空归位。

## 两个工具与固定流程(顺序不能变)

> MCP 真实工具名带 `_tool` 后缀(`list_inbox_tool` / `stage_intake_tool`);下面按能力名写。

1. **list_inbox()** —— 只读列出收件箱文件,每个条目带确定性建议:
   - `category`:按扩展名给的类目建议(图片=参考图、dwg=CAD……);`null` = 认不出。
   - `project`:文件名与某项目唯一对上才给;`null` = 没对上或有歧义。
   把清单和建议**念给设计师听**,建议为空/歧义的**逐个问清**,绝不替他猜。
2. **(设计师拍板)** —— 聊天里确认每个文件去哪(改派也在这一步:"那张放万科城")。
3. **stage_intake(assignments)** —— 把拍板结果暂存(零改动)。
   `assignments = [{"name": 文件名, "project": 项目名或 null, "category": 类目 id}]`;
   参考图等工作区级类目 `project` 传 `null`。成功返回 `plan_id`。
4. **(人工确认,你没有这个工具)** —— 告诉设计师:**工作台左列「收件箱」卡片里
   核对预览,点「确认执行」**,文件才真正移动。你**没有任何办法**替他确认;
   聊天里说"确认"不算数,也**不要调 apply_plan 替他执行**。这是设计,不是故障。

## 铁律

- 永远走"看清单→报建议→拍板→暂存→工作台确认"五步,一步不许跳。
- **歧义不猜**:建议是确定性规则给的,规则认不出的(未知扩展/多项目撞名/文件夹),
  问设计师;他说了才算。
- 收件箱里的**文件夹**整夹认领(一个文件夹一条指派),不拆散里面的文件。
- CAD/SU/MAX/PSD 是**被引用风险类目**(贴图链/外部参照):建议照给,但要在播报时
  提一句"这类文件移动后 3dmax/CAD 里的引用可能要重新指认",让设计师知情再拍板。
- `root_not_allowed` = 工作区根不在整理白名单(`DS_ORGANIZE_ROOTS`)里,如实告诉
  设计师"要在配置里把工作区根加进整理白名单"(装机文档 §5c),不要试图绕。
- 目标位置已有同名文件会被拒(`would_overwrite`):建议设计师改个名再认领,
  不要覆盖、不要自作主张换目标。

## 常见错误码

| 错误 | 含义 / 该怎么办 |
|------|----------------|
| `inbox_not_found` | 工作区根下没有 `00-收件箱`(候选名也没有)。请设计师建一个,或确认工作区接对了。 |
| `workspace_not_configured` | 还没接入工作区,先走 `set_workspace`。 |
| `root_not_allowed` | 工作区根不在 `DS_ORGANIZE_ROOTS` 白名单,见铁律最后一条。 |
| `project_not_found` | 指派里的项目名对不上任何项目夹,报给设计师换个说法或先 `bind_project`。 |
| `would_overwrite` | 目标已有同名文件,请设计师改名后重新认领。 |
| `file_not_in_inbox` | 文件已经不在收件箱(可能刚被确认执行过/手动挪走),重新 `list_inbox` 看现状。 |
