# organize — 文件整理(带人工确认闸)

## 什么时候用

用户说"帮我整理这个文件夹 / 把这些文件归类 / 批量改名 / 归档旧文件"之类。
**只能移动(move)和重命名(rename),不能删除**——没有删除工具,别答应用户去删。

## 三个工具与固定流程(顺序不能变)

1. **scan_dir(root)** —— 只读扫描目录,返回文件清单。先扫再提方案,不许凭想象出方案。
2. **stage_plan(root, operations)** —— 把方案暂存(零改动,不碰任何文件)。
   - `operations` 是列表,每项 `{"op": "move"|"rename", "src": "相对路径", "dst": "相对路径"}`。
   - 成功返回 `plan_id` 和 `summary`。**把 summary 原样展示给用户,不要转述改写。**
3. **(人工批准,你没有这个工具)** —— 告诉用户:在终端跑 `ds-approve <plan_id>` 批准。
   你**没有任何办法**替用户批准;用户不批,计划就永远执行不了。这是设计,不是故障。
4. **apply_plan(plan_id)** —— 只有用户批准后才会成功。执行前工具会整体复验文件快照,
   期间文件变过会拒绝执行(要重新 stage)。

## 铁律

- 永远走"扫描→暂存→用户批准→执行"四步,一步不许跳。
- 不删除、不覆盖:目标已存在等冲突工具会报错,把错误如实告诉用户。
- 只能整理白名单(`DS_ORGANIZE_ROOTS`)内的目录;`root_not_allowed` = 目录不在白名单,
  告诉用户该目录未开放整理,不要试图绕。

## 常见错误码

| 错误 | 含义 / 该怎么办 |
|---|---|
| `root_not_allowed` | 目录不在白名单,告知用户,不要重试别的写法绕过 |
| `path_escape` | 方案里有路径逃出根目录,修正方案 |
| `not_approved` | 用户还没跑 ds-approve,提醒用户批准 |
| `plan_drift` | 文件在暂存后变过,重新 scan + stage |
| `would_overwrite` / `conflict` / `src_missing` / `dst_parent_not_dir` | 方案与磁盘现状冲突,如实告知并修正方案 |
| `already_applied` | 该 plan 已执行过,不能重复执行 |

没列到的错误码 → **把错误原样告知用户**,不要自行重试或换写法绕过。
