# design-studio — 室内设计项目记忆系统(P1)

> 单设计师、本地、Markdown 为唯一真相源。AI agent 维护文件,人策展。
> 沿用 [[llm-wiki]] 的"LLM 维护 markdown + check 脚本"范式。

## 这是什么
解决"项目一多、时间一长就忘了谁要改什么、改到哪一步"的记忆系统。
**P1 只做记忆 + 状态 + 主动提醒**,不接 CAD→3D、不接效果图(那是 P2/P4)。

最终目标是"项目全生命周期系统",所以字段已按全生命周期设计,P1 阶段只是先**记录**未深度参与的环节。

## 目录
```
clients/<业主>.md        业主档案:联系方式/偏好/预算/关联项目
projects/<项目>.md       项目主页:业主/阶段/户型 + 变更记录 + 沟通日志
schema/SCHEMA.md         字段规范(改字段先改这里)
bin/ds-todo              主动提醒:扫所有项目的未关闭变更 + 超期未更新项目
bin/ds_web.py            工作台本地服务(web/dist + 只读 /api,端口 8766)
web/                     工作台前端(React+Vite 源码;dist/ 构建产物进仓,用户机免 Node)
```
> 项目/业主总索引已不再用手维护的 `index.md`(内置文件工具禁用后无人能维护)——
> 改由 `list_projects` 工具实时枚举 `projects/`,`lint_pkb` 体检可查出残留的旧 `index.md`。
P2 起每个项目加 `projects/<项目>/assets/`(DXF/FBX/效果图归档),届时项目主页从单文件升级为目录。

## agent 操作契约(每次维护遵守)
1. **业主提需求/改动** → 在对应 `projects/<项目>.md` 的「变更记录」追加一行:
   `- [待确认] C<n> YYYY-MM-DD 内容`,并更新文件末尾 `最后更新:`。
2. **状态推进** → 只改方括号里的状态:`待确认 → 进行中 → 已完成`(或 `已关闭`=放弃/取消)。**不要删行**,保留追溯。
3. **沟通记录** → 追加到「沟通日志」,一行一条,带日期。
4. **新业主/新项目** → 用 `create_project` / `create_client` 工具建,绝不手写文件(内置文件工具已禁用,手写会落错目录、扫不到)。项目盘点用 `list_projects`,不再维护 `index.md`。
5. **每次会话开头**或被问"有啥要跟进的" → 跑 `bin/ds-todo`,把未关闭事项 + 超期项目报给设计师(这就是"主动提醒",对治"会忘")。

## 阶段词表(全生命周期)
`洽谈 / 量房 / 平面方案 / 方案深化 / 效果图 / 施工图 / 施工交底 / 施工跟进 / 软装 / 竣工验收 / 售后`

## 变更状态词表
`待确认 / 进行中 / 已完成 / 已关闭`(`ds-todo` 把「待确认」「进行中」视为未关闭)
